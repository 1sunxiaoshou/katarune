# 决策记录

本页只保留选择、关键理由和替代关系。未特别标注的条目为已决定；实现细节见对应专题，进度见[路线图](../03-规划/路线图.md)。编号与原有标题保留，历史过程可从 Git 查阅。

## 产品与协作

### D-001 · 项目名称

产品、窗口和安装包统一使用 Katarune，仓库标识为 `katarune`。以统一名称建立产品身份，不再展示中文别名。

### D-002 · 新项目而非原仓库重构

采用独立项目，不以旧工程代码或用户数据兼容为目标。这样可以按当前产品边界建立实现，不引入历史迁移负担。

### D-003 · Web 技术优先

当前界面和大部分 Harness 优先采用 TypeScript/Web 生态，本地原生能力通过清晰接口接入。技术选择服务于阶段性实现，不限制数字生命的长期载体。

### D-004 · 使用 AI SDK 与 assistant-ui

AI SDK 负责模型、工具、流式输出与基础 Agent 循环；assistant-ui 负责聊天 Runtime 和交互。复用成熟框架，升级作为独立任务；具体版本以包锁为准。

### D-005 · Harness 定位

现阶段建设产品 Harness，自研集中在角色、记忆、语音、形体、桌面能力和用户控制。通用 Agent 基础继续复用框架。

### D-006 · 复用优先

框架原生类型、消息格式、协议和生命周期保持单一来源；只在 SQLite、IPC、安全及产品语义处薄适配。避免镜像模型、重复转换和没有真实迁移需求的兼容层。

### D-007 · 项目级 Agent Skills

框架 Skills 存放在仓库 `.agents/skills/` 并锁定来源，按任务加载。安装、版本核对与升级规则集中在 [AGENTS.md](../../AGENTS.md)，避免过时 API 和供应链漂移。

### D-008 · 工程变更规范

严格 TypeScript、共享 Zod 契约、语义化版本与 Conventional Commits 作为统一基线。验证按实际变更风险选择，不把工具尚未落地写成已通过。

## 运行时与工程

### D-010 · TypeScript 服务运行时

可信 Harness 使用 Electron 内置 Node.js main process，当前不增加 Bun 或独立 Node sidecar。减少运行时编排和原生依赖变量。

### D-011 · 桌面容器

采用 Electron 管理产品界面和可信服务；React 位于 sandboxed renderer，VRM 已由独立 Unity Runtime 承担。敏感能力通过最小 preload 桥接，避免向界面开放主进程权限。

### D-012 · 持久化方案

SQLite、better-sqlite3 与 Drizzle 保存产品关系数据，迁移 SQL 纳入版本控制并在开窗前执行。消息复用框架原生持久化格式；长期记忆正文不进入 SQLite。

### D-014 · 模型运行时管理

使用 AI SDK Provider Registry；官方 Provider 优先，兼容端点和已确定的单项能力只做薄适配。不自研通用模型协议或第二套 Registry。

### D-015 · Electron 工程工具链与打包方式

使用 npm、electron-vite 与 electron-builder；Windows 采用 NSIS。成熟工具负责归档与安装生命周期，项目只维护必要扩展，资源准备见工程规范。

## 角色、模型与数据

### D-016 · 角色级 Memory Wiki

长期记忆采用角色独立的 Markdown Wiki：核心页受限注入，扩展页按需检索；提供搜索、读取与受限补丁工具。revision、角色锁、原子写入和删除失败恢复保障一致性，界面不获得真实文件权限。

### D-017 · 用户供应商配置

保存非敏感供应商配置，由 Definition 创建对应 Provider；凭据仅保留引用。只有启用且实际能力可调用的配置进入运行 Registry，数据库中有记录不代表能够调用。

### D-018 · 系统安全凭据存储

凭据由 Electron safeStorage 加密，数据库只保存不透明引用；renderer 只能替换或清除，不能读取已保存 secret。加密不可用时失败关闭，不降级为明文。

### D-019 · 最小模型配置与连接验证

模型发现优先反映真实账号库存，LiteLLM 辅助类别识别和明确的官方目录回退；未知类别由用户确认。认证失败与未知自定义端点不以公共目录伪装库存，避免错误导入或虚假可用性。

### D-020 · 基础导航

聊天、角色和设置保持清晰入口；通用图标用 Lucide，供应商品牌用随包 SVG。具体界面随现行实现维护，业务操作复用标准菜单和对话框。

### D-021 · assistant-ui 与 shadcn UI 边界

聊天组件复用 assistant-ui Registry，通用组件复用 shadcn/Base UI 和默认主题 token。避免基础组件包装层、平行颜色系统及不必要的样式分叉。

### D-023 · Provider 身份使用单一来源

`provider_configs.id` 同时作为数据库主键和 Registry Provider Key，`provider_type` 只选择 factory。内部复合模型标识不用于产品展示，减少双身份同步。

### D-024 · 角色即 Agent、活动角色与会话绑定

`characters` 是角色与 Agent 的唯一实体，会话固定归属角色；角色 Runtime 独立，界面切换不取消其他角色的后台运行。角色包展示已按 D-064 替代旧裁切交互，历史记录不作为现行 UI。

### D-025 · 通用资产注册表与托管协议

资产元数据与不可变托管文件分离，使用受限资产协议访问。稳定 ID、内容哈希和引用回收支持恢复与删除，避免 Base64 持久化和真实路径泄露。

### D-026 · Electron 本地 AI 消息流

每个线程和运行独立管理原生聊天传输，通过 MessageChannel 提供背压和取消。复用 AI SDK/assistant-ui 的格式，不增加本地 HTTP 服务或镜像流协议。

### D-027 · 统一工具平面

沿用 AI SDK 与 assistant-ui Toolkit 聚合工具。前端只上传受校验的名称、描述和 Schema，不能覆盖可信同名工具或取得 main 执行权限。

### D-028 · 本地附件事实来源与按需物化

本地托管附件是唯一事实来源，当前消息临时物化，历史图片按需读取并复验会话归属。不持久化 Base64，也不预建 Provider Files API、远端引用或上传缓存。

### D-029 · 动态上下文、工具提示与缓存边界

角色规则保持稳定，main 将当前日期和 IANA 时区作为原生 call options 加入模型上下文；精确时间按需调用工具。工具专属和高频执行状态留在各自作用域，缓存策略须按 Provider 实测。

### D-030 · Renderer 统一通知中心

页面瞬时反馈使用 Toast，需在当前表单修正的错误使用作用域 Inline。通知不替代业务状态、不持久化，避免重复反馈和常驻成功文案。

### D-031 · 单次生成式 TTS、角色声音与派生缓存

TTS 作为独立 Capability，模型和音色由可信服务解析，音频是可再生缓存。后续流式交付和 Unity 播放由 D-056/D-057 扩展；音色元数据及用户默认值以 D-033 为准。

### D-032 · 首版桌面分发、安装卸载与更新策略

Windows 首版采用 `app.katarune.desktop`、x64、per-user NSIS 离线安装器与薄 Win32 绘制扩展。默认卸载保留个人数据、更新不清理数据；全部删除须显式选择并检查链接目录和文件占用。旧 Qt 安装须先正常卸载，不能混用引擎文件清单。在线更新与发布后端尚未接入；公开发布前完成 Windows IV Authenticode 云 HSM、SHA-256/RFC 3161 时间戳，以及 macOS Developer ID、公证和 Stapling。证书供应商资格与采购仍待确认，当前内部包无签名、不自动公开。

### D-033 · Provider 自主发现与模型级音色元数据

发现和检查由各 Provider Definition 自主实现；可刷新的模型 metadata 与用户 settings 分离，刷新不覆盖用户默认值。音色是模型级元数据，目录只辅助选择，所有语音模型允许手动 Voice ID，供应商负责判断实际有效性。

### D-034 · 应用默认模型与设备级常规偏好

角色专用模型优先于应用默认；显式选择不可用时不得静默回退。主题、自动朗读和减少动态效果属于设备偏好；产品模型设置进入 SQLite，避免将全部配置塞入通用 KV。

## 形体与行为

### D-035 · Unity VRM 渲染技术验证基线

数字形体采用独立 Unity、URP、UniVRM 与窗口控制组件；现行运行时仅支持 VRM 1.0。复用成熟模型适配与渲染能力，避免 Web 和原生运行时重复实现骨骼驱动。

### D-036 · Unity 程序化形体第一阶段

程序化待机方案已由 D-050/D-064 的资源基线替代。标准化形体接口仍沿用，但不把历史呼吸、摆头或阶段状态当成当前默认表现。

### D-037 · Unity 原始材质与桌面灯光基线

保留模型原始材质，柔和描边作为可逆选项，灯光与抗锯齿由场景管理。避免为了统一外观破坏角色素材，实际观感按模型验收。

### D-038 · Unity Runtime Facade 与模型事务边界

Facade 和带 revision 的 Snapshot 是统一控制与权威状态边界，模型更换使用 prepare/validate/commit 事务。失败保留旧模型，Core、Motion、UniVrm、Runtime 职责分开。

### D-039 · Unity 预设动作第一阶段

早期固定预设动作入口已由 D-052/D-064 的资源清单替代。连续混合、取消与单一动作播放器边界保留，不在运行时增加角色名称或固定动作枚举分支。

### D-040 · Unity UI Toolkit 桌宠 HUD

已废弃：Unity 产品 HUD 由 D-063 的 Electron 胶囊与面板替代。Unity 继续负责角色窗口、操作区、音频和字幕。

### D-041 · Unity 角色行为 Core 最小领域边界

行为请求、定义、计划和实例保持分离；计划及权威实例由 Unity 内部构造。Core 不引用 Clip、Provider 或模型格式，避免资产与宿主倒灌到领域层。

### D-042 · Unity 行为资产定义与通用 Humanoid 播放边界

复杂行为资产以版本化 `.kbehavior` 定义并严格导入，保存能力、通道、片段、退出和许可信息；Motion 通过 Humanoid Binding 播放。用户角色包另按 D-064 使用 VRMA，不建立第二套播放器。

### D-043 · 桌面态语音陪伴与文字对话双模式

原桌面双模式方案已由 D-061/D-063 替代。角色和会话继续共用；“进入世界”与具体玩法仍是后续探索。

### D-044 · Unity 三样片资产表达与安全退出锚点

三份历史样片已退役，保留其证明的约束：通道和 Mask 必须符合素材实际覆盖，安全退出须连接合法姿态，许可按具体素材核验。不能借用旧样片通过记录证明新素材合格。

### D-045 · Unity 行为调度器与单 PlayableGraph 接管边界

Core 调度器唯一授予与释放通道，Motion 在同一播放图执行动作和恢复。手动动作与调度身体实例互斥；取消、终态回收和队列提升保持幂等。

### D-046 · Unity 提供表演工具与 Agent 完成屏障

Unity 提供实际可用的形体能力，宿主适配为受信任工具，不复制能力目录。工具化对白与 Agent 完成屏障部分已由 D-054 替代：请求接受和实际播放完成分开。

### D-047 · 退役历史 Quiet Idle，重新建立默认姿态基线

历史 Quiet Idle 与临时静止基线已退役或被 D-049/D-050 替代。资源缺失按当前兜底规则处理，不恢复旧程序化阶段或旧测试素材。

### D-048 · 桌面角色展示采用角色转台与投影构图

当前桌面角色通过投影构图调整，调试转台和预览服务于模型/资产验收。世界玩法与物理交互不在此条提前确定。

### D-049 · 待机微动改为身体驱动二级物理

程序化呼吸/摆头主驱动已由 D-050 替代。模型二级物理仍独立运行，不把环境风等同于已完成角色专属待机美术。

### D-050 · 本机测试默认待机改用 VRMA 资产

本机曾使用 VRMA 验证默认循环与手势；当前系统动作由 D-064 角色包清单决定。默认动画未配置时保持静态姿态，不假定旧本机动作存在或可分发。

### D-051 · 手动动作采用 Unity 原生连续打断混合

手动动作采用 Unity 原生连续权重混合；连续打断保留当前贡献，重复选择不无条件重播。复用既有 PlayableGraph 和取消边界，不增加动画库或并行过渡层。

### D-052 · 外部 Humanoid 动画资源包

现有 Humanoid 动作可由外部 `.motionpack` AssetBundle 提供，动作按稳定 ID 和实际清单登记。包受 Unity 版本/平台约束；用户角色包格式以 D-064 为准。

### D-053 · 文本优先的 AI 角色控制与输入排队

文本控制闭环已完成；工具化 `speak` 与按句阻塞方案已由 D-054 替代。普通聊天保持原生文本与现有 Agent 循环。

### D-054 · Unity 消费原生 Agent 事件流

完整转发原生聊天事件，由 Unity 建立对白、表情和动作时间线；工具执行回调只等待接受确认，播放终态另报。Agent 完成不等待播放排空，后台 drain 只管理资源回收，不重复执行流中的工具事件。

### D-055 · Unity 从启动即覆盖显示器的无边框窗口

Unity 从启动即覆盖目标显示器的物理屏幕，以透明窗口和局部命中实现桌面形体。角色构图变化不等于窗口几何变化；布局归属见桌面交互设计。

## 语音、桌面与资产

### D-056 · uLipSync 实时语音口型

对白音频和时间戳补入原生对白节点，由实际 AudioSource 驱动字幕与 uLipSync。音色 Profile 独立于 VRM，唯一口型平滑和停止清零避免重复驱动。

### D-057 · 完整文本输入与增量语音交付

完整文本输入后增量交付 PCM，独立管道和有界缓冲控制消费。断流冻结有效音频位置，迟到对齐不提前翻页；只缓存完整校验产物，不能以网络读取量当作播放时钟。

### D-058 · 首版离线语音输入

离线 ASR 采用 SenseVoiceSmall INT8、Silero VAD 与 Electron utilityProcess。识别权重显式下载并纳入内部包，麦克风音频不默认保存。

### D-059 · 按能力配置默认模型与语音双选

应用默认对话模型、TTS 模型与音色可被角色分别继承或固定，ASR 为全局配置。调用时由 main 解析和校验，不在前端建立另一套默认值规则。

### D-060 · 桌宠自动轮流语音对话与常驻识别模型

模型常驻和离线断句沿用；长按开启、播放时停止收音与轮流门控已被 D-061 替代。现行语音生命周期由唯一采集端管理。

### D-061 · 桌宠全双工语音与确认式插话

播放期间持续采集，疑似人声先暂停，最终文字确认才打断旧播放，误触恢复；语音输入优先于未发送文字。绑定校验、外放防自触发、旧生成收尾与运行 ID 清理避免跨会话误控制。

### D-062 · 紧凑图标栏与单层 Tab HUD

已废弃：紧凑 Tab HUD 由 D-063 的单层 Electron 面板替代。当前控件与快捷键只在桌面交互设计维护。

### D-063 · 桌宠窗口分工与紧凑面板

Unity 拥有角色、播放和字幕；Electron main 管理胶囊、面板、显示器、布局与绑定，不建独立字幕窗口或第二时钟。具体交互以 [桌面交互设计](../00-项目/桌面交互设计.md) 为准。

### D-064 · 角色包与资源管理边界

角色包 v1 组合立绘、VRM 1.0 与系统/自定义 VRMA；作者不指定全局 ID，main 生成身份、托管资源并做内容去重，Unity 实际验证与整体激活。契约和失败回滚只在 [角色包格式](../02-架构/角色包格式.md) 维护。

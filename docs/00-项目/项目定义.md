# 项目定义

## 名称

- 产品名称：**Katarune**（安装包、应用内及窗口标题统一使用此名称）
- 代码与仓库标识：`katarune`
- 对外标语：**新一代的数字伙伴~**

`Katarune` 结合了讲述（`kataru`）、符文（`rune`）与声音（`tune`）的意象，表示语言不只是被生成，也会通过声音、表情、动作与数字形体被演奏出来。

> 名称已经确定为项目工作名称。正式公开发布前仍需完成商标、域名和主要软件分发平台的可用性检查。

## 一句话定义

Katarune 致力于创造能与人共同生活、感知和探索世界的数字生命。

## 长期愿景

数字伙伴可以在电脑中与人互发消息、一起游戏，在虚拟世界中活动和玩耍；未来也可以拥有实体躯体，通过观察、移动与行动探索物理世界。电脑、虚拟世界和实体躯体都是其活动的载体。

当前以对话、角色记忆、语音和数字形体建立体验基线；桌面陪伴是阶段性实现。游戏互动、虚拟世界活动和实体躯体属于长期愿景，尚未实现，具体方案与推进顺序有待后续任务确定。

## 当前工程定位

现阶段以 Web 技术构建产品 Harness，组合现有模型与通用 AI 能力，聚焦角色、记忆、语音、数字形体和桌面交互。技术边界服务于当前实现，不限制数字生命的长期愿景。

## 我们要做什么

第一阶段以现有 ATRI Chat 能力为范围，重新建立更清晰的实现：

- 类 ChatGPT 的流式对话界面与会话管理。
- 用户可配置的模型供应商与模型选择。
- 角色设定、系统提示词与角色资产管理。
- 可持续的角色记忆。
- TTS 与 ASR 输入输出管线。
- VRM 表情、动作、镜头和口型驱动接口。
- 桌面应用需要的数据、权限和运行时管理。

## Harness 的边界

AI SDK 提供模型调用、工具调用、流式输出和 Agent 循环等基础能力。Katarune 不再围绕这些基础能力重新发明通用 Agent 框架，而是在其上构建产品 Harness。

Katarune 的核心责任是：

- 把角色身份、上下文、记忆和模型组合起来。
- 将模型决策连接到声音与数字形体。
- 管理本地数据、桌面权限和用户资产。
- 为不同能力定义稳定、类型安全的接口。
- 保证用户对供应商、数据和行为策略拥有控制权。

## 复用优先

以下领域原则上优先采用现有实现：

- 聊天 UI、流式消息和工具调用展示。
- 模型供应商协议与 Provider SDK。
- Agent 工具循环与停止条件。
- 通用文件、搜索、脚本执行和外部服务连接。
- 可满足需求的 MCP、ACP 或其他开放协议实现。
- UI 基础组件、表单、数据表格和资产选择器。

只有当现成实现无法满足 Katarune 的核心体验或安全边界时，才进入自研范围。

## 当前不做

- 为所有模型供应商维护一套自有协议实现。
- 重写通用聊天组件库或通用 Agent Runtime。
- 为尚未出现的需求预建复杂工作流系统。
- 在第一阶段扩展到现有产品没有的文件、终端和编码代理能力。
- 为了追求纯 TypeScript 而立即重写所有可工作的本地原生能力。
- 迁移 ATRI Chat 的用户数据、会话或旧文件记忆。

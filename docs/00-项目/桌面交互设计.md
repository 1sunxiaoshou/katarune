# 桌面交互设计

> 状态：已确认的桌面交互目标，尚未整体实现。本文只定义桌面态边界；具体视觉稿、尺寸、动效、正式摄像机交互和除 `Esc` 外的快捷键键位仍待构建与实机验证。2026-09-09 修订：现有展示转台主要用于调试，不据此锁定正式产品的镜头操作。

当前 Unity 已有透明覆盖层、径向 HUD 和角色展示转台，服务于模型、动作、材质与取景调试。下述双模式、快捷按钮排和底部交互区属于待实现目标，不能把现有调试入口视为最终产品交互，也不因目标界面尚未实现而提前删除调试能力。

## 当前优先切片：聊天输入与文本字幕

> 状态：2026-09-10 按 D-054 接入原生事件流字幕，取代 D-053 的工具化对白。

现有 Electron 聊天界面通过“连接桌宠”启动 Unity，并将当前角色与会话绑定到控制工具。Electron 将完整 AI SDK `UIMessageChunk` 流转发给 Unity，聊天界面与 Unity UI Toolkit 字幕使用原生文本事件，不定义 `speak` 工具。对白 TTS、时间戳字幕、uLipSync 与 Fish 增量 PCM 已按 D-056/D-057 接入，首版输入继续使用聊天界面。

字幕位于屏幕下方居中区域，正文居中，使用浅粉 `#F9DFEA` 背景（初始不透明度 90%）与深灰紫 `#493747` 正文，不使用白色文字描边；面板可用细淡白边框。字幕保持鼠标穿透，避开任务栏，按自然句和段落分段显示，长句优先在逗号或空格处分段，合并多余空白；具体宽度、字号、阅读速度与动效通过构建调试确定。无 TTS 时按阅读时长完成字幕显示并反馈；有声对白由实际音频播放游标推进分页和完成。

当前轮运行期间允许用户继续发送消息，界面显示排队状态，当前 Agent 原生流结束后即可处理下一条；Unity 独立维护跨轮播放队列。字幕和音频不阻塞 Agent 步骤，首版不做插话打断。

下述桌面双模式与快捷操作属于后续产品目标，不作为此切片的前置条件。

## 产品形态

言奏采用“一体双态”：桌面态保留轻量桌宠与陪伴能力，全屏世界态承载更深的角色活动。两者使用同一角色和持续状态，不建立彼此割裂的角色副本或对话上下文。

本轮只确认桌面交互。全屏世界态的玩法、视觉和实现方式继续开放讨论，不在本文中预设桌面工坊、AI 小镇、VRChat、大世界或其他尚未定案的产品形态。

## 桌面态的两个模式

桌面态默认进入“语音陪伴模式”，并可临时切换为“对话模式”。两种输入共享同一对话上下文，字幕和输入复用屏幕底部的同一区域，不增加第三套界面。

| 模式 | 底部区域 | 输入与麦克风 | 穿透边界 |
| --- | --- | --- | --- |
| 语音陪伴模式（默认） | 沿用逐句上移的字幕/转写表现，显示用户语音输入波形与 AI 回复 | 麦克风由用户手动开关；关闭时明确显示静音，不伪装为仍在收音 | 底部区域完全鼠标穿透，不提供可点击文字框 |
| 对话模式 | 同一底部区域进入可点击编辑状态并提供文字输入 | 进入时临时暂停麦克风，避免键盘噪声或语音与文字重复输入；退出时恢复进入前的麦克风开关状态 | 只有输入面板接收鼠标与键盘，其他透明区域继续穿透 |

Electron 继续负责完整对话历史。Unity 与桌面表现层只呈现当前陪伴交互所需的字幕、转写、输入和状态，不新增完整历史面板。

## 模式切换

- 小圆球提供键盘图标进入对话模式，并在对话模式中改为返回语音的按钮。
- 两种模式也可通过全局快捷键切换；具体键位仍待后续实机验证。
- `Esc` 明确用于退出对话模式。
- 文字和语音输入进入同一角色、同一会话上下文，不因模式切换建立新会话。
- 对话模式只临时暂停麦克风，不改写用户进入该模式前的麦克风选择。

## 小圆球与快捷操作

小圆球不再展开为放射菜单，而是根据当前位置向屏幕内侧展开一排快捷按钮，避免控件落到屏幕外。默认快捷项固定为：

1. 进入世界。
2. 文字输入。
3. 实时语音。
4. 更多。

实时语音开启后，同一快捷排上下文化为：

1. 进入世界。
2. 文字输入。
3. 静音。
4. 结束语音。

低频设置进入常规设置或“更多”，不继续堆入快捷排。本决策只确定信息架构和交互方向；“进入世界”本轮仅保留入口语义，不实现世界态。

## 状态与波形

小圆球只表达对话和语音所需的最小状态：默认、正在听/检测到用户说话、AI 正在说、静音。思考、工具执行、任务进度和其他复杂状态不进入小圆球。

麦克风开启必须持续且明确可感知，不能只在检测到语音的瞬间出现反馈；麦克风关闭必须明确显示静音。底部波形必须区分用户输入和 AI 输出，并至少使用形态、位置、方向、节奏或文字/图标中的一种非颜色线索，不能只靠颜色区分来源。

## 摄像机与布局

- 正式桌面摄像机是否固定、是否允许用户旋转，依据构建过程中的调试与实机体验再决定；不再预先限定为固定镜头。
- 当前展示转台用于检查模型、动作、材质和取景，保留其旋转、受限俯仰、缩放与构图能力；这些调试操作不自动成为正式用户功能。
- 缩放只允许有限、稳定的档位；具体档位与取景参数待视觉和实机验证。
- 字幕、转写、波形和文字输入复用底部同一区域，不再新增独立输入窗或第三套字幕 UI。
- 对话模式下只有实际输入面板取消穿透，角色与其余透明区域继续保持桌面穿透语义。

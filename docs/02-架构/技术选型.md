## 逻辑架构

```text
Electron Desktop
├── Sandboxed Renderer
│   ├── assistant-ui
│   ├── Chat and Asset Management
│   └── Audio Input / Playback
├── Preload
│   └── Minimal Typed IPC Bridge
└── Trusted Main Process / Katarune Harness
    ├── AI SDK Agent
    ├── Provider Registry
    ├── Character Context and Policy
    ├── TTS / ASR Capabilities
    ├── SQLite Thread and Message Store
    └── Optional Utility Processes / Protocol Clients
```

长期记忆不等于会话历史。P1 与 P2 先建立可恢复的线程和消息存储；记忆的提取、检索、更新、遗忘、用户控制与旧文件迁移在独立调查后再确定，不提前创建记忆表或工具接口。

VRM 仍属于言奏的目标能力，但渲染技术、资产边界和驱动接口尚未确定。当前原型不引入 VRM Runtime 或 VRM 工具；相关组件只在独立技术调查通过后进入上述运行时边界。

## 已验证的数据库与打包基线

- Drizzle Schema 位于 `src/main/database/schema.ts`；使用 `drizzle-kit@0.31.10` 生成版本化 SQL，并提交 `drizzle/` 目录。
- main process 启动时先打开用户数据目录中的 `katarune.sqlite` 并启用 WAL 与 busy timeout；执行需要重建表的版本化迁移时暂时关闭外键约束，迁移提交后立即恢复外键并通过 `foreign_key_check` 验证引用完整性。renderer 只能通过 preload 的最小类型化 IPC 读取状态。
- `threads` 保存 assistant-ui 线程元数据，`messages` 保存 `ThreadHistoryAdapter.withFormat` 产生的框架原生记录；renderer 使用对应 format adapter 的 `encode` / `decode`，言奏不维护第二套消息结构。线程删除通过 SQLite 外键级联清理消息。
- `provider_configs` 保存非敏感 Provider 创建配置；系统生成的 UUID `id` 同时作为数据库主键与 AI SDK Registry Provider Key，共享 Zod 契约限制可选 HTTP(S) Base URL、JSON 设置和已支持的 `provider_type`，API Key 与 Token 不进入 SQLite。
- `model_configs` 保存供应商外键、AI SDK Registry 模型类别、厂商原始模型 ID、可空显示名称、AI SDK 通用生成默认值和启用状态；类别允许 `languageModel`、`embeddingModel`、`imageModel`、`transcriptionModel`、`speechModel`、`rerankingModel` 与 `videoModel`，已有记录默认为 `languageModel`。同一供应商配置下的模型 ID 唯一，删除供应商时级联删除模型。默认模型后续由应用或角色配置引用，不进入该表。
- 开发环境和 Windows x64 unpacked 产物均通过首次迁移、写入、关闭、二次启动和同记录恢复验证；打包产物包含迁移文件，并为 Electron ABI 重建和 ASAR 解包 `better-sqlite3`。
- `npm run test:database` 会在 Electron ABI 下创建隔离的临时数据库，验证线程与 `ai-sdk/v6` 消息、Provider/模型配置的写入、同类型 Provider 多实例、同一 Provider 下模型 ID 唯一性、关闭重开恢复、更新和级联删除；同时覆盖已执行旧本地 Provider 身份迁移的数据库升级到合并后迁移链且保持 Provider、模型与外键引用，并在结束后清理测试数据。
- 当前 unpacked 目录约 442.54 MiB，其中 `app.asar` 约 50.22 MiB，`app.asar.unpacked` 约 45.16 MiB。该数据不是安装包下载体积，签名、更新、安装格式与体积优化仍待后续分发验证。

## 已验证的 AI 框架基线

- AI SDK 7 以 ESM 形式运行在 Electron main process；无密钥验证使用 `ai/test` 的确定性 mock model，覆盖 Provider Registry、`ToolLoopAgent` 和流式文本。
- `provider_configs.id` 是供应商实例身份的单一来源，同时作为数据库主键、模型外键目标与 AI SDK Registry 的稳定 `providerId`；`provider_type` 选择受支持的 Provider factory。`display_name` 可修改；API Key 与 Token 只通过 `credential_ref` 指向操作系统安全存储；`settings` 不接受任意 JSON，只能保存共享 Zod Schema 明确允许的非敏感配置。当前只开放已核实的 `includeUsage` 与 `supportsStructuredOutputs` 布尔项；接入具体 factory 时再收窄为对应 Provider Schema。
- `provider_type` 的唯一来源是 `src/shared/providers.ts`，值与 `@ai-sdk/<provider_type>` 的官方包名后缀一致。第一批枚举只包含 `gateway`、`openai-compatible`、`openai`、`anthropic`、`google`、`deepseek`、`xai`、`moonshotai` 与 `alibaba`。其中 `gateway` 使用 AI SDK 的 Gateway Provider；`openai-compatible` 用于兼容端点。其他官方 Provider 等到进入实际实现范围时再扩展；媒体生成、TTS、ASR Provider 不进入这组语言模型运行时枚举。
- 当前 `ai` 核心包直接包含 AI Gateway；已锁定 `@ai-sdk/openai-compatible@3.0.12`、`@ai-sdk/openai@4.0.16`、`@ai-sdk/anthropic@4.0.16`、`@ai-sdk/google@4.0.18`、`@ai-sdk/deepseek@3.0.12`、`@ai-sdk/xai@4.0.16`、`@ai-sdk/moonshotai@3.0.15` 与 `@ai-sdk/alibaba@2.0.14`。Runtime 只使用这些包公开的 factory，并在配置变化后重建 Registry。Ollama、OpenRouter 等社区或兼容服务当前通过 `openai-compatible` 表达。
- `model_configs.settings` 当前只对应 AI SDK 通用 `LanguageModelCallOptions` 的受控子集，包括最大输出 token、temperature、top-p、top-k、存在/频率惩罚、停止序列和 seed；Runtime 使用 `wrapLanguageModel` 与 `defaultSettingsMiddleware` 应用默认值，不建立第二套调用设置。其他模型类别的专属设置和解析器尚未实现，且不会回退到语言模型调用。
- main process 使用 Electron 异步 `safeStorage` 加密凭据，密文保存在用户数据目录的独立文件中，SQLite 只保存 `credential_ref`。preload 只接受替换和清除凭据的写入式请求，不提供读取、列举 secret 或由 renderer 指定 `credential_ref` 的方法；操作系统加密不可用时不启动 AI Runtime。`npm run test:credentials` 已在真实 Electron 进程验证加密、解密和删除。
- `npm run test:ai:deepseek` 只在显式执行时从被 Git 忽略的 `.env.local` 读取 `KATARUNE_TEST_DEEPSEEK_API_KEY`，并已验证 `safeStorage → credential_ref → DeepSeek factory → Registry → model_configs → generateText` 的真实链路。该命令会调用付费外部 API，不属于普通 `npm test`。
- assistant-ui 的 `useChatRuntime`、`RemoteThreadListAdapter`、格式化 `ThreadHistoryAdapter` 与 `AssistantRuntimeProvider` 已在 sandboxed renderer 中成功挂载，当前显式禁用发送，不伪造已配置的模型能力。
- Provider Factory、动态 Registry、显式模型连接测试、Provider/模型设置页与受信任密钥录入已接入；默认模型和角色级模型选择尚未实现。assistant-ui 官方默认 HTTP 传输不能直接视为言奏的最终方案，main 与 renderer 之间的取消、错误、工具调用和背压语义需要在 P2 前确定。
- renderer 已接入 assistant-ui 官方 Registry 成品 Thread、shadcn/ui `base-nova`、Tailwind CSS 4、Base UI 与 Lucide；旧 Iconoir、自研 Button/IconButton/Surface 及平行设计系统 CSS 已删除。Provider/模型设置保留可信数据链路，界面改用 shadcn Card、Tabs、Input、NativeSelect、Switch、Badge 等默认组件组合，设置分区导航直接使用纵向 Tabs，不引入 Swiper。字体、内容宽度、动效、圆角、阴影、表面、边框、信息密度和组件状态全部采用上游默认，不建立平行 token；产品层只维护普拉娜/阿洛娜颜色映射、主题选择、左下角设置入口和未来会话时间轴。
- 接入完整 Thread、Markdown、reasoning、附件和工具展示后，当前 renderer 初始 JavaScript 约 1,111.50 KiB，按实际访问路径拆分的设置页约 52.17 KiB，样式约 91.03 KiB。初始 chunk 已触发 Vite 的 500 KiB 警告；后续应在接通真实聊天链路时分析按功能拆分的可行性，不通过调高阈值掩盖问题。

## 共享契约与测试基线

- IPC channel、Zod Schema 与推导类型集中在 `src/shared/ipc.ts`。main process 在产生状态时校验，preload 在结果进入 renderer 前再次校验，renderer 不通过类型断言跳过运行时边界。
- sandboxed preload 将 `zod/mini` 直接打入单文件产物，不在运行时加载第三方模块；加入线程、Provider、模型配置与写入式凭据 IPC 契约后，当前 preload 约 60.83 KiB，已验证不存在外置 Zod `require`。
- `npm run test:ui` 构建应用后使用不可见 Electron 窗口验证设置页加载、左下角设置入口、Provider/模型内容和双主题切换，并断言两套主题只改变颜色而共享 shadcn 默认圆角尺度。
- `npm test` 运行全部 Node 单元测试；当前覆盖 IPC 契约、安全凭据仓库、九种官方 Provider factory、动态 Registry、连接探测边界，以及无网络、无密钥的 `ToolLoopAgent` 和流式输出。
- Node 单元测试不替代 Electron 实际运行、`better-sqlite3` ABI、ASAR 和 Windows 产物验证。数据库边界使用 `npm run test:database`，涉及打包边界的变更仍须执行 Windows 产物验证。

## 首个原型需要回答的问题

首个技术原型应使用一条最小链路验证已选组合，并暴露仍待解决的版本与打包风险：

1. 启动桌面应用。
2. 读取本地供应商配置。
3. 流式完成一次模型回复。
4. 执行一个类型安全、无高权限的本地测试工具。
5. 将线程写入 SQLite 并在重启后恢复。
6. 完成 Windows 开发构建和可分发构建。

需要记录的指标包括：

- 冷启动时间与空闲内存。
- 安装包和解压后的体积。
- `electron-vite` 下 main、preload 与 renderer 的 TypeScript 开发体验和调试链路。
- `better-sqlite3`、音频和 ASR 等原生依赖的重建与打包难度。
- AI SDK、assistant-ui 与测试工具的兼容性。
- `electron-builder` 生成的 Windows 产物、签名、更新和崩溃诊断能力。

## 暂不引入的抽象

- 自定义 Agent 基类体系。
- 自定义模型 Provider 通用协议。
- 与 AI SDK 重复的消息流协议。
- 为每个工具实现自有远程调用标准。
- 在验证单 Agent 闭环前设计多 Agent 平台。

# 技术选型

本文记录当前共识、已经验证的版本基线与仍需验证的候选项，不提前锁定尚未讨论完成的能力。

## 离线语音与默认配置

首版 ASR 使用 `sherpa-onnx-node@1.13.8`、SenseVoiceSmall INT8 和 Silero VAD，在 Electron utilityProcess 中离线推理。聊天中的单次听写填入草稿；桌宠连接后可自动开麦并持续检测，最终识别结果按当前绑定送入聊天队列。打断须等识别文字确认，误触恢复原播放。真人耳机连续对话、外放防自触发和 Player 联调已由使用者实机验收通过。详见 [D-058](../01-决策/决策记录.md#d-058--首版离线语音输入)、[D-060](../01-决策/决策记录.md#d-060--桌宠自动轮流语音对话与常驻识别模型) 与 [D-061](../01-决策/决策记录.md#d-061--桌宠全双工语音与确认式插话)。

应用默认对话模型、TTS 模型与音色保存在 SQLite；角色可分别继承或固定。ASR 是全局配置。main 在调用时解析有效模型与音色并校验可用性，renderer 只展示选择状态。详见 [D-059](../01-决策/决策记录.md#d-059--按能力配置默认模型与语音双选)。

## 逻辑架构

```text
Electron Desktop
├── Sandboxed Renderer
│   ├── assistant-ui
│   ├── Chat and Asset Management
│   └── Audio Input / Playback
├── Preload
│   └── Minimal Typed IPC Bridge
└── Trusted Main Process / Katarune Harness
    ├── AI SDK Agent
    ├── Unity Capability Tool Adapter
    ├── Provider Registry
    ├── Character Context and Policy
    ├── Role-scoped Markdown Memory Wiki
    ├── TTS / ASR Capabilities
    ├── Speech Synthesis Host Port
    ├── SQLite Thread and Message Store
    └── Optional Utility Processes / Protocol Clients

Unity Avatar Runtime (independent technical slice)
├── Capability Tool Provider: expression / speech / action / performance catalog
├── Core: state snapshot / behavior settings / AvatarPoseFrame / behavior-performance domain contracts
├── Motion: strict behavior asset / Humanoid rig binding / generic PlayableGraph playback
├── UniVrm: loader / rig-binding adapter / expression and control-rig driver / MToon outline
└── Runtime
    ├── AvatarRuntimeFacade (single control and state boundary)
    ├── AvatarRuntimeSession (prepare / validate / transactional commit)
    ├── SceneRig / Window / subtitle rendering
    └── Control connection and desktop input zones
```

长期记忆不等于会话历史。根据 [D-016](../01-决策/决策记录.md#d-016--角色级-memory-wiki)，每个角色在 `userData/memory/agents/<character-id>/` 拥有独立 Markdown Wiki：`index.md` 与 `profile.md` 作为受限核心上下文注入，其余页面通过 `wiki_search`、`wiki_get` 和 `wiki_apply_patch` 按需操作。角色 ID 由 main process 绑定而不进入工具输入；revision、跨进程锁、原子替换和删除暂存负责并发与生命周期一致性。SQLite 不保存记忆正文，也不迁移 ATRI Chat 的旧文件记忆。

VRM Runtime 使用独立 Unity 工程、URP/MToon、UniVRM 和 UniWindowController。运行时只加载外部 VRM 1.0；模型替换遵守 `prepare → validate → commit`，Facade 发布带 Revision 的权威快照。Core、Motion、UniVrm 和 Runtime 分别负责领域契约、PlayableGraph 与动作包、模型适配、窗口及跨进程控制。手动动作通过外部 `.motionpack` 以稳定字符串 ID 登记，新增动作不重建 Player；正式动作美术仍待选择。

桌宠现行窗口边界见下文及[桌面交互设计](../00-项目/桌面交互设计.md)。

手动动作播放按 [D-051](../01-决策/决策记录.md#d-051--手动动作采用-unity-原生连续打断混合) 使用 Unity 原生 `AnimationClipPlayable` 与 `AnimationMixerPlayable`，不引入额外动画库。基础呼吸与手动动作统一固定 `0.25s` 线性过渡；连续打断保留所有贡献输入的当前权重，重复点击当前动作不重播。既有调度表演分支和 Core 通道仲裁不变，仍由同一 PlayableGraph 输出到 Control Rig。

Windows Unity 透明窗口按 `FullScreenWindow` 与原生分辨率启动，UniWindowController 负责透明和手动穿透。主屏启动时不重复设置窗口尺寸；面板切屏或显示器变化时按目标屏幕实际物理边界移动同一 HWND。角色移动与缩放只更新 Unity 相机投影。面板提供目标屏幕选择，胶囊和面板保持在 Unity 上层。VRM 加载明确使用 UniVRM 官方 URP 材质生成器，避免首帧前自动检测误选 Built-in 管线。此切片不实现世界玩法、模式过渡或角色拖拽。

## 文本优先的角色控制切片（已实现开发基线）

按 D-054，连接桌宠直接使用框架已有的会话 ID，不提前创建数据库会话；首次发送消息时沿用框架初始化与标题生命周期。启动阶段校验角色存在，实际聊天请求仍校验会话归属。Electron main 通过本机 Named Pipe 向当前绑定的 Unity 转发完整 AI SDK `UIMessageChunk` 流；Unity 从原生文本事件驱动字幕时间轴，并在角色窗口内显示，推理不作为对白。不定义 `speak` 工具，聊天与历史直接保留原生文本。桌宠控制工具可用时，在原有角色设定后追加用户确认的身体提示，说明字幕对白、真实工具动作与自主选择时机；未连接时不注入。`avatar_action` 和 `set_expression` 由 SDK 工具执行回调触发并接收 Unity 接收确认，实际播放状态另行报告；观察工具事件不重复执行。字幕播放独立于 Agent 步骤，原生流结束立即结束聊天 UI 的运行状态并允许下一轮生成；Unity 自行维护跨轮播放队列。Electron 的后台 drain 确认只管理借出音频的资源生命周期，不参与聊天完成判定。按 D-056，原生对白块结束后旁路合成，音频和时间戳补入同一 Unity 节点；Unity 播放游标驱动字幕，uLipSync 经 Facade 和行为系统输出口型。

聊天通过公开的 `useChat` 与 `useAISDKRuntime` 接口适配；原生文本事件直接作为对白并持久化，不定义 `speak` 工具。绑定桌宠的会话对 `sendMessage` 做顺序等待，当前运行结束后发送下一条输入；队列目前只在内存中。对白 TTS、时间戳与 uLipSync 已接入并进行声画验收；自动重连和安装包内置 Unity 尚未接入，具体状态见[推进计划](../03-规划/角色行为与动画系统推进计划.md#当前优先确认并打通文本控制闭环)。

## 对白语音与时间戳

D-056 的实现链路为原生 text 块 → 独立供应商时间戳能力 → Unity 对白节点 → AudioSource → uLipSync → Facade/行为系统 → VRM。按 D-057，Fish 使用 `/v1/tts/stream/with-timestamp` 增量接收 PCM 与片段，经独立二进制管道交给 Unity 有界缓冲播放，AudioSource 播放游标映射出的有效音频样本驱动流式字幕；完整文件与缓存仍走 WAV 播放。普通 `/v1/tts`、`doGenerate()` 和连接测试不变。OpenAI/Google 沿用普通合成；有声、无声统一由 Unity 的 AvatarSpeechSubtitles 按句分页，长句再按停顿标点和长度拆分。可靠片段时间用于映射页边界，缺失时按音频总时长估算切换，不再整块显示。朗读文本通过统一 Markdown AST 提取，聊天正文保持原样。

main 完整文件路径每轮只执行一个合成请求，最多预取下一块，以 runId/dialogueId 补充音频；Unity 的原生时间线保留对白与动作顺序，并由 `AudioSource.timeSamples / clip.frequency` 驱动字幕。新播放实例使用独立 ID，取消先由 Unity 释放资源，再回收文件。自动表演期间禁用历史朗读，main 再次校验。没有匹配桌宠时使用浏览器；开始 Unity 播放后失败不重播到浏览器。

uLipSync 3.1.5 锁定提交 `ece3272762f2148dd8d3e658ec04fcbd79d4d97e`。AudioSource 的上游代理把实际采样交给隔离的分析器，生命周期门控避免卸载后回调；每次播放创建新的分析状态。唯一口型平滑位于行为系统，清空输入直接归零。Profile 采用上游 JSON，按供应商实例/模型/Voice ID 定位，开发校准与录制入口见[工程规范](../04-开发/工程规范.md#语音与-ulipsync-开发验收)。

流式供应商通过可选 `streamSpeech()` 暴露格式、音频、对齐和结束事件。当前完整 text 块输入不变；Unity 到达对白后连接，供应商读取受消费背压约束。Unity 用 750 毫秒起播和 1.5 秒断流恢复缓冲；不足整次 PCM 回调时保持样本并输出静音，播放位置和字幕时钟暂停。下一页对齐未到达时保持当前页，后续对齐可修正页边界；仅完整校验后的 PCM 封装 WAV 并缓存，流中断不缓存。

普通缓存保持兼容；时间戳产物采用独立命名空间，模式与供应商实例参与键计算，单个原子文件包含音频、哈希和片段。播放临时目录限定在 userData/speech-playback，启动时仅清理已退出进程留下的自有 session 目录，无数据库迁移。

实时语音的完整识别文本由 main 校验当前绑定后，以 `user-subtitle` 消息经现有 Unity 控制管道即时展示。它不占用动作/语音队列，也不触发忙碌状态；Unity 在本地加“你：”前缀并使用浅色气泡，角色字幕自动接替。文本保持纯文本，双端限制长度。

桌宠全双工控制按 D-061 建立在现有语音链路上：renderer 的采集和 VAD 在 Agent 生成与 Unity 播放期间持续运行；主进程只接受当前角色与线程绑定的状态及播放控制 IPC。VAD 暂停当前运行的 Unity AudioSource、uLipSync 和字幕时钟，SenseVoice 最终文字确认后才静音旧运行并将新用户输入插到待发文字前；误触恢复原播放位置。外放时先请求系统回声消除，并在正在播放时丢弃与最近助手文本高度重合的转写作为轻量防自触发保护。旧 Agent 生成最多等待 10 秒，超时取消并保留部分回复，聊天消息元数据记录播放打断和生成是否完整。Unity 以运行 ID 清理未播对白和表演，并回报实际播放状态。采集帧只经既有 ASR utilityProcess 推理，音量反馈只传递归一化级别，不保存原始麦克风音频。

## 已验证的数据库与打包基线

- Drizzle Schema 位于 `src/main/database/schema.ts`；使用 `drizzle-kit@0.31.10` 生成版本化 SQL，并提交 `drizzle/` 目录。
- main process 启动时先打开用户数据目录中的 `katarune.sqlite` 并启用 WAL 与 busy timeout；执行需要重建表的版本化迁移时暂时关闭外键约束，迁移提交后立即恢复外键并通过 `foreign_key_check` 验证引用完整性。renderer 只能通过 preload 的最小类型化 IPC 读取状态。
- `threads` 保存 assistant-ui 线程元数据，并以不可变的 `character_id` 外键绑定角色；所有线程 IPC 和 adapter 查询均携带角色范围。`messages` 保存 `ThreadHistoryAdapter.withFormat` 产生的框架原生记录；renderer 使用对应 format adapter 的 `encode` / `decode`，言奏不维护第二套消息结构。线程删除通过 SQLite 外键级联清理消息。
- 长期记忆正文不进入 SQLite；Markdown Wiki 与 SQLite 分别承担记忆正文和产品关系数据的事实来源，二者只通过稳定 `character.id` 建立目录归属。
- `provider_configs` 保存非敏感 Provider 创建配置；系统生成的 UUID `id` 同时作为数据库主键与 AI SDK Registry Provider Key，共享 Zod 契约限制可选 HTTP(S) Base URL、JSON 设置和已支持的 `provider_type`，API Key 与 Token 不进入 SQLite。
- `model_configs` 保存供应商外键、动态检查得到的单一 AI SDK Registry 模型类别、厂商原始模型 ID、可空显示名称、通用 `metadata`、能力 `settings` 和启用状态。`metadata` 属于可刷新的模型检查结果，`settings` 属于用户拥有的模型级调用默认值；两者的共享 IPC 外层均为最大 64 KiB 的 JSON Object 或 `null`，写入和 Runtime 解析前由 `model_type` 对应的 Definition/Capability Schema 再次验证。Speech 的 `metadata.voices` 保存音色 ID、展示名称和可选描述，`voices = null` 表示无法枚举；`settings.defaultVoiceId` 保存该模型的默认 Voice ID，刷新 metadata 不读取或改写它。唯一约束为供应商配置与模型 ID；删除供应商时级联删除模型。无 Adapter 或 settings 失效的记录不自动删除或改写。
- `characters` 是角色与 Agent 的唯一实体，保存角色名称、立绘资产外键、卡片专用的 `0–1` 焦点位置与 `1–3` 缩放、可空语言模型软引用、成对出现的可空声音模型软引用与 voice、系统提示词和时间戳，并按创建时间倒序展示。单行 `app_state` 以外键保存活动角色。角色表为空时从经过 Schema 校验的 `resources/characters/default-character.json` 初始化；已有数据库始终优先。新角色先作为 renderer 草稿存在，离开且有实际改动时才由 main process 生成 UUID 并一次写入；无改动草稿不进入 IPC 或 SQLite。删除角色显式事务清理所属线程，消息沿线程外键级联删除；若删除活动角色则先切换到相邻角色，唯一角色拒绝删除。语言或声音模型被删除、禁用或改变类别后保留原 ID，由角色编辑页显示不可用状态。
- 单行 `app_settings` 保存可空应用默认语言模型外键。更新 IPC 只接受当前可调用的语言模型；删除模型或 Provider 时由 SQLite `ON DELETE SET NULL` 清空，禁用时保留引用。角色语言模型为空时继承应用默认；显式角色模型始终优先且不可用时不回退，聊天与标题生成共用该解析规则。
- `assets` 是按 `character_portrait/character_vrm/chat_attachment` 区分类别的通用资产注册表；`ready` 记录必须具备 MIME、字节数、SHA-256 和原始文件名，`missing` 记录保留稳定引用但不伪造元数据。三类文件都保存在用户数据目录的无扩展名不可变 `assets/<uuid>` 对象中，renderer 不接收 Base64、storage key 或绝对路径。当前 PNG/JPEG/WebP 立绘先经 `asset-staging/<uuid>.tmp` 暂存并通过 `katarune-asset://staged/<uuid>` 预览；聊天图片可通过正式资产协议预览，非图片附件只显示元数据；VRM 本期只固定存储边界。
- 聊天附件已实现“本地资产事实来源、当前消息临时物化、历史图片按需读取”。assistant-ui 负责选择、拖拽、粘贴、生命周期和 `view_chat_image` 状态 UI，`KataruneAttachmentAdapter` 经 preload/IPC 导入副本并产生 URL 为 `katarune-asset://asset/<uuid>` 的 AI SDK `FileUIPart`。SQLite 保持框架原生消息格式，`message_assets` 负责会话范围授权与垃圾回收。模型调用前只保留最后一条用户消息的原始附件，更早附件投影为轻量引用；当前附件通过 `ToolLoopAgent.experimental_download` 物化，历史图片由 main 工具复验归属与完整性后使用 AI SDK `toModelOutput` 仅向当前工具步骤返回文件内容。工具持久化结果不含 Base64，旧结果不会自动重放图片。`view_chat_image` 对所有语言模型注册，不维护 Provider 能力表；不支持时由 Adapter/Provider 抛错并显示脱敏提示。不使用 `uploadFile()`、`providerReference`、远端文件缓存或 Data URL 持久化。限制为 25 MiB/文件、当前消息 10 个/50 MiB、历史图片 4 张/50 MiB和单次回复合计 100 MiB。
- 模型发现和检查由对应 `ProviderDefinition` 实现，main process 编排器只负责安全凭据、Schema 校验和持久化。导入时 `inspectModel()` 的明确类型覆盖 renderer 提示，冲突时拒绝；未知类型必须由用户确认。检查结果写入模型的 `metadata`；检查给出的建议初始 settings 仅在创建该模型记录时采用，随后由用户独立控制。刷新失败不覆盖旧 metadata，刷新成功也不修改 settings。Gateway 原生目录、LiteLLM 类型补充、完整快照与在线未命中回退规则保持不变：401/403 不回退，未知自定义 Base URL 与 Gateway 失败时不以静态目录伪装实时库存。
- 新建供应商在凭据保存后自动获取并添加已知类别模型；main process 复用本次发现结果执行导入检查，批次结束后刷新 Runtime。已有配置保持不变，未知类别只作为当前设置页的临时列表，仅在“全部”列表显示，用户按需选择类别后添加，不设独立分类；公共目录兜底不自动入库，不增加目录持久化缓存或后台同步。

## 已验证的 AI 框架基线

- AI SDK 7 以 ESM 形式运行在 Electron main process；无密钥验证使用 `ai/test` 的确定性 mock model，覆盖 Provider Registry、`ToolLoopAgent` 和流式文本。
- `provider_configs.id` 是供应商实例身份的单一来源，同时作为数据库主键、模型外键目标与 AI SDK Registry 的稳定 `providerId`；`provider_type` 选择代码级 Provider Definition。共享 Provider 配置只声明 renderer 表单所需的 `credentialMode`。Definition 提供 discovery、inspection、settings Schema、AI SDK factory 和实际 Capability Adapter；可调用模型 ID 由 main process 根据这些方法与当前配置动态返回，不维护供应商支持类型数组。
- `provider_type` 的唯一来源是 `src/shared/providers.ts`。当前枚举包含 `gateway`、`openai-compatible`、`openai`、`anthropic`、`google`、`fish-audio`、`deepseek`、`xai`、`moonshotai` 与 `alibaba`。其中 `gateway` 使用 AI SDK 的 Gateway Provider；`openai-compatible` 用于兼容端点并允许无凭据的本地服务；Fish Audio 没有已锁定的官方 AI SDK Provider，项目内只实现其 `SpeechModelV4` 薄适配，不新增 SDK 依赖。统一 AI SDK Provider Registry 同时解析语言与语音模型；其他类别或供应商是否可调用继续由 Definition 的实际 Capability 方法决定。
- 当前 `ai` 核心包直接包含 AI Gateway；已锁定 `@ai-sdk/openai-compatible@3.0.12`、`@ai-sdk/openai@4.0.16`、`@ai-sdk/anthropic@4.0.16`、`@ai-sdk/google@4.0.18`、`@ai-sdk/deepseek@3.0.12`、`@ai-sdk/xai@4.0.16`、`@ai-sdk/moonshotai@3.0.15` 与 `@ai-sdk/alibaba@2.0.14`。Runtime 只使用这些包公开的 factory，并在配置变化后重建 Registry。Ollama、OpenRouter 等社区或兼容服务当前通过 `openai-compatible` 表达。
- `model_configs.settings` 的语言能力 Schema 当前对应 AI SDK 通用 `LanguageModelCallOptions` 的受控子集，包括最大输出 token、temperature、top-p、top-k、存在/频率惩罚、停止序列和 seed；Speech 能力 Schema 当前包含模型级 `defaultVoiceId`。Runtime 对语言模型使用 `wrapLanguageModel` 与 `defaultSettingsMiddleware` 应用默认值，Speech 连接测试从同一模型 settings 读取 Voice ID。不同 Provider 或模型类别的差异留在各自 Definition/Capability Schema；未经验证的数据不得持久化或调用，其他模型类别不会回退到语言模型。
- main process 使用 Electron 异步 `safeStorage` 加密凭据，密文保存在用户数据目录的独立文件中，SQLite 只保存 `credential_ref`。preload 只接受替换和清除凭据的写入式请求，不提供读取、列举 secret 或由 renderer 指定 `credential_ref` 的方法；操作系统加密不可用时不启动 AI Runtime。`npm run test:credentials` 已在真实 Electron 进程验证加密、解密和删除。
- `npm run test:ai:deepseek` 只在显式执行时从被 Git 忽略的 `.env.local` 读取 `KATARUNE_TEST_DEEPSEEK_API_KEY`，并已验证 `safeStorage → credential_ref → DeepSeek factory → Registry → model_configs → generateText` 的真实链路。该命令会调用付费外部 API，不属于普通 `npm test`。
- assistant-ui 的 `useChatRuntime`、`RemoteThreadListAdapter`、格式化 `ThreadHistoryAdapter` 与 `AssistantRuntimeProvider` 已在 sandboxed renderer 中成功挂载。标题流使用其官方底层包 `assistant-stream@0.3.26` 的 `createAssistantStream`，不手写流分块。角色模型和应用默认模型均为空时保持发送禁用。角色存在可用 SpeechModel 与 voice 时，`useChatRuntime` 注入 `KataruneSpeechSynthesisAdapter`，消息操作区直接使用 assistant-ui 原生朗读/停止状态；设备级自动朗读仅在无匹配活动桌宠时，于当前可见角色最终回复稳定完成后调用同一消息 `speak()`；匹配当前会话的活动桌宠始终由 main 驱动对白语音，不受该开关影响，renderer 抑制该轮完成后的重复朗读。
- main process 的 TTS 服务按角色权威配置解析同一个 Provider Registry 中的 SpeechModel，并把角色保存的不透明 Voice ID 原样交给 Provider；音色目录只服务 UI 选择，不参与保存或调用白名单。OpenAI、Google Gemini 与 Fish Audio Adapter 都请求并校验 WAV；Google Provider 包负责把返回的裸 PCM 无损封装为 WAV。角色界面按 `speechModel` 类型构建“可搜索目录 + 手动 Voice ID”编辑区，目录为空时只显示手动输入。缓存、取消、错误清洗和 renderer 播放继续沿用单次生成式 TTS 边界。
- Provider Factory、动态 Registry、显式模型连接测试、Provider/模型设置页、应用默认模型、角色级模型选择与受信任密钥录入已接入。renderer 为窗口内访问过的每个角色按需保留独立 `RemoteThreadListRuntime`，每个线程 Runtime 再持有独立 `AssistantChatTransport`；其自定义 Electron fetch 通过 preload 管理的每次运行独立 `MessageChannel` 接收 main process 产生的 AI SDK SSE 字节流。pull 帧提供背压，cancel 或端口关闭触发 main 中的 `AbortController`，不同线程和角色可并发生成且传输状态互不复用。main 根据线程绑定读取角色、模型和系统提示词，不信任 renderer 提交的模型或 Agent 配置，并登记活动流以在线程、角色或窗口销毁前定向取消。聊天 Agent 通过应用级 `AISDKToolkit` 聚合层合并 main 中的可信工具、当前模型对应的 Provider 原生工具与 IPC 校验后的 frontend tools；前端只上传名称、描述和 JSON Schema，不上传执行函数，且不能覆盖任一可信同名工具。`ToolLoopAgent` 最多执行 8 步，renderer 在前端工具结果或审批响应完成后使用 AI SDK 官方条件自动续跑。默认 main 工具只有无参数、无高权限的 `get_current_time`，按需返回用户设备当前的带 UTC 偏移本地时间和 IANA 时区；OpenAI、Anthropic、Google、xAI 及其 AI Gateway 上游模型按各 SDK 官方名称条件化装配原生 Web Search/Web Fetch/URL Context，其他 Provider 不伪装支持，当前不接第三方搜索后端或自研计算器。首次对话完成后，assistant-ui 的标题生命周期通过普通 invoke IPC 请求 main 创建独立标题 Agent；该 Agent 复用相同的角色优先、应用默认继承规则与系统提示词，但不复用聊天实例或工具，输出限制为 80 token、结果限制为 30 字符并直接写入 SQLite。当前不恢复应用退出时仍在运行的流。
- renderer 使用 assistant-ui Registry 成品 Thread、受控 Model Selector 与 shadcn/ui `base-nova`、`neutral` 默认配置，底层为 Tailwind CSS 4、Base UI 与 Lucide；Provider 品牌图标来自 Lobe Icons 的静态 SVG 包并随应用打包，OpenAI-compatible 继续使用通用网络图标。亮色/暗色主题复用 shadcn 默认语义 token，以根元素 `.dark` 类切换并将偏好保存在 renderer 本地，不维护产品级颜色系统、基础组件包装层或平行视觉 token。设置页以“常规 / 模型”一级 Tab 组织；常规页与模型页使用相同的右侧视图宽度和方角外边框，内部采用无底板连续设置行，提供可搜索默认语言模型、紧凑亮暗主题、自动朗读和减少动态效果，后三项为设备级 renderer 本地偏好；模型页实时展示 SQLite 中的供应商配置，并按共享 `model_type` 契约展示模型列表与类别筛选。发现模型只展示模型名称、ID 和已确定的单一类型；目录未知或冲突时显示问号，添加时强制选择。供应商条目通过悬停或聚焦操作编辑和删除，供应商与模型的创建/编辑分别复用通用 Dialog，删除复用通用确认 Dialog。模型区顶部只保留搜索、创建和获取操作；搜索对名称、ID、类别、状态和供应商执行本地分词 AND 匹配，并与类别筛选叠加。
- renderer 根节点挂载统一通知中心。业务通过言奏通知 API 发送通知，Base UI Toast 只承担右上角 Portal、三条上限、计时、键盘导航和播报，Zustand 内存 store 按 scope 管理 Inline；两种渠道均不进入 IPC、SQLite 或重启恢复。页面级一次性操作的成功、警告、失败与短时加载统一使用 Toast，模型列表、角色页和会话列表不挂载 Inline outlet；只有需要用户在当前 Dialog 或表单中就地修正的错误才使用对应 scope 的 Inline。页面加载/空状态、角色自动保存、确认框内部错误以及 assistant-ui 模型生成、流和工具错误继续由所属状态表达，不并入通用通知。
- 聊天页使用可完全收起的弹性左侧栏：顶部直接复用角色页列表的 `CharacterCard`，中段通过 assistant-ui `ThreadListPrimitive.Root/New/Items` 和 `ThreadListItemPrimitive.Root/Trigger/Title` 渲染当前角色的普通会话，左下角始终悬浮无容器底板的设置与内容显隐图标按钮，侧栏在展开状态下为其预留底部空间。会话项不建立镜像状态，切换、重命名、归档和删除直接使用当前角色的 `RemoteThreadListAdapter`；消息持久化后调用线程列表 `reload()`，使 assistant-ui 在窗口运行期间同步最新标题、消息活动时间和排序。SQLite 的 `last_message_at` 只随消息写入更新，普通 `updated_at` 继续记录标题、归档等元数据修改，列表按前者排序。Base UI Context Menu 只承担右键菜单交互。归档项不进入星轨，管理入口待后续规划。角色卡与列表作为同一可访问性区域分层显隐；隐藏时侧栏收至零宽度，聊天主区扩展至完整窗口，左下角按钮的几何位置与外观保持不变。显隐偏好仅保存到 renderer 本地，不进入 SQLite、IPC 或角色状态。
- 角色页继续以设定集式结构组织名称、模型、系统提示词、完整立绘主视觉和右侧角色列表。新增图标将临时角色插入列表顶部；切换角色、返回聊天或前往设置时提交有改动草稿，无改动草稿直接丢弃。“更换形象”按钮与右键菜单打开简单包选择弹窗；完整立绘来自 `portrait`，两处卡片来自 `thumbnail`（缺失则回退完整立绘），1:1 容器内等比显示，旧裁切入口与依赖已删除。角色删除只从复用会话样式的右键菜单发起，并通过通用确认框显示所属会话数量。离开角色页时提交候选活动角色；首次访问目标角色时创建其 Runtime 并显示空白新对话，再次切回时恢复原先选中的线程和后台运行。非活动 Runtime 保持 Hook 与 history adapter 挂载但不渲染聊天 DOM；模型引用更新通过角色配置 Context 影响后续发送门控，不以配置字段作为 Runtime key。
- renderer 随应用打包 `Noto Sans SC Variable` 和 `Yellowtail`；后者仅用于角色卡片名字下方的拼音／罗马字，保留角色签名感。角色名称、会话标题、欢迎标题、角色页、设置页及普通文本使用常规无衬线字体，代码继续使用等宽字体。界面以主文字、次要文字、辅助信息三档颜色和 400／500／600 字重区分层次，浅色与深色主题分别定义；已移除宋体和英文衬线字体的引用及依赖。

| --- | --- | --- | --- |
| 角色身份、长期行为与安全规则 | 稳定 `instructions` | 可见 | 由 main process 从角色配置构造，不接受 renderer system message |
| 当前日期与用户时区 | `callOptionsSchema` + `prepareCall` → `instructions` 末尾两行文本 | 可见 | main process 产生并传入 call options；字段、顺序和格式固定，不包含时分秒 |
| 其他模型确实需要的请求级动态数据 | `callOptionsSchema` + `prepareCall` | 由 `prepareCall` 显式加入后可见 | 只传可信、最小、与当前回答相关的数据 |
| Agent 共享执行状态 | `runtimeContext` | 默认不可见 | 用于请求 ID、feature flag、步骤状态和生命周期，不承载给模型看的说明 |
| 工具专属配置与敏感值 | `toolsContext` + `contextSchema` | 默认不可见；动态 description 可选择性读取 | 每个工具只接收自己的 context；密钥、绝对路径和内部 ID 不进入描述 |
| 工具选择提示 | `description` 与参数 Schema 描述 | 可见 | 基础描述保持稳定；只在模型决策确实依赖当前 context 时动态生成 |
| 工具可用范围、顺序与审批 | `activeTools`、`toolOrder`、`toolApproval` | 以工具定义或审批结果体现 | 权限由可信配置执行，不用自然语言提示代替授权 |
| 多步循环中的变化 | `prepareStep` | 取决于返回的 messages、instructions、tools 或 context | 只用于步骤间真实变化、消息压缩和 Provider 缓存断点 |

每次聊天模型调用使用以下固定格式，并将内容追加在角色 instructions 之后：

```text
Current date: 2026-07-28
Time zone: Asia/Shanghai
```

`currentDate` 必须由 main process 按 `timeZone` 计算为 `YYYY-MM-DD`，`timeZone` 必须是已解析的 IANA 时区标识；二者作为 call options 传入 Agent，经 `callOptionsSchema` 校验后由 `prepareCall` 写入 instructions。renderer 不得直接提供或覆盖这些值。未来增加 locale、设备状态或工具相关字段时，不得直接扩展这段内容，必须先确认模型是否需要、值多久变化以及是否更适合放入工具 context。

缓存优化遵循“稳定前缀、变量后置、按 Provider 验证”：

- 稳定的角色 instructions、工具名称、Schema、基础 description 与工具顺序优先进入可复用前缀；`toolOrder` 用于保持发送给 Provider 的工具顺序稳定。
- 高频变化但不影响模型判断的数据只留在 `runtimeContext` 或 `toolsContext`。动态 description 也是模型输入，变化时同样可能截断可缓存前缀。
- 两行环境说明固定放在稳定角色 instructions 之后，不写入时分秒；同一日期和时区内保持逐字节一致。日期跨天或用户时区变化时，该位置之后的缓存前缀可能失效，这是为保证模型默认具备日期与时区认知而接受的低频代价。
- 当前只在 instructions 中提供日期和时区；需要精确时分秒时调用 `get_current_time`，不假设存在隐式系统能力，也不依赖历史工具结果。
- Anthropic 可按 AI SDK Dynamic Prompt Caching 模式在 `prepareStep` 中为最后消息设置 `cacheControl`，OpenAI 使用对应的 prompt cache options/key，Google 使用隐式缓存或 cached content；这些分支保留在 Provider 边界，不抽象成同构能力。
- 接入缓存优化前后记录 `usage.inputTokenDetails.cacheReadTokens` 与 `cacheWriteTokens`，并使用 `include.requestMessages` 或 Provider request body 检查最终发送内容。短上下文可能达不到 Provider 最小缓存 token，不以存在配置项作为命中证据。

当前已实现日期与时区的 call options、Schema 校验和 `prepareCall` instructions 注入，以及按需返回带 UTC 偏移本地时间与 IANA 时区的 `get_current_time`；动态工具 context、缓存断点与缓存观测尚未实现。后续每接入一种工具，先判断提示属于全局角色规则、请求动态上下文、工具 description、参数 Schema 还是不可见执行 context，再决定最小放置位置。

## 共享契约与测试基线

## 当前桌面窗口边界

### 角色包管理

按 [D-064](../01-决策/决策记录.md#d-064--角色包与资源管理边界)，用户角色包由 Electron main 管理容器、托管文件、身份、去重和角色引用；Unity 负责模型与动画实际校验、加载和播放。内置模型/动画随 Unity 分发，默认包信息与立绘供 Electron 读取。作者清单不带全局动作 ID，导入时生成并持久化，动画文件内容去重不合并动作身份。格式详见[角色包格式 v1](角色包格式.md)。包导入通过 `yauzl` 流式暂存、Zod 清单校验、类型与内容哈希去重和 Unity 验证后事务发布；相同 ZIP 复用包和动作 ID。在线候选校验不改变当前包，离线使用隐藏的临时验证 Player。

### 当前实现

角色绑定包的 `portrait` 和可选 `thumbnail` 用于展示；旧立绘记录保留，旧取景坐标不再使用。默认包复用同一清单格式、身份为 `builtin:default`，不可删除；其原动画已丢失，清单当前为空。Unity 整体准备 VRM 与系统/自定义 VRMA，现有动作控制器负责采样、重定向、200ms 混合与取消；失败保留旧模型和清单。在线切换成功后保存绑定，数据库失败恢复旧包；离线保存引用，下次启动加载。AI 工具只暴露当前已验证自定义动作 UUID、名称和描述。

Unity 以全屏透明窗口覆盖选定显示器，角色构图在 Unity 相机中调整，用户与角色字幕由 Unity 播放时间轴直接绘制。Electron main 管理胶囊、临时面板、显示器、布局偏好、置顶顺序和会话绑定；胶囊原生拖动可跨屏。调整模式只在角色投影操作区接收输入，胶囊和面板矩形优先穿透。字幕没有独立 Electron 窗口和位置偏好。面板和胶囊使用轻量 renderer，不装载聊天 Runtime、ASR 或播放器。

完整布局请求仅用于首次恢复、重置、切屏和显示器变化；输入模式请求不写 Unity 窗口矩形或重置角色构图。切换会话沿用同一 Player，以绑定代次和 `session-reset` 清理旧表演。具体交互与验收边界见[桌面交互设计](../00-项目/桌面交互设计.md)。

# 技术选型

本文只记录当前共识与需要验证的候选项，不提前锁定尚未讨论完成的运行时和打包方案。

## 已确认的方向

| 领域 | 方向 | 状态 |
| --- | --- | --- |
| 语言 | TypeScript 优先 | 已决定 |
| UI | React + assistant-ui | 已决定 |
| Agent 基础 | AI SDK | 已决定 |
| 产品形态 | Web 技术驱动的 Windows 桌面应用 | 已决定 |
| 桌面容器 | Tauri v2 | 倾向，待验证 |
| 数据 | 本地优先、SQLite | 约束已确认，库待决定 |
| 模型供应商 | AI SDK Provider + OpenAI-compatible | 倾向，待验证 |
| 通用扩展 | 优先 MCP、ACP 或成熟实现 | 原则已决定 |
| TTS/ASR | 独立 Capability，不与 Agent 循环耦合 | 架构方向已确认 |
| VRM | 言奏原生核心能力 | 已决定 |

## 逻辑架构

```text
Tauri Desktop
├── React Application
│   ├── assistant-ui
│   ├── Chat and Asset Management
│   ├── VRM Runtime
│   └── Audio Input / Playback / Lip Sync
└── Katarune Harness
    ├── AI SDK Agent
    ├── Provider Registry
    ├── Character Context and Policy
    ├── Memory Tools
    ├── VRM Tools
    ├── TTS / ASR Capabilities
    ├── Thread and Message Store
    └── Optional External Workers / Protocol Clients
```

## 首个原型需要回答的问题

运行时不通过纸面偏好决定。首个技术原型应使用同一条最小链路比较候选方案：

1. 启动桌面应用。
2. 读取本地供应商配置。
3. 流式完成一次模型回复。
4. 执行一个类型安全的前端 VRM 工具。
5. 将线程写入 SQLite 并在重启后恢复。
6. 完成 Windows 开发构建和可分发构建。

需要记录的指标包括：

- 冷启动时间与空闲内存。
- 安装包和解压后的体积。
- TypeScript 开发体验与调试链路。
- 原生 SQLite、音频和 ASR 依赖的打包难度。
- AI SDK、assistant-ui 与测试工具的兼容性。
- Windows 签名、更新和崩溃诊断能力。

## 暂不引入的抽象

- 自定义 Agent 基类体系。
- 自定义模型 Provider 通用协议。
- 与 AI SDK 重复的消息流协议。
- 为每个工具实现自有远程调用标准。
- 在验证单 Agent 闭环前设计多 Agent 平台。

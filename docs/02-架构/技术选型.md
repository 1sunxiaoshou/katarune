# 技术选型

本页描述当前系统组成和责任边界。进度见[路线图](../03-规划/路线图.md)，选择的理由见[决策记录](../01-决策/决策记录.md)。

## 系统组成

| 部分 | 技术与职责 |
| --- | --- |
| 桌面宿主 | Electron；可信 main process 运行 Harness、模型调用和数据服务 |
| 产品界面 | React、assistant-ui、shadcn/Base UI、Tailwind CSS |
| 模型与工具 | AI SDK、Provider Registry 和 Provider Definition 薄适配 |
| 本地数据 | SQLite、基于 N-API 的 better-sqlite3、Drizzle；记忆正文共用本地数据库 |
| 跨进程契约 | 共享 Zod Schema、最小 preload IPC 与原生消息流 |
| 语音 | 独立 TTS Capability；sherpa-onnx、SenseVoiceSmall INT8 与 Silero VAD |
| 数字形体 | 独立 Unity Runtime、URP、UniVRM、UniWindowController 与 uLipSync |
| 工具链 | npm、electron-vite、electron-builder/NSIS、Vitest 与 Unity CLI |

Node/npm 基线以 `.node-version` 和 `package.json` 为准，JS 依赖以 `package-lock.json` 为准。Unity Editor 和 Package 版本以 `ProjectVersion.txt`、`manifest.json` 与 UPM 锁文件为准；文档不重复维护完整版本清单。

## 责任边界

```text
Electron
├── Renderer：聊天、角色、设置、语音采集与普通朗读
├── Preload：受校验的最小 IPC
└── Main：Agent、模型/工具、角色、记忆、资产、凭据、语音服务
    ├── SQLite / 托管资源
    ├── 离线 ASR utilityProcess
    └── Unity 生命周期、会话绑定与可信管道

Unity Avatar Runtime
├── Core：行为契约、实例、通道与调度
├── Motion：Humanoid 动作与统一播放图
├── UniVrm：模型、Control Rig、表情与材质适配
└── Runtime：Facade、模型事务、音频、字幕、窗口、输入与沉浸镜头/背景
```

密钥、文件系统、数据库和工具执行权限留在可信边界。renderer 只通过 preload 提交受限请求；main 校验归属和权限，不相信前端给出的模型、系统提示词或授权状态。

外部框架已有的类型、消息格式、编码器和生命周期直接复用。SQLite、Electron IPC 与产品领域语义只做必要薄适配，不维护第二套 Agent Runtime、消息模型或通用 Provider 协议。

## 数据与模型

- `characters` 是角色与 Agent 的唯一身份；会话固定绑定角色，切换界面不改变已有会话归属。
- SQLite 保存角色、会话、模型配置与产品设置；消息使用 assistant-ui/AI SDK 原生持久化格式，Schema 与版本化迁移位于 `src/main/database/` 和 `drizzle/`。
- 长期记忆分为日记、人物和纪事，SQLite 保存 Markdown 正文、稳定标识、版本。阅读与原位编辑共用同一个 Tiptap 实例，只切换可编辑状态；标题布局与日记正文滚动容器保持不变，切换状态保留滚动位置，保存后的后台刷新不重建正文；长文连续滚动，不计算页数。其 Markdown、表格和任务列表扩展保持基础排版；文档模块进入记忆条目时按需加载，不引入编辑器云服务或新的存储格式。人物与纪事通过角色绑定的单个 `memory` 工具按需搜索、读取、分页查看、保存与遗忘；关键词检索和小型目录注入不依赖外部服务，短正文连同版本直接返回，长正文按需读取。人物关系与纪事进展写在正文中，不维护条目关联表或对话来源表；更新在事务中提交，遗忘内容退出检索。旧 Wiki 已退役，不迁移旧数据。
- 日记使用 main 中独立 AI SDK Agent，携带角色设定与当天文字对话，以第一人称生成纯文本／基础 Markdown；人物、纪事的检索和读取工具提供背景，`finish_diary` 无执行副作用地提交最终草稿，程序负责校验与保存。工具参数承载输出 Schema，不请求 JSON Schema 响应格式，不强制工具选择，不全局屏蔽 SDK 警告。按消息入库时的本地日期及时区排队，本地次日 00:01 及启动时处理待整理日期，每个角色的同一日记日期只自动尝试一次，失败或中断后手动重试。任务状态和受控失败原因分类持久化，不存储供应商原始错误；日记页显示最近失败日期、原因和重试入口，旧失败未记录原因时明确说明。输出经 Schema 与当天对话变化校验后写入，无内容则跳过。用户可在日记页关闭，退出应用取消在途生成。
- 本地聊天附件通过 preload 的 Electron `webUtils.getPathForFile` 获取用户所选 File 的路径，main 校验后保存单文件引用，renderer 仅持有资产 URL。无本地路径的粘贴内容保存一份托管文件。引用读取当前文件内容，协议不永久缓存，源文件不可用时提示重新添加；删除记录不删除外部源文件。附件不自动复制进角色工作区，main 直接提供模型可用路径：请求批准模式为只读的 `/attachments/<id>/<filename>`，完全访问模式为实际本地路径。挂载仅包含发送的单文件，不暴露源目录；读写工作区中的加工结果由 Bash 完成。导入时 main 记录角色，并在首次发送绑定会话，覆盖框架尚未保存首条消息的阶段；后续读取复验会话归属。图片按需读取，不持久化 Base64，不增加旧附件迁移。
- 凭据由 Electron `safeStorage` 加密，数据库只保存不透明引用；加密不可用时失败关闭。
- Provider Definition 负责供应商发现、模型检查和能力适配，Registry 负责模型解析。真实账号库存与用户配置决定可用性，公共目录只辅助识别，不能冒充自定义端点库存。
- 应用默认模型、TTS 模型与音色可由角色继承或显式覆盖；显式配置不可用时不静默回退。音色元数据刷新不覆盖用户设置。

## 对话、语音与形体

聊天沿用 AI SDK 原生流和 assistant-ui Runtime。每次运行使用独立 MessageChannel，具有背压和取消；模型、工具和凭据留在 main，不引入本地 HTTP 服务。

工具调用直接显示动作摘要，展开一次查看参数和结果；Bash 额外根据退出码判断执行失败。附件区分图片缩略图与带名称、类型、大小的文件卡片。聊天中的本地 Markdown 文件链接与托管附件共用文件交付接口：main 校验会话归属、当前目录权限及真实路径，再提供文本／图片预览、直接打开原文件或系统另存为；保存位置由使用者在系统对话框选择，不受源文件目录范围限制。工作区及已授权目录中的普通文档直接交由本机应用打开，不创建临时副本；托管附件只提供预览和另存为，保持不可变存储及完整性校验。可执行文件与脚本只提供文本预览（适用类型）及另存为。工作区交付文件上限 50 MiB，文本预览最多 200 KB，图片预览转换为 PNG。原始附件与消息存储格式保持不变；实时命令输出和结构化文件变更展示暂缓。

普通私人聊天按 D-027 接入官方 `@ai-sdk/tool-bash` 与 `@ai-sdk/tool-web-fetch`。每个角色在应用数据目录的 `workspaces/<characterId>` 保留文件，各会话共用文件；SQLite 以 `threadId` 保存访问模式和额外目录授权，main 校验会话归属与私人聊天类型，沿用既有消息、资产和记忆模型。新会话默认请求批准，空白会话读取默认状态不入库，明确切换模式时才调用 assistant-ui 原生初始化。请求批准模式通过 `just-bash` 的挂载文件系统开放自身工作区和当前会话显式授权目录；工作区可读写，外部目录区分只读／读写。该模式的 Bash 不配置网络，不运行本机 Python、FFmpeg 等程序。完全访问模式改用本机 Bash 子进程，在当前系统用户权限下直接操作文件、程序和网络，不提供应用级文件沙箱；Windows 使用已安装的 Git for Windows。单条命令超时或取消会结束对应进程树，切换权限或撤销目录仅取消当前会话在途工具。

工具权限入口位于聊天输入框底部、附件按钮旁，仅显示并切换请求批准／完全访问权限；完全访问使用橙色图标与文字，切换模式保留草稿，不进入角色编辑页。私人会话右键菜单提供「工作区」入口，与重命名、归档、删除同组，不增加分隔线或已批准目录查看选项；操作不切换当前聊天，不提供手动撤销目录的 IPC。外部目录只能由模型调用 `request_directory_access` 请求授权，通过 AI SDK 原生工具批准和 assistant-ui 的批准／拒绝交互后授予，不提供手动添加目录的界面和 IPC。main 用进程内密钥绑定角色、会话、工具调用与输入，拒绝篡改、跨会话和重复使用。重启后未处理的旧批准请求失效，需重新请求；同一会话的已批准目录与模式持久保留。迁移 0031 不继承旧角色级权限，会话删除级联删除权限记录。文件及网页内容不能授权或切换模式。工作区文件由用户整理，删除聊天不会清理工作区文件，删除角色也不自动删除其工作区。

Web Fetch 以 `fetch_url` 暴露，只读取公开 URL 并提取页面内容；请求批准模式中每次联网调用使用原生签名批准，完全访问权限模式自动执行。保留官方 SSRF 检查，不访问内网、携带登录态或执行页面脚本，也不提供搜索引擎查询。Bash 禁止联网与独立网页工具审批分别控制。看图统一使用 `view_image`：仅接受必填 `path`，直接读取附件、工作区或已授权路径，不提供 `load_chat_attachment`；路径读取遵守当前会话的单文件及目录权限，工具统一处理大小限制与原生多模态输出，模型仍须具备视觉能力。文本／数据附件通过 Bash 读取，图片、PDF、音频和视频保持当前原生输入路径及模型能力限制。直播与日记不继承本机工具。

TTS 与 ASR 独立于 Agent 循环。普通朗读由 renderer 播放；匹配当前会话的桌宠由 Unity 播放，避免重复朗读。ASR 在 utilityProcess 离线推理，聊天 renderer 拥有唯一采集生命周期，胶囊只展示和控制。

Electron 将当前绑定会话的原生事件转发给 Unity，并提供按对白锚点编排日常动作与表情的 `avatar_perform` 和受限的 `avatar_control` 工具。配置了舞蹈的角色另有 `avatar_play({ action })`，伴奏和镜头由动作资源决定，播放独立于对白；Unity 先确认接收，再按前文播放顺序准备和启动，回报完成、取消或失败；演出占用声音和主字幕，期间回复仅保留在聊天记录，Main 获得逐块出声许可后才调用 TTS。实际状态在每步模型调用中提供，不自动唤醒 Agent。Main 解析能力与身份，Unity 拥有提示点执行、通道调度及播放时间线，Agent 完成不等待音频排空；正文直接作为对白，不定义 `speak` 工具。详细顺序、插话与资源回收见[角色行为与动画系统](角色行为与动画系统.md)。

角色包的身份、去重、绑定和导入事务由 main 管理，Unity 实际校验与加载模型/动画。内置默认包的全部资源直接从 `resources/characters/default-package/` 解析，发行时由 Electron 携带同一目录；Unity Player 不保存默认包副本。导入准备使用独立 Unity 子进程，缺少 `idle` 时异步生成模型适配的次级骨骼循环并缓存；默认模型在构建前预烘焙。main 管理取消和发布，骨骼测量及播放仍由 Unity 拥有。角色包统一使用 v3：动作在 `actions` 定义，`idle` 与 `bindings` 引用稳定 key；单次动作、循环动作和同步演出共用主动画字段 `motion`。Unity 复用 Core 实例调度，main 不复制动画状态机。契约见[角色包格式](角色包格式.md)。窗口、输入、布局和字幕归属见[桌面交互设计](../00-项目/桌面交互设计.md)。

## 直播

按 D-076／D-077，`LiveService` 在 main 管理本场生命周期、单轮互斥、有界事件缓冲和角色占用。`threads.kind` 区分普通与直播会话；直播配置单独保存，数据库仅保存 CredentialStore 引用。后台复用 ChatService、ToolLoopAgent、原生 UIMessage 流和 `readUIMessageStream`；定时器不依赖页面。模型只读取最近有限条记录并按完整轮次裁剪，数据库保留完整历史。assistant-ui 通过现有 Runtime 适配读取后台更新，不再次调用模型或写入直播记录。

`BilibiliConnection` 按 D-078 保留官方开放平台并支持网页直连，共用消息长连、20 秒心跳、校验、去重与退避重连。官方方式负责请求签名、项目开启／结束和项目心跳；网页方式由 `BilibiliWebApi` 解析真实房间、登录态、设备标识及 WBI 参数，不创建官方互动项目。两种凭据分别存放在 CredentialStore，数据库保存独立引用。网页新版弹幕与批次礼物由固定的 `protobufjs` 8.0.0 解码后再经 Schema 校验，不自研 Protobuf 解析器。

开播状态与连接状态分离，长连鉴权或收到弹幕不作为开播确认。官方方式等待开播事件；网页方式在消息鉴权后查询房间开播状态，并接收后续开下播通知，迟到的查询不能覆盖较新的事件；重连后重新确认。只接受当前连接的已知平台事件，不把观众文字识别为送礼。协议参考官方[应用 API](https://open-live.bilibili.com/document/eba8e2e1-847d-e908-2e5c-7a1ec7d9266f)、[长链命令](https://open-live.bilibili.com/document/f9ce25be-312e-1f4a-85fd-fef21f1637f8)，以及 [blivedm 网页连接实现](https://github.com/xfgryujk/blivedm/blob/dev/blivedm/clients/web.py)、[新版消息字段](https://github.com/Akegarasu/blivedm-go/blob/master/pb/events.proto)。网页访问限制或登录失效明确反馈，不自动切换接入方式。

按 D-080，抖音由 `DouyinConnection` 独立处理房间查询、本地 Webcast 签名、WebSocket、gzip／Protobuf、ACK、心跳及退避重连。只解码消费的字段，64 位观众／房间／消息 ID 保持十进制字符串；连击礼物按分组累计值转成增量。连接收到可解码数据后才进入已连接，开播依据平台房间状态，下播优先采用控制消息。状态查询独立于 10 秒心跳：长连通过后立即复查，未开播／待确认时每次请求结束后等 3 秒，直播中等 10 秒；请求串行，失败按 6／12／24／30 秒退避。迟到查询不能覆盖结束事件，已结束的同一内部房间不会被缓存的直播中结果重新激活；发现新的内部房间 ID 时重新连接。取消、断线或切换会终止对应查询调度，旧请求不能干扰新连接。压缩前后消息均限制 2 MiB，未知或无效消息忽略。事件进入相同 `LiveService`，AI 观众为 `{platform, id, name}`；id 使用 `平台:uid或open_id:原值`，未知身份为 null。

`LiveLoginService` 在 main 管理扫码登录。B 站通过二维码签发／轮询接口和独立 CookieJar 限制同平台 HTTPS 跳转；抖音由 `DouyinBrowserLogin` 在无 preload、无 Node、启用 sandbox 的隐藏官方登录页完成初始化与回调，通过受限的网络观察获取二维码及扫码状态。会话为临时独立分区，拒绝权限、下载及新窗口；账号查询只允许固定的两个官方路径。二维码经本机编码为 PNG，通过最小 IPC 传递，renderer 不接收 QR token、Cookie 或回调。浏览器存在登录 Cookie 仅触发独立账号查询，验证通过才保存加密凭据。额外安全验证须使用者明确点击后才展示官方窗口；扫码后保留有界验证时间。取消、过期、切换平台及关闭窗口销毁会话，迟到结果不能落库。

本人房间查询成功但没有房间时返回空结果，`LiveService` 进入 `connection=waiting`，保持 `broadcast=unknown`、`error=null` 及已保存账号，不执行消息连接或生成故障记录。界面显示账号信息和重新检测；缺少房间不等于平台确认未开播。损坏的返回数据、身份校验及网络失败继续作为错误处理，不用等待状态掩盖。

账号头像从经过身份校验的资料中读取，B 站使用 face、抖音使用 avatar_medium／avatar_thumb；共享 Schema 与 renderer CSP 仅允许 HTTPS 的 hdslb.com／douyinpic.com 子域，图片不发送 referrer。恢复已有账号时可重新验证并刷新本次账号展示信息，缓存绑定凭据引用，退出账号即清除；不为补充头像改写旧凭据。未开播账号卡片只显示头像、昵称、平台和状态，身份 ID 继续留在内部事件归属中。

媒体启动与平台连接独立。`LiveService` 先准备角色和本地媒体输出，未配置房间也可进入运行状态；已有配置的连接在后台尝试，失败只更新连接反馈。单轮主持调度继续检查消息连接和平台开播状态，离线预览不启动 AI。

三种接入方式各有一份独立凭据引用，当前设置只选择其中一种；切换方式时 `changeConnection` 取消旧连接及请求，清除派生房间号但保留所有凭据。页面默认显示方式入口，点击已保存方式调用 `connect`，在线连接直接复用；返回仅改变前端视图，检测结果不抢回详情。首次登录或明确重新登录才扫码，新的扫码账号完成保存后清除旧账号的派生房间号。`connect` 在无房间配置时重新验证账号并查询自己的房间：B 站使用 UID 对应的 getRoomInfoOld，抖音恢复保存凭据到新的隔离官方页面，使用自资料 room_data.owner.web_rid，不用账号 UID 或内部 room_id 替代。没有返回房间时保留账号并提示重新检测；重进页面后点击已保存方式可恢复账号。验证与连接共用取消生命周期，取消后不能保存迟到的房间。抖音导出凭据时排除 Chromium 接受的无名称 Cookie，既有凭据读取时仅忽略这一项，其他非法 Cookie 继续拒绝。迁移 0029 新增抖音凭据引用，既有配置默认 B 站。扫码账号与房间连接分离，断开保留配置和三种方式凭据，显式退出账号只删除指定网页登录态；网页界面不再提供手动房间号和 Cookie 表单。

协议交叉参考 [DouYinDanma](https://github.com/renmu123/biliLive-tools/tree/8b079a687ceb59054d66c232515557188d3b866e/packages/DouYinDanma) 与 [DouyinLiveWebFetcher](https://github.com/saermart/DouyinLiveWebFetcher)。签名封装参考 [DouyinLiveRecorder 的协议实现](https://github.com/y123ao6/DouyinLiveRecorder/blob/main/src/platforms/_xbogus.py)，该资料注明来源 dart_simple_live；其 GPL 来源实现及大型 SDK 未作为依赖或复制入仓库。这里只实现消费所需的协议格式与标准散列／RC4 运算。网页登录初始化参考 [VideoNote-MCP](https://github.com/HuangYincan/VideoNote-MCP/blob/401baad1853c238ec767e425db73965eecede39d/app/downloaders/douyin_browser.py)，复用 Electron 而不新增 Playwright 运行依赖；按 [Electron Debugger 文档](https://www.electronjs.org/docs/latest/api/debugger)先完成首次空白页导航再启用网络观察，避免命令挂起。二维码接口与 Webcast 签名是两条不同链路，签名向量测试不能证明二维码风控或真实弹幕连接已通过。

Unity 的直播模式隐藏原生窗口，在角色姿态更新完成后使用 URP StandardRequest 主动提交离屏相机渲染；不能依赖隐藏窗口的普通呈现回调。角色与沉浸背景输出到沿用当前 URP 抗锯齿设置的 RenderTexture，UI Toolkit 纹理合成实际播放字幕，AsyncGPUReadback 经有界队列传输 RGBA。AudioListener 的 tap 先复制语音／配乐 PCM，再静音 Unity 的直播监听；音频线程不编码、写管道或分配。控制 JSON、画面与 PCM 使用独立管道。main 为本地素材流管理 60 fps 与随源分辨率变化的编码码率，默认 1080p；直播软件单独配置平台输出，RTMP 拉流不反向协商源编码参数。

按 D-079，FFmpeg 优先使用实际预检通过的 NVENC，否则预检 Media Foundation 硬件编码；不静默使用软件编码。H.264／AAC 只编码一次，tee 分别封装为 RTMP 的 FLV 和预览用分段 MP4。预览复用编码后的原尺寸画面与音轨，经有界 IPC 交给 Electron MediaSource／video 同步播放；音轨经 MediaElementAudioSourceNode 接入 GainNode，监听以 10 ms 渐变调整增益，不切换 video 或窗口静音。每个 renderer 复用一个 AudioContext，同一 video 复用其音频源；关闭预览时断开连接并挂起上下文，返回时恢复。预览每段从关键帧开始，慢接收或页面重新可见后可重新接入，不积压旧画面；离页或最小化停止预览传输，主输出继续。MediaMTX 只启用 `127.0.0.1` 的 RTMP，默认路径 `/katarune/live`，没有远程输出地址或任意编码参数入口。

视频时间轴按音频累计采样校准单调时钟，在音频块之间插值，避免把块回调频率当作画面帧率；允许一帧以内的渲染相位误差，缺帧使用前帧补足恒定帧率时间轴，静音仍持续输出。固定版本、下载 SHA-256 见 `resources/live-media-manifest.json`；准备脚本生成可执行文件／DLL 校验清单并携带许可证与源码来源。监督程序以 Job Object 管理编码器和流服务，控制管道关闭或任一媒体子进程退出均回收整组进程。端口冲突报错，不结束其他应用或静默改端口。

直播间展示元数据由 main 校验并传递标题、封面地址和简介，网页连接直接复用房间信息请求；官方连接仅异步补充公开展示信息，不用该请求判断开播或影响鉴权。抖音封面读取房间 cover.url_list，按顺序选择有效图片，后续房间状态查询同时刷新封面；同房间短暂缺少或返回无效封面时保留上一张有效封面，新房间重新初始化。封面与账号头像共用 HTTPS 的 hdslb.com／douyinpic.com 子域校验，renderer CSP 同步限定这些图片来源，加载时不发送 referrer；简介按纯文本绘制，不执行平台 HTML。无元数据时使用占位，不阻塞弹幕连接。

共享 Schema 位于 `src/shared/live.ts`，经现有 `ipc.ts` 导出；直播 IPC 仅接受主窗口主 frame，读取配置返回凭据配置状态和已保存账号的展示信息。预览至多一段等待 renderer 完成 SourceBuffer 更新后确认，不等待 `video.play()` 完成；启动先缓冲两个半秒片段，避免播放启动与后续片段互相等待。媒体不进入通用控制 IPC。日志仅记录阶段与安全故障投影，沿用 D-075，不记录观众正文、密钥、临时鉴权或供应商响应。接收端及实际验收边界见[路线图](../03-规划/路线图.md#验收口径)。

## 日志与诊断

D-075 已决定并接入。目标是通过本地诊断回答故障发生在哪个进程、操作和阶段，保留错误类型、HTTP 状态、原因链与安全栈位置，不索取聊天正文或密钥。原先 Main 的零散控制台、Unity 原始 Player 文件和界面提示不能组成完整记录；旧故障中已经丢弃的原因无法追溯恢复。

```text
Main / IPC 业务边界 ────────────────────────┐
Renderer / Preload ─ 最小 IPC ─────────────┤
ASR Worker ─ 原有进程消息 ─────────────────┤
Unity ─ 原有本地管道 ─────────────────────┤
                                         ↓
                Main：Schema 校验 → 安全字段投影 → 关联 / 限流 / 去重
                                         ↓
                有界队列 → 专用写入线程 → electron-log → JSONL
                                         ↓
                         设置页打开日志目录；内部接口提供状态与本地导出
```

### 存储与资源边界

- 唯一常规写入入口位于 `src/main/diagnostics/`；共享契约在 `src/shared/diagnostics.ts`。日志存于当前数据目录的 `logs/diagnostics/`，开发与安装版继续隔离，不使用业务数据库。
- 复用 electron-log 5.4.4 的文件传输、格式和轮转接口。同步 I/O 在专用 Worker 运行，Main 不等待磁盘；每批最多 32 条，收到完成确认后再发送。避免直接使用库内部没有容量限制的异步队列。[组件官方文档](https://github.com/megahertz/electron-log/blob/master/docs/transports/file.md)
- 单文件目标 5 MiB，目录最多 50 MiB，归档最长 7 天，活动文件满 24 小时后在后续写入时滚动；文件年龄在写入线程启动时从首条事件的 observedTimestamp 恢复，轮转后重新计时，不依赖 Windows 可能沿用的文件创建时间；单条最多 8 KiB。Main 全局待发队列 512 条、故障后备内存 512 条，优先淘汰 DEBUG。重复 ERROR 归并为同一故障编号并输出计数摘要；满载丢弃计数保留在诊断状态和退出事件中。
- Renderer 每来源每秒 20 条、突发 100 条。Main 从真实发送窗口确定身份，拒绝子 frame；renderer 不指定路径、进程身份或任意属性。不接管 console，不开放 electron-log 自带的任意对象 renderer 入口。
- 写入失败进入有限内存降级，10 秒后尝试重建写入线程，成功后补写并报告恢复。关闭最多等待 1.5 秒；硬崩溃与持续磁盘故障可能丢失末尾事件，不承诺零丢失。
- Unity 线程日志回调只提取安全字段并入队，独立计时器发送，避免音频/渲染线程做磁盘操作；断连时写 `avatar-runtime/unity-fallback.jsonl`，当前与旧文件分别约 512 KiB。该安全后备文件与常规日志隔离，不自动纳入导出。[Unity 6000.3 线程约束](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Application-logMessageReceivedThreaded.html)
- 生产 Player 以 `-nolog` 禁止原始引擎文件；工作清单位于 `avatar-runtime/avatar-package.json`。测试的原始 Editor 日志、截图与音频仍是显式验收产物，不进入诊断包。旧 logs 目录中的历史文件不自动删除或导出。

### 关联与异常责任

每条记录包含 schemaVersion、UTC timestamp / observedTimestamp、level、稳定 event、component、source、bootId、processInstanceId 和 Main sequence；Unity 原始序号另存 sourceSequence。按事件选用 operationId、parentOperationId、runId、dialogueId、toolCallId、performanceId、bindingEpoch、durationMs、outcome 与 incidentId。IPC 异步上下文使用 AsyncLocalStorage 透传，沿用现有业务 ID，不维护另一套播放状态，也不将 UUID 称为 OpenTelemetry TraceId。

目前接入启动/数据库打开/缓存降级/退出、受控 IPC 异常、AI 步骤与工具结果、流失败、对白出声许可、TTS 生成及首音、ASR 请求和子进程退出、Unity 错误、舞蹈与表演终态、播放状态、包验证失败及日记失败。普通级别不记录 token、音频帧、字幕每帧或麦克风数据。SDK 自身重试仍由 SDK 管理，保留 RetryError 与末次错误链，不虚构尚未开放的逐次重试回调。

负责处理失败的边界记录原始异常的安全投影；同一 Error 传播时复用故障编号。TTS、聊天与 IPC 错误提示携带编号，通知支持复制；降级记录结果，用户主动取消为正常终态。IPC 的 rejection 重新构造安全提示，避免 Electron 自动将原始异常、cause 与绝对栈路径打印到控制台。

可预期拒绝采用 `OperationRejected`，外部参数入口采用 `parseRequest`：WARN + `outcome=rejected` + 共享 Schema 白名单 `reasonCode`，用户提示提供安全原因码，不生成故障编号。原因包括 `invalid-input`、`forbidden-source`、`resource-unavailable`、`ownership-mismatch`、`operation-not-allowed`、`operation-in-progress`、`configuration-required`、`missing-port`、`method-not-allowed`、`unsupported-media`、`rate-limited`。只在已知拒绝条件处标记；持久化数据／内部输出的 Zod 错误、数据库或文件系统异常仍为故障，未知异常默认 ERROR。

覆盖业务 IPC 请求参数、会话／附件归属与直播只读限制、角色包并发与取消归属、直播控制来源与预览参数、诊断接口、聊天流、语音取消请求及资源协议。消息式入口维持原有错误响应／关闭／忽略语义；过期的预览确认、已结束的取消和正常会话切换不当作非法操作。拒绝事件不包含请求正文、资源 ID、URL、Zod issues 或原始异常；同来源／事件／原因码每 10 秒记录首条并汇总额外次数，最多保留 128 个汇总项，刷盘及关闭时补齐计数。此机制用于故障诊断，不是逐请求安全审计，也不代替各业务入口的权限校验。

错误投影只允许错误名、已审查错误码、HTTP 状态、可重试性、最多四层原因和十二条相对栈位置。自由 message 一律标记 messageRedacted；不序列化 SDK 请求/响应对象。API Key、认证头、Cookie、聊天/记忆/识别正文、SQL 参数、工具参数、音频、图片、完整 URL、用户名和绝对路径不进入日志。先白名单投影，再限长和编码；导出重新校验契约并投影错误字段。[OWASP 原则](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

### 生命周期与使用入口

日志在数据库、凭据和 AI 服务前初始化。启动写 session.pending；正常关闭且日志排空后删除，下次发现残留仅报告“上次未正常结束”。Main 未捕获异常/拒绝及初始化失败记录 FATAL 后以非零退出，不继续运行。Electron 记录 renderer 与 child 退出，ASR/Unity 记录退出码。Renderer 全局错误、拒绝与 React 根错误分别收集；Preload 采用 Electron preload-error 入口，避免重复订阅跨世界 window 事件。

设置 → 常规仅提供“打开日志目录”入口，与其他设置保持简洁一致；不展示日志统计、导出选项或详细诊断开关。打开失败沿用普通错误通知。状态、导出与临时 DEBUG 保留为内部诊断接口；导出按最近 1 小时/24 小时/7 天筛选，确认范围、事件数量和大小后保存本地 JSON，排除数据库、凭据、资源、原始引擎日志与转储。DEBUG 最长 30 分钟，重启恢复 INFO。无远程上传。

原生内存转储仍为待单独授权的可选诊断能力，默认不采集；普通 JS 日志不等于原生崩溃栈，Electron 也不覆盖独立 Unity Player 的原生崩溃。验证入口和当前边界见[工程规范](../04-开发/工程规范.md#日志与诊断验证)。

## 分发与扩展

舞蹈镜头使用自包含的 glTF 2.0 GLB，由标准节点动画和 `KHR_animation_pointer` 表达位姿与相机参数。复用 UniGLTF 文件解析，Unity 直接求值标准曲线；参考身高、动画选择与跨相机切换放在包清单。Main 进行有界容器校验并管理资源，Unity 验证实际时长、按舞蹈音频游标采样和恢复构图。VMD 在制作阶段转换，不增加运行时 MMD 依赖。格式与制作入口见[角色包格式](角色包格式.md)，选择依据见决策 D-073。

Windows 内部包通过 electron-builder/NSIS 分发，已包含 Unity Player、默认资源与离线语音权重；默认卸载保留个人数据，覆盖更新不清理数据。构建准备和验证入口见[工程规范](../04-开发/工程规范.md#windows-内部发行包)。

当前技术边界服务于数字生命的阶段性实现。游戏、虚拟世界、实体躯体以及 MCP/ACP 等扩展按具体需求选择方案，不提前建立平台适配或通用工作流。

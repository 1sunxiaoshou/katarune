# 角色包格式

角色包是一个 ZIP，包含 `manifest.json`、立绘、VRM 1.0 模型和自包含的 Humanoid `.vrma` 动画。当前统一使用 v2，不读取尚未发布的 v1 清单。

## 最小示例

```json
{
  "formatVersion": 2,
  "name": "我的角色",
  "version": "1.0.0",
  "portrait": "portrait.png",
  "model": "avatar.vrm",
  "systemActions": {
    "idle": { "file": "idle.vrma" },
    "greet": { "kind": "oneShot", "file": "greet.vrma" },
    "nod": { "kind": "oneShot", "file": "nod.vrma", "layer": "head" },
    "think": {
      "kind": "loop",
      "enter": "think-enter.vrma",
      "loop": "think-loop.vrma",
      "exit": "think-exit.vrma"
    }
  },
  "customActions": [
    {
      "key": "001",
      "name": "招手",
      "description": "问候或告别",
      "playback": { "kind": "oneShot", "file": "wave.vrma" }
    }
  ]
}
```

示例中的动作都必须有对应文件；没有资源的动作直接省略。

## 清单字段

| 字段 | 说明 |
| --- | --- |
| `formatVersion` | 固定为 `2` |
| `name` / `version` | 包名称；作者版本，例如 `1.0.0` |
| `portrait` | 立绘的包内路径 |
| `thumbnail` | 可选卡片图；省略时使用立绘 |
| `model` | VRM 1.0 模型的包内路径 |
| `author` / `license` | 可选作者和许可说明 |
| `systemActions` | 系统动作，可以为空对象 |
| `customActions` | 自定义动作，可以为空数组 |

系统动作分两部分：`idle` 是基础循环，`idle_variations` 是一次性待机变化数组，均用 `{ "file": "路径" }`；以下语义使用示例中的播放定义：

| 用途 | 系统语义 |
| --- | --- |
| 问候、肯定、否定 | `greet`、`nod`、`shakeHead` |
| 交谈、思考 | `talk`、`talkGesture`、`think`、`thinkGesture` |
| 鼓掌、欢呼、鼓励 | `clap`、`cheer`、`encourage` |
| 疑惑、耸肩、指向 | `confused`、`shrug`、`point` |
| 姿态、情绪 | `akimbo`、`holdArms`、`afraid`、`downcast`、`alert` |
| 阅读、低语 | `read`、`whisper` |

不保留缺少资源的旧预设动作别名。系统语义对应什么动作，由当前包实际提供的 VRMA 决定。

自定义动作填写 `name`、`description`、`playback`；可选 `key` 用作包内标识。编号用字符串，例如 `"001"`。省略 key 时使用名称；标识必须唯一，重名动作填写不同 key。作者不填写全局 UUID。

## 播放规则

- `oneShot`：填写 `file`。同通道原循环被打断时，播完经其 `enter` 再回到 `loop`；没有原姿态时回到 idle。
- `loop`：必须填写 `loop`，`enter`、`exit` 可省略。进入段播完持续循环，直到切换、自然结束或取消。
- `layer` 可选 `body`（默认全身）、`upperBody`（躯干、手臂、手指、颈头）、`head`（颈头）。三个通道并行，头部最后混合；上半身和头部不写髋部、腿部或位移。
- `blending` 默认 `override`，头部默认 `additive`。加法动作扣除参考姿态再叠加；可用 `reference` 指定参考 VRMA，省略时使用进入段或主片段第 0 帧。全身只支持覆盖。
- `blendSeconds` 为动作切换的平滑时长，0–2 秒，默认 0.2 秒。循环互切先播旧 `exit`，再播新 `enter → loop`。
- 素材应保证 `enter` 末帧接上 `loop` 首帧、循环首尾闭合；来源特有的重叠在制作时烘焙。`enter → loop` 自然接续，不追加冻结姿态平滑。
- 同一正在播放的循环再次请求保留实例和进度。每个通道支持一层原循环恢复；同通道一次性动作播完或取消后，保留原实例但重播 `enter → loop`，没有 enter 则从 loop 开始。未被打断的其他通道持续推进，不重播入场。取消指定动作不清除其他通道；会话重置清除全部。
- AI 使用 `system:think` 或 `custom:001` 等标识，支持 `play`、`finish`、`cancel`。持续姿态允许同时说话，不阻塞对白或后续动作。idle 与自动待机变化不进入 AI 清单。
- 旧 v1 清单需要改为 v2 后重新打包导入；旧记录保留但不进入可选列表，不自动修改或删除本地数据。

## 导入与保存

所有路径都是包内相对路径，使用 `/`，不接受绝对路径、URL、`..`、重复路径或链接。只允许清单、引用的资源及根目录可选的 UTF-8 `LICENSE.txt`、`CREDITS.txt`；未知字段和重复 JSON 成员拒绝导入。

导入在后台整体验证模型及全部动画片段，成功后才发布，可以取消；失败保留原角色。未配置 idle 时自动生成固定人体站姿和模型适配的次级骨骼循环并缓存，当前角色继续运行。已有 idle 直接播放，Spring Bone 跟随身体运动，不施加持续环境风。

应用生成包 ID 和动作 UUID，重启后保持；相同 ZIP 重导入复用原身份，同内容资源按 SHA-256 去重。更改名称、版本或重新打包不触发覆盖旧包。删除正在使用的包前须先更换绑定，不删除角色或聊天。

限制：ZIP 1 GiB、解压 2 GiB、1024 文件、清单 1 MiB；模型 512 MiB、单个动画 128 MiB、图片 25 MiB 且宽高不超过 4096。名称 80、作者 200、动作描述 1000、许可 2000 个 Unicode 码点；最多 256 个自定义动作、32 个待机变化。VRMA 当前不接受表情、视线及非人体轨道。

## 默认包与验证

默认包为不可删除的 `builtin:default`。包含公共人体 idle、两段待机变化、20 个系统动作和 9 个自定义变体。点头、摇头使用头部增量；问候、说话手势、鼓掌提供上半身版本，完整版本保留为 `Greet01Full`、`Talk03Full`、`Clap01Full`。跳跃等大幅动作保留全身曲线。转换采用默认 Humanoid 限位，未带入源游戏 IK、表情、道具和次级曲线；来源见默认包 `CREDITS.txt`。

检查入口：`npm run typecheck`、`npm test`、`npm run test:database`、`npm run test:character-packages`；构建 Player 后运行 `npm run test:avatar-packages`。自动检查验证加载与控制规则，最终动作观感需实机验收。

内部控制机制见[角色行为与动画系统](角色行为与动画系统.md)，构建与实机检查见[工程规范](../04-开发/工程规范.md)，格式依据见 [VRM Animation](https://vrm.dev/en/vrma/)。

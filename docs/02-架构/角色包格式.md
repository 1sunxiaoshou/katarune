# 角色包格式

角色包是 ZIP，包含 `manifest.json`、角色形象和自包含的 VRM Animation 1.0 `.vrma`。当前清单使用 **v3**：所有动作只在 `actions` 定义一次，`idle` 和 `bindings` 通过稳定的包内 key 引用动作。旧版清单需重新制作导入，应用保留已有记录，不自动迁移或删除用户数据。

## 结构与命名

```text
manifest.json
avatar/
  model.vrm
  portrait.png
  thumbnail.png
actions/
  idle/motion.vrma
  wave/motion.vrma
  think/enter.vrma
  think/motion.vrma
  think/exit.vrma
  redreaming-angel/motion.vrma
  redreaming-angel/audio.wav
  redreaming-angel/subtitles.srt
  redreaming-angel/camera.glb
```

这是默认包使用的组织规则；用户包可以使用其他安全的相对路径。音频保留实际扩展名和原始内容。JSON 字段使用小驼峰，动作 key 与目录名使用英文小写、数字和连字符，例如 `point-left`。key 长度不超过 80，必须唯一且稳定，修改中文显示名称不改变 key；不同动作允许使用相同显示名称。作者无需填写全局 UUID。

## 清单示例

```json
{
  "formatVersion": 3,
  "name": "我的角色",
  "version": "1.0.0",
  "model": "avatar/model.vrm",
  "portrait": "avatar/portrait.png",
  "actions": [
    { "key": "idle", "name": "基础待机", "description": "平静站立", "playback": { "kind": "loop", "motion": "actions/idle/motion.vrma" } },
    { "key": "wave", "name": "招手", "description": "问候或告别", "playback": { "kind": "oneShot", "motion": "actions/wave/motion.vrma", "layer": "upperBody" } },
    { "key": "think", "name": "思考", "description": "保持思考姿态", "playback": { "kind": "loop", "enter": "actions/think/enter.vrma", "motion": "actions/think/motion.vrma", "exit": "actions/think/exit.vrma" } }
  ],
  "idle": { "base": "idle", "variations": [] },
  "bindings": { "greet": "wave", "think": "think" }
}
```

| 字段 | 含义 |
| --- | --- |
| `formatVersion` | 固定为 `3` |
| `name` / `version` | 包名称与作者版本，版本使用 `1.0.0` 格式 |
| `author` / `license` | 可选作者、许可说明 |
| `model` | VRM 1.0 模型路径 |
| `portrait` / `thumbnail` | 立绘、可选缩略图；未提供缩略图时使用立绘 |
| `actions` | 统一动作库，可以为空数组；每项填写 `key`、`name`、`description`、`playback` |
| `idle.base` | 可选基础待机动作 key，引用全身覆盖的循环动作，仅包含循环主体 |
| `idle.variations` | 可选待机变化 key 数组，引用全身覆盖的单次动作，不能重复 |
| `bindings` | 可选固定用途绑定，值为本包动作 key，同一动作可绑定多个用途 |

未提供基础待机时，Unity 自动生成模型适配的待机；未提供变化数组时使用默认包的待机变化，显式填写空数组可关闭变化。所有显式引用必须存在，错误引用拒绝整包。用途绑定只引用普通动作。

固定用途：`greet` 问候、`nod` 点头、`shakeHead` 摇头、`talk` 交谈、`talkGesture` 说话手势、`think` 思考、`thinkGesture` 思考手势、`clap` 鼓掌、`cheer` 欢呼、`encourage` 鼓励、`confused` 疑惑、`shrug` 耸肩、`point` 指向、`akimbo` 叉腰、`holdArms` 抱臂、`afraid` 害怕、`downcast` 低落、`alert` 警觉、`read` 阅读、`whisper` 低语。缺少用途时直接省略；绑定本身不创建自动触发器。

## 播放定义

| `playback.kind` | 中文名称 | 内容 |
| --- | --- | --- |
| `oneShot` | 单次动作 | `motion` 为播放一次的 VRMA |
| `loop` | 循环动作 | `motion` 为循环主体，`enter`、`exit` 为可选进入、退出片段 |
| `performance` | 同步演出 | `motion` 与可选 `audio`、`subtitles`、`camera` 共用时间轴，目前用于舞蹈 |

- `layer` 可选 `body`（默认全身）、`upperBody`（上半身）、`head`（颈头）。作用范围独立于播放类型；上半身与头部不写髋部、腿部或位移。
- `blending` 默认 `override`，头部默认 `additive`。加法动作扣除参考姿态再叠加；可用 `reference` 指定参考 VRMA，省略时使用进入段或主体第 0 帧。全身只支持覆盖。
- `blendSeconds` 为切换平滑时长，0–2 秒，默认 0.2 秒。循环互切先播旧 `exit`，再播新 `enter → motion`。
- 素材须保证进入段接上循环首帧、循环首尾闭合。自然衔接不追加冻结姿态平滑。
- 同一循环再次请求保留实例和进度。同通道单次动作结束或取消后恢复原实例，并重播进入段；其他通道保持推进。取消指定动作不清除其他通道，会话重置清除全部。
- AI 使用统一的 `action:<key>` 选择动作。自动待机素材不进入 AI 可调用清单；手动下拉可按实际播放类型预览。

## 同步演出

```json
{
  "key": "redreaming-angel",
  "name": "复梦天使",
  "description": "带音乐、歌词与镜头的舞蹈",
  "playback": {
    "kind": "performance",
    "motion": "actions/redreaming-angel/motion.vrma",
    "audio": "actions/redreaming-angel/audio.wav",
    "subtitles": "actions/redreaming-angel/subtitles.srt",
    "camera": { "kind": "track", "file": "actions/redreaming-angel/camera.glb", "referenceHeight": 1.6553590819239616 }
  }
}
```

演出使用全身覆盖，只允许省略 `layer` / `blending` 或填写 `body` / `override`，不包含 `enter`、`exit`、`reference`。沿用 `blendSeconds`。身体、表情、视线随同一游标采样；素材独占这三类控制，暂停程序化呼吸／摆动、自动眨眼、鼠标跟随、情绪与语音口型写入，未提供的面部和视线保持中性。Spring Bone 的头发与衣服物理保留，结束或中断后恢复原有控制。

`audio` 可选，引用包内原格式伴奏，单文件不超过 128 MiB。使用与实际播放相同的 Unity 解码器预检，不以扩展名设置白名单、不转码；可解码、时长大于 0 且不超过一小时即可。伴奏最多比动作短 50 毫秒，较长伴奏在动作结束时停止。

`subtitles` 可选，引用 UTF-8 SRT（可有 BOM，支持 LF / CRLF），不超过 1 MiB、4096 条。首条编号为 1，后续正整数编号严格递增且允许跳号。时间使用 `HH:MM:SS,mmm --> HH:MM:SS,mmm`，区间不重叠，最大一小时且不超过实际动作时长（容差 50 毫秒）。每条包含 1–1000 个 Unicode 码点，允许换行。音乐字幕按实际游标显示为粉色，区间间隙与终态清空；演出独占主字幕，普通对白不抢占，空隙不回填对白。

`camera` 可选，使用带类型的统一配置：

- `{"kind":"presets","keys":[{"at":0,"view":"center"}]}`：1–64 个递增的秒数时间点，范围 0–3600 且不超过动作时长。机位为 `overhead`（俯视）、`center`（居中）、`closeup`（近景），到点柔和切换。
- `{"kind":"track","file":"actions/dance/camera.glb"}`：引用不超过 **16 MiB 的自包含 glTF 2.0 GLB**。不再接受私有 JSON 采样文件，也不把普通镜头 GLB 称为 VRMA。禁止外部缓冲区、图片引用和未支持的必需扩展。

镜头 GLB 使用标准相机节点与层级、节点位移／四元数旋转／正数缩放动画，以及 `KHR_animation_pointer` 的相机参数动画。支持 `LINEAR`、`STEP`、`CUBICSPLINE`；位置与参数按标准曲线求值，线性四元数采用最短弧插值，三次样条四元数归一化。使用未压缩的浮点密集访问器，单通道最多 120001 个时间点，时间须递增且在一小时内。静态相机也可使用。所有镜头段、动画的结束时间须不超过动作时长，允许 50 毫秒尾差；首个关键帧之前和末帧之后保持端点。

GLB 保持 glTF 的米制、Y 向上坐标，相机朝本地 -Z；Unity 在读取时转换坐标。制作时将参考角色脚底放在场景原点，镜头位置与角色使用同一空间。相机垂直视角、正交视口半高与裁剪范围随轨道求值，画幅按应用窗口的垂直视角适配；不导入景深、镜头偏移、场景灯光、材质或网格。位置绝对值不超过 1000 米，垂直视角 1–179 度，正交半高大于零且不超过 1000 米。

`track` 配置另有三个可选字段：

- `referenceHeight`：制作时参考角色的外形高度，单位米，大于零且不超过 10。提供时，位置、正交尺寸与裁剪距离按目标角色外形高度等比缩放；省略时保持文件尺度。两种情况均以当前角色脚底为原点，并跟随播放前角色的展示朝向。
- `animation`：按名称选择一个动画。省略时同时应用互不冲突的动画通道，以支持 Blender 将物体与镜头参数拆成多个片段的原生导出；多个片段写入同一属性时拒绝并提示显式选择。
- `shots`：多相机演出的镜头段，最多 256 项，从零秒开始且严格递增。`node` 是 GLB 中唯一的相机节点名称，到点直接切换相机，包括透视／正交切换。省略时场景必须恰好有一个相机节点。glTF 不规定活动相机，因此镜头段属于包清单的演出编排。

```json
"camera": {
  "kind": "track",
  "file": "actions/dance/camera.glb",
  "referenceHeight": 1.65,
  "shots": [
    { "at": 0, "node": "WideCamera" },
    { "at": 8, "node": "CloseCamera" }
  ]
}
```

镜头、动作与歌词使用同一实际音频游标；没有音乐时使用同一演出时钟。不在标准曲线之上叠加预设平滑。结束柔和恢复，取消／失败立即恢复完整投影、构图与交互。

### 在 Blender 制作镜头

1. 在参考角色旁创建相机，以角色脚底为原点制作位移、旋转与焦距动画。场景首帧设为 **0**，按舞蹈的秒数与帧率对齐；导入器保留文件时间，不自动删除前面的留白。
2. 选中相机及需要的父级 Empty，导出 **glTF 2.0 → GLB**。开启 Cameras 和 Animation，动画模式选 **Scene**；需要变焦时开启 **Animation Pointer**。Blender 5.2 的该选项仍标为 Experimental，已用未修改的原生导出文件验证位移和焦距同时读取。
3. 将文件放入动作目录，在 `playback.camera.file` 引用。先实时预览，再按需要填写 `referenceHeight`。无需编写或提交逐帧 JSON，也不要求安装 Unity Editor。

单相机阶梯动画可以使用标准 `STEP`。同一演出包含平滑运镜与多次硬切时，可分别制作多台相机并填写 `shots`；Blender 的时间线相机绑定标记不会自动成为 glTF 的活动相机编排。默认两支舞蹈通过相邻可表示的 float32 时间点保留原硬切，轨道保持标准 GLB，未增加私有 glTF 扩展。

### 将已有 VMD 镜头转换为 GLB

安装 Blender 的 MMD Tools 扩展后，从仓库根目录运行：

```powershell
blender --background --factory-startup --python-exit-code 1 `
  --python scripts/convert-vmd-camera.py -- input.vmd camera.glb --duration 224.5
```

`blender` 可替换为本机 Blender 可执行文件路径。脚本默认 60 FPS，`--duration` 可截取或延长末镜，省略时使用 VMD 镜头时长；`--scale` 默认 0.08，将 MMD 单位换成米；`--floor` 默认 0，指定参考角色脚底高度。它输出标准 GLB 与可放入清单的 `camera` 配置，不修改源 VMD，也不覆盖已有输出。透视／正交变化自动输出相机节点与镜头段。转换后仍需以目标角色实时检查构图。

AI 通过 `avatar_play` 选择演出，配乐与镜头由动作定义决定。工具接收后返回 accepted，等待前文实际播完再启动；准备、真实启动、完成／取消／失败由播放器反馈，不随对白结束停止。演出期间的回复只进入聊天记录，明确停止可用 avatar_control.cancel。当前不提供暂停、继续或循环控制。桌面下拉可以直接播放；选择其他有效动作会中止当前演出并切换，再次点击当前播放项停止对应动作；它不重置会话或对白。

## 导入与保存

所有路径使用包内相对路径与 `/`，拒绝绝对路径、URL、`..`、重复路径和链接。只允许清单、引用资源及根目录可选的 UTF-8 `LICENSE.txt`、`CREDITS.txt`，拒绝未知字段与重复 JSON 成员。模型、动画、配套媒体完整验证后才发布；取消或失败保留原角色与已导入资源。

应用生成包 ID 和动作 UUID，重启保持；同一 ZIP 重导入复用身份，同内容资源按 SHA-256 去重。新名称、版本或重新打包不覆盖旧包。删除在用包前须更换绑定，不删除角色或聊天。

限制：ZIP 1 GiB、解压 2 GiB、1024 文件、清单 1 MiB；模型 512 MiB、单个动画或伴奏 128 MiB、图片 25 MiB 且不超过 4096×4096。最多 256 个动作定义（含待机与演出）、32 个待机变化。名称 80、作者 200、动作描述 1000、许可 2000 个 Unicode 码点。

VRMA 按 [VRM Animation 1.0](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm_animation-1.0/README.md) 解释人体旋转、髋部位移、表情节点的 `translation.x` 与 `lookAt` 旋转。合法轨道可组合或独立存在，允许省略 `humanoid`；目标模型缺少的合法自定义表情安全忽略。仍验证文件自包含、节点及动画结构、有限数值和目标属性，不接受未声明节点、非规范轨道或外部资源引用。

## 默认包与菜单

默认包为不可删除的 `builtin:default`，清单 v3、包版本 2.1.0。统一动作库共 **26 项**：基础待机 1 项、待机变化 2 项、普通动作 21 项、舞蹈演出 2 项。19 个固定用途通过 `bindings` 引用动作。动作目录与 key 统一命名，现有四个自定义动作 UUID 保持。

“我的悲伤是水做的”附 MP3、49 条歌词与 60 FPS GLB 镜头轨道，保留 44 处切镜；原镜头到 219.667 秒，末镜保持至动作结束的 224.5 秒。该镜头按与动作一致的髋部高度比例烘焙到默认角色空间，参考身高采用默认角色包围盒高度，避免光环导致镜头与动作重复采用不同缩放。“复梦天使”保留千夏居中版，约 50.67 秒、60 FPS 采样，带 6 处切镜及 6 条日中双语歌词。音乐取日语版原曲 48.000–98.667 秒，首句在动作第 1.402 秒出现。原有动作、音乐与歌词保持文件原始字节；此前实时对齐已由使用者确认，本次增加镜头不代表新镜头已完成使用者实机验收。

桌面下拉从实际能力生成动作列表，顶部用“单次动作 / 循环动作 / 舞蹈演出”三个标签筛选，外观沿用原选择器。当前实际播放项显示选中态，列表仅列出动作，再次点击播放项停止对应动作；自动待机素材按真实类型列入。包详情显示统一动作列表与待机、演出数量。

验证入口：`npm run typecheck`、`npm test`、`npm run test:database`、`npm run test:character-packages`；构建 Player 后运行 `npm run test:avatar-packages`，启动与菜单实机链路使用 `npm run test:startup`。自动化与使用者实机验收分别报告。

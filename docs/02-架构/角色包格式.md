# 角色包格式 v1

> 状态：默认包、包选择、导入删除、数据库绑定和 Unity 运行时 VRMA 适配已接入。默认动画资源已丢失，按用户决定先留空，后续配置。决策见 [D-064](../01-决策/决策记录.md#d-064--角色包与资源管理边界)。

## 范围与职责

角色包组合立绘、VRM 形象、系统动画和自定义动画。聊天角色继续拥有自己的名称、提示词、模型、声音、记忆与会话；角色包不携带这些配置，不执行脚本，也不自动修改聊天角色名称。一个聊天角色引用一个包，多个聊天角色可共用同一包；同时运行一个桌宠的现行规则不变。

Electron main process 负责解析清单、托管用户文件、生成 ID、资源去重、包引用与删除。Unity 负责模型和动画的实际校验、加载、调度与播放。renderer 通过受校验的 IPC 使用包信息和托管立绘，不获得托管目录真实路径。

角色页的立绘入口为角色包选择。完整立绘用于角色页，独立卡片图用于角色列表和包选择弹窗；作者直接提供裁好的图片，包内不保存焦点、缩放或裁切坐标，应用不提供角色包取景编辑器。选择包即可获得整个动作清单，不逐项勾选动作，也不提供动画编辑器。

## 文件容器

用户包扩展名为 `.katarune-character`，内容为普通 ZIP。根目录必须有 UTF-8 JSON `manifest.json`，无外层目录。文件夹布局不固定，清单中的相对路径是唯一定位依据。

```text
example.katarune-character
├── manifest.json
├── portrait.png
├── thumbnail.png
├── avatar.vrm
└── animations/
    ├── idle.vrma
    ├── look-around.vrma
    └── wave.vrma
```

- 立绘：PNG、JPEG 或 WebP，必须有一个可解码的文件；卡片图使用同样格式，可省略。
- 图像不强制比例或固定分辨率。卡片图推荐正方形 `512×512`，完整立绘推荐长边约 `2048` 像素，可保留透明背景。每张图片不超过 25 MiB，宽、高分别不超过 4096 像素；不设最小尺寸，不因偏离推荐尺寸拒绝导入。
- 卡片图完整等比显示，不拉伸或二次裁切；不同宽高比通过留白适配。未提供卡片图时使用完整立绘，同样完整等比显示。角色列表、主页左上角和包列表的图片区保持 1:1；图片比例不作为导入约束。
- 形象：必须有一个 VRM 1.0 文件，资源内嵌，不引用外部文件或网络资源。扩展名不能替代格式校验。
- 动画：v1 使用自包含 VRMA 文件，单文件包含一段大于 0、最多 3600 秒的 Humanoid 动画，不引用包外资源。v1 播放范围为人体骨骼动画；含表情或其他尚不支持的轨道时应明确拒绝，不静默丢弃。动画是否适合模型仍须由 Unity 校验及预览确认。
- 不接受 FBX、PMX、Unity 工程、DLL、脚本或 `.motionpack` 作为 v1 清单中的模型/动画输入。作者在包外完成格式转换。

采用 VRMA 的依据是其标准化 Humanoid 动画表达，以及锁定的 UniVRM 0.131.0 已包含对应 importer。当前项目的 `.motionpack` 是版本和平台受限的 AssetBundle；不能直接当作本格式，也不能假定已有 VRMA 待机链路等于自定义动作接入完成。实现时需要将 VRMA 对接现有统一调度与播放边界，不能增加第二套并行播放器。

## 清单示例

以下是作者填写的完整清单示例。示例名称和文件仅用于说明，不是可导入资源包。

```json
{
  "formatVersion": 1,
  "name": "示例角色包",
  "version": "1.0.0",
  "author": "示例作者",
  "license": "见资源原作者授权",
  "portrait": "portrait.png",
  "thumbnail": "thumbnail.png",
  "model": "avatar.vrm",
  "systemActions": {
    "idle": { "file": "animations/idle.vrma" },
    "idle_variations": [
      { "file": "animations/look-around.vrma" }
    ]
  },
  "customActions": [
    {
      "name": "挥手",
      "description": "向用户挥手打招呼，适合问候和告别。",
      "file": "animations/wave.vrma"
    }
  ]
}
```

| 字段 | 必填 | 契约 |
| --- | --- | --- |
| `formatVersion` | 是 | 整数 `1`；不支持的版本拒绝导入 |
| `name` | 是 | 包显示名称，1–80 个 Unicode 码点 |
| `version` | 是 | 作者版本，`主.次.修订` 三个无前导零的非负整数，例如 `1.0.0`；不作为包身份或自动更新依据 |
| `author` | 否 | 1–200 个 Unicode 码点；省略时显示未提供 |
| `license` | 否 | 1–2000 个 Unicode 码点的授权/借物说明；缺失不代表允许分发，文件自带的许可信息继续有效 |
| `portrait` | 是 | 包内立绘文件相对路径 |
| `thumbnail` | 否 | 包内卡片图相对路径；省略时使用 `portrait`，不填写裁切坐标 |
| `model` | 是 | 包内 VRM 1.0 文件相对路径 |
| `systemActions` | 是 | 对象；允许为空，未提供的系统动画使用内置兜底规则 |
| `customActions` | 是 | 数组，0–256 项；不提供任何作者定义的全局 ID |

JSON 不接受重复成员名；所有对象拒绝未知字段。文本须非空且无控制字符；`description` 与 `license` 可包含正常换行和制表符。作者信息只作为展示内容，不解析为可执行指令。

## 两类动作

### 系统动作

系统动作使用固定标识，不能由作者任意新增。v1 支持：

| 标识 | 值 | 触发与播放 |
| --- | --- | --- |
| `idle` | `{ "file": "相对路径" }` | 系统持续待机，循环播放；包可以省略，使用内置待机兜底 |
| `idle_variations` | 同上对象的数组，0–32 项 | 系统调度的待机变化，单次播放后回到待机；保留现有待机变化能力 |

只固定标识与触发语义，动画内容由角色包作者提供。省略 `idle_variations` 继承内置变化；空数组明确禁用变化。缺失 `idle` 使用内置 `idle`。内置动画需对当前模型有效，否则激活失败并保留原包，不把“文件存在”视为兜底成功。当前内置动作尚未配置：缺失系统动作时保留静态基础姿态，不伪造待机动画，也不向 AI 暴露动作。

包显式提供的系统动画损坏或不支持时拒绝激活，不静默替换为默认。系统动作不进入 AI 自定义动作清单。新增倾听、思考等系统标识应先扩展本契约与调度规则，v1 不预建这些状态。

### 自定义动作

每项只包含 `name`、`description`、`file`，均必填；名称 1–80 个 Unicode 码点，用途描述 1–1000 个 Unicode 码点。文件必须是包内 VRMA。名称可重复；同一文件可由不同描述的动作引用，不依赖文件名或显示名寻址。

Electron 在首次成功导入时用 `crypto.randomUUID()` 生成动作 ID，持久化后由角色包引用；Unity 回报可用性后，Electron 向 AI 提供对应 ID、名称与描述。工具执行以 ID 寻址，只允许当前绑定角色包中的可用自定义动作。名称与描述是用途元数据，不追加为高权限系统指令。

v1 自定义动作单次播放，结束恢复系统待机，沿用现有取消与打断边界；不开放无限循环、脚本回调或作者自定义调度器。手动预览也可播放自定义动作，但自动调用来源是 AI，导入动作不会自动播放。

## 身份与去重

作者清单不包含 `packageId`、`actionId`、资产哈希、绝对路径或安装状态。系统生成的数据保存在应用内部记录中，不回写作者 ZIP。

- 用户包 ID 与自定义动作 ID 均由 main process 生成 UUID，并在角色切换和重启后保持不变。资源哈希不是动作 ID。
- 系统动作按固定标识寻址，并在当前角色包范围解析；不同包的 `idle` 不冲突。
- 资源以实际文件字节的 SHA-256 和资源类型识别，同类型、同内容只托管一份；相同名称但内容不同保留为不同资源。播放参数、动作名称、用途与触发类型属于引用记录，不改变共享文件身份。
- 去重单位是单个立绘、模型或 VRMA 文件，不是整个 ZIP 或编译后的动作集合。不做相似动画或重新编码后的语义去重。
- 对整个原始 ZIP 记录 SHA-256。同一 ZIP 已安装时再次导入直接返回既有包，保留其包/动作 ID；已卸载后重导入生成新 ID。ZIP 重新打包或内容有变化，v1 作为新包导入，文件资源仍可去重。
- 包显示名和作者版本不会触发覆盖。v1 不提供自动升级/合并；用户显式更换角色的包引用。后续如需原位升级再定义稳定动作映射，不能按数组下标、名称或文件哈希猜测动作身份。
- 删除包先检查角色引用：仍被角色使用时拒绝删除，用户先更换包。删除不级联删除聊天角色、会话或记忆；仅回收没有引用的用户资源。

## 内置默认包

内置包使用系统保留身份 `builtin:default`，用户清单无权声明内置身份。它是一个可选择但不可删除的包，也是缺失系统动画的兜底来源。

默认模型和动画随 Unity Player 分发，由 Unity 解析内部固定资源标识；Electron 随包持有默认包信息、完整立绘与卡片图，桌宠关闭时仍能展示。默认包使用相同清单格式，构建时可以展开存放，不必压成 ZIP；“内置、不可删除”由应用登记，不是作者字段。清单仍使用包内相对路径；Unity 的内部加载定位由应用适配，不另建作者可见清单格式，也不把 Unity 私有路径暴露给 renderer。

默认自定义动作的 UUID 在构建资源清单时生成并保留；后续构建不得随机重建已有 ID。Electron 描述与 Unity 资源目录需使用同一份构建清单，加载时以整体资源实际验证和回报的可用能力为准。更新只替换内置资源，不覆盖用户包和角色绑定。

用户包 v1 必须携带自己的模型与立绘；可以不携带动作。默认包只兜底缺失的系统动作，不自动向用户包追加默认自定义动作。内置资源本身仍按应用版本升级，不承诺与用户文件跨来源物理去重。

## 导入与校验边界

导入流程为：选择 ZIP → main 暂存与检查 → 解析资源 → Unity 实际校验 → 发布包记录。包未通过校验前不成为可选的就绪包，也不改变当前角色绑定；Unity 运行时使用候选校验接口；桌宠关闭时启动隐藏的临时 Unity 验证进程，完成或取消后退出。未验证的包不进入选择列表。失败或取消清理暂存，不影响既有包和共享资源。

路径使用 `/` 分隔的包内相对路径，长度 1–240 个 Unicode 码点。不接受绝对路径、盘符、反斜杠、空段、`.`、`..`、冒号、URL、控制字符、Windows 保留设备名、尾部空格/句点或其他 Windows 非法文件名字符。拒绝符号链接和特殊文件；规范化后大小写不敏感的重复路径、文件与目录冲突均拒绝。先检查再写入，解析后的目标必须留在暂存根目录。

v1 导入上限：ZIP 1 GiB，实际解压总量 2 GiB，普通文件 1024 个，清单 1 MiB，单个模型 512 MiB，每张图片 25 MiB，单个动画 128 MiB。解压过程中累计实际写入量，不能只信 ZIP 声明大小；立绘和卡片图解码前检查宽、高分别不超过 4096 像素。清单必须引用存在且格式匹配的文件；只允许清单、被引用资源以及根目录可选 UTF-8 `LICENSE.txt`、`CREDITS.txt`（每份最多 1 MiB），额外内容拒绝导入。

Unity 校验 VRM 版本、骨架、动画轨道、正时长和可播放性；Electron 校验容器、清单、路径、大小和字节哈希。完整包激活遵守候选准备、验证、提交，模型与动作一起切换，失败保留旧形象和旧动作清单，不发布半成功包。本规范不以未经测量的加载耗时作为完成条件。

## 当前实现与验收

默认包位于 `resources/characters/default-package/`，使用现有完整立绘、独立生成的 1:1 大头卡片与 `Models/default-avatar.vrm`。`systemActions` 和 `customActions` 当前为空；以后在这份清单中补动作文件，内置自定义动作的 UUID 同步记录在 `action-ids.json`。构建复制默认包资源到 Player 的 `KataruneLocal` 目录，Electron 独立保存包元数据和图片。

迁移为已有角色绑定 `builtin:default`，新角色也使用该包。原立绘文件及数据库记录保留，不再参与显示；旧裁切界面、IPC、暂存预览与 `react-easy-crop` 已删除，历史坐标列只保留在数据库中。

包弹窗浏览时不更换绑定，点击“使用”才提交。在线先整体激活模型与动作，再保存绑定；数据库失败恢复旧包。桌宠关闭时保存绑定，下次启动加载。内置包不可删除，被角色引用或正在切换的包也不可删除。包删除不删除角色或聊天数据。

验证命令：`npm test`、`npm run test:database`、`npm run test:character-packages`、`npm run test:ui`。构建 Windows Player 后可用 `npm run test:avatar-packages` 检查实际加载、VRMA 重定向、取消、切换、失败保持及语音/字幕；测试夹具不会作为默认动作分发。动画审美、最终资源内容以及新包的原生桌面使用体验仍需使用者验收。

2026-10-01 已通过类型检查、336 项单元测试、数据库和角色包导入集成测试、主窗口/UI 检查、178 项 Unity EditMode 测试与 Windows Player 构建。实际 Player 已验证候选校验不改变当前包、系统待机、自定义动作、取消、跨包 ID 失效、失败保留旧包，以及合成音频口型和字幕回归；没有调用真实语音供应商。原生画面检查可运行 `npm run test:avatar-packages -- --visible` 并查看本次 `.test-dist/avatar-packages/` 输出，隐藏窗口截图在 Windows 上可能为黑色。上述结果不代替最终动作资源及人工使用体验验收。

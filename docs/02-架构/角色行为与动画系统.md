# 角色行为与动画系统

本页维护当前形体运行机制与需要保留的不变量。实施待办统一放在[路线图](../03-规划/路线图.md)，不再维护独立阶段计划。

## 职责

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| Electron main | 对话、记忆、模型/工具、TTS、可信传输和 Player 生命周期 | 动画帧、骨骼或混合权重 |
| Unity Core | 行为契约、实例生命周期、通道所有权与调度 | Provider、文件路径和具体模型格式 |
| Unity Motion | Humanoid Binding、动作资源和统一 PlayableGraph | AI 决策与用户数据 |
| Unity UniVrm | VRM 1.0、Control Rig、表情及材质适配 | 通用 Agent 循环 |
| Unity Runtime | Facade、模型事务、窗口、音频、字幕与实际运行状态 | 供应商凭据与独立会话历史 |

外部控制统一经过 Facade；模型替换遵守 `prepare → validate → commit`，候选失败保留原模型。Unity 返回权威状态，Electron 不通过“请求已发送”推定播放已开始或完成。

## 对白、动作与表情

1. Electron 转发当前会话的完整 AI SDK `UIMessageChunk` 流。原生文本建立对白，工具事件建立编排位置，推理、参数和结果不是对白。
2. 动作/表情由受信任的工具执行回调提交；观察流事件不重复执行工具。只向 AI 暴露当前模型和角色包实际可用的能力。
3. 工具接收确认与实际播放终态分开。Agent 循环不等待 Unity 排空；Unity 独立维护跨轮播放队列，后台 drain 只管理音频资源回收。
4. 表情到达时间线节点时应用并保持。动作真正开始后，`allowSpeech` 决定是否放行后续对白；禁止并行时等待动作终态。
5. TTS 从完整原生文本块结束事件衍生，音频和时间戳补入同一对白节点；不引入 `speak`、隐藏标签或第二份对白历史。

普通消息使用框架原生格式持久化。绑定会话的新文字按顺序等待当前生成结束；语音确认式插话优先于尚未发送文字。队列不持久化，界面生成状态不等于 Unity 播放状态。

## 音频、字幕与口型

Electron 管理 Provider、缓存、音色和格式校验；Unity 管理实际 AudioSource、口型和字幕时钟。普通朗读与桌宠播放不能同时消费同一回复；Unity 已开始播放后发生失败，不在浏览器重复播放。

有声字幕按实际播放游标推进，无声对白使用阅读时间轴。Fish 增量 PCM 使用独立二进制管道与有界缓冲；断流时输出静音并冻结有效播放位置及字幕，可靠对齐未到时保持当前页。网络接收量和 PCM 预读量不等于用户已经听到的音频。

uLipSync 分析实际音频，结果经 Facade/行为系统驱动 VRM；平滑只有一个来源。停止、取消、切换和模型卸载须释放播放资源并清零口型。音色 Profile 与模型分离，按供应商实例、模型 ID 和 Voice ID 定位。校准与回放入口见[工程规范](../04-开发/工程规范.md#语音与-ulipsync-开发验收)。

## 行为与通道

复杂表演沿用 `请求 → 定义 → 计划 → 实例` 的边界：

- `BehaviorIntent` 表达高层意图和约束；不包含骨骼、帧或混合权重。
- `BehaviorDefinition` 声明能力、通道、片段、同步点、退出及许可信息。
- `PerformancePlan` 由 Unity 内部编译，不由 AI 或宿主构造。
- `PerformanceInstance` 保存权威生命周期、revision 和结束原因；重复取消、终结和迟到事件须幂等。

Core 调度器唯一授予与释放通道；终态释放资源后再提升互斥队列。立即取消、安全点退出、暂停和继续有不同语义，只能按定义支持的控制能力执行。安全限制和明确用户停止优先于 AI 请求。

当前通道为基础身体、全身表演、上半身手势、头部手势、表情、视线和口型。通道是语义资源，不与 Animator 图层一一对应，也不合成一个全局“倾听/思考/说话”状态机。

动作和基础姿态沿用统一动作调度；手动与 AI 请求使用相同的通道和转换规则。Mask、通道及退出段按素材真实覆盖范围验证，不能因名称叫“解释”就裁掉腿部或改变重心。角色包有 `idle` 时直接播放；没有时，内置归一化固定站姿拥有身体通道，头发和衣饰播放模型适配的烘焙循环。身体不额外叠加呼吸或重心噪声；眨眼、视线、口型沿用各自通道。

持续环境风已移除。烘焙循环在 VRM 更新后写回次级骨骼，同时暂停 Spring Bone 写回；预制动作期间恢复物理，回到待机时平滑恢复循环。导入异步准备、默认预烘焙与缓存规则只在[角色包格式](角色包格式.md)维护。不能适配的链保持参考姿态，不伪造已安装动作能力。

## 资源与切换

用户角色包采用 VRM 1.0 与 VRMA，身份、系统动作、自定义动作和失败回滚以[角色包格式](角色包格式.md)为准。`.motionpack` 是现有 Unity AssetBundle 资源入口，`.kbehavior` 是复杂行为定义入口；二者不替代用户角色包契约，也不增加并行播放器。

角色包整体准备模型与动作。在线激活成功后保存绑定，数据库失败恢复旧包；切换会话沿用同一个 Player，通过绑定代次与 reset 清理旧表演。字幕、输入排除区和窗口布局见[桌面交互设计](../00-项目/桌面交互设计.md)。

## 动作控制器与编排规则

角色包 v2 已接入系统语义、包内自定义标识、进入／循环／退出及独立头部／上半身遮罩；未发布的 v1 读取分支已移除。VRMA 适配器使用一个 Core PerformanceScheduler 管理三个播放通道的实例，按身体 → 上半身 → 头部合成归一化姿态，再由 VRM 写回模型。默认包实际资源见角色包格式。

### 请求与实例

保留系统／自定义动作入口：系统请求固定语义，自定义请求包内名称或编号。main 按当前绑定角色解析能力和资源身份；Unity 生成、更新和终结播放实例，回报真正开始与终态。AI 提供目标行为及结束／取消意图，不提供骨骼、权重或游戏内部参数编号。

明确请求可以切换到不同循环姿态。当前实例与同一行为的重复请求按更新或幂等处理，避免每条请求都重新播放进入段；实例终态后再次请求可以重新开始。持续姿态保持到下一次明确切换或结束；一次性动作按片段结束。缺失明确语义的动作不由文件名猜测补齐。

### 动画层

| 层／通道 | 内容 | 控制与转换规则 |
| --- | --- | --- |
| 基础身体 | idle、当前站姿／坐姿基准 | 保留返回姿态；被完整身体行为覆盖时不同时写同一组骨骼 |
| 身体行为 | 思考、交谈、抱臂、叉腰等 enter / loop / exit | AI 可切换循环；正常结束走退出段，明确停止支持强制取消 |
| 一次性身体手势 | 问候、鼓掌、鼓励、指向等 | 依据真实曲线采用上半身遮罩或全身占用；结束回到原循环或基础姿态 |
| 头部手势 | 点头、摇头 | 扣除参考姿态后叠加在当前颈头旋转上，结束平滑恢复；VRMA 期间程序化头部调整不写同一骨骼 |
| 视线 | 注视目标、头颈与眼球跟随 | 在身体和头部动画后独立叠加；眼球补偿原动画的头部转向，不受身体兜底权重影响 |
| 表情与口型 | 表情、眨眼、语音口型 | 沿用各自通道；情绪身体动作不自动等同于已映射的脸部表情 |
| 次级骨骼 | Spring Bone 或已有烘焙循环 | 保持唯一写回来源；站姿烘焙不直接套用于坐姿或其他大幅姿态 |

三个播放通道独立推进；上半身不写髋腿与位移，头部只写颈头。每个通道保存一层原循环：同通道手势暂停原实例并暂借其占用，结束或取消后恢复相同实例，从 `enter` 重新进入 `loop`；缺少 enter 则从 loop 第 0 帧开始。其他通道持续运行，不重播入场。加法混合使用 `参考旋转的逆 × 采样旋转`，再乘到下层旋转上。转换和取消只重置对应通道的混合，不冻结其他通道。

素材制作阶段保证 `enter` 末帧与 `loop` 首帧连续，来源特有的重叠预先烘焙，循环相位同步调整。播放器按 `enter → loop` 自然接续，不在边界追加冻结姿态平滑；`blendSeconds` 仍用于不同动作之间的切换。资源曲线质量与播放器衔接分别验证，角色包不携带来源游戏的状态机参数。

上半身遮罩用于保持当前身体姿态的组合，不等于源动作原本只动上半身。默认问候、说话手势和鼓掌提供遮罩及完整版本，跳跃、蹲起保留全身配合。源游戏控制器确认有加法头部和肢体控制层，但没有证据表明其全部交互动作都按本项目的上半身规则运行。

### 状态与转换条件

实例生命周期沿用 Requested、Accepted、Running、Paused、Exiting、Completed、Cancelled、Failed；运行阶段记录 Enter、Loop、Exit 和混合目标。阶段和动作资源分开，新增资源不增加一整套生命周期状态。

| 触发 | 预期转换 |
| --- | --- |
| 新循环请求，身体可用 | 当前姿态 → 新行为进入段 → 循环 |
| 当前循环被同通道一次性手势打断 | 保存原行为 → 手势 → 原行为 enter → loop；只支持一层恢复关系 |
| 同一持续行为再次请求 | 更新当前实例或返回当前状态，不重启进入段 |
| 请求切换另一循环 | 旧循环 → 旧退出段 → 新进入段 → 新循环，不插入 idle；退出期间只保留最新切换请求，重复选择不重播 |
| 请求正常结束 | 循环 → 退出段 → 保存的父行为／基础姿态 |
| 手动选择“无” | 取消临时手势并自然退出各通道的持续姿态；待启动的切换请求取消 |
| 用户强制停止、会话 reset 或模型卸载 | 取消相关实例、释放占用及延迟事件；绑定代次变化后旧事件不可影响新角色 |
| 进入／退出段自然结束 | 当前按片段自然结束推进，并使用行为的 blendSeconds 混合；按边退出阈值留待素材需要时扩展 |
| 系统自动待机变化 | 只在允许的空闲时启动；明确请求到达时让位 |

各通道分别回报实例终态；取消指定动作只影响该实例，会话重置、卸载及明确全局停止才清除全部。对白屏障按通道记录一次性动作，持续姿态不阻塞 drain；不同通道的手势能同时开始。身体动作不能因一句话结束而清除独立表情或口型。发起明确循环切换的处理与自动小动作的冷却分开，不逐个 token 改变身体行为。

### 验收与后续

1. 已支持 v2 契约、系统语义、包内自定义 key 和分段循环；默认包同步使用 v2。
2. 已接入进入、持续、退出、循环切换、重复请求和强制取消；一次性动作结束恢复同一原循环实例。循环请求接收与实例终态分开，持续姿态不占用对白排空屏障。
3. 头部／上半身混合及上表默认资源已接入；检查三通道并行、髋腿遮罩、同实例恢复、独立取消和进入／退出。
4. 检查 idle → 思考 → 点头与问候并行 → 恢复思考 → idle、循环互切，以及全部默认资源加载和播放；自动化与最终观感分别验收。
5. 自动事件触发策略仍待实现；自动待机变化只在三个动作通道都空闲时触发。任一预制动作运行时，兜底次级烘焙让位于 Spring Bone。

“有节奏”具体指：自动待机变化不连续触发，同一思考实例不因重复请求反复抬手。AI 明确要求从思考切到交谈或抱臂时，按转换规则执行，不以装饰动作的冷却拒绝该请求。

## 尚未确定的扩展

长舞蹈、唱歌或剧情表演需要有效素材后再完善分段、语音锚点和安全退出。主动行为、共同活动、虚拟世界与实体躯体属于后续方向，不把已退役样片或旧阶段计划当作当前能力。

扩大能力时保留三类验收：实际资源加载与失败保持；并行/打断/终态资源回收；当前角色上的有声画面与表现质量。已有自动化结果不替代新素材的视觉验收。

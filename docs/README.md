# 言奏文档

这里记录言奏的产品定义、工程决策和演进计划。项目已经完成 P1 技术验证基线与 P2 最小垂直闭环，可信模型流、工具调用、可恢复会话和首个真实 TTS Provider 均已贯通；P3 已完成角色、多会话、聊天附件与角色级 Memory Wiki 的最小闭环，P4 已接通 Windows Unity 桌面角色、AI 控制、原生对白 TTS、时间戳字幕、uLipSync 与 Fish 增量 PCM 播放；资产体验、正式桌面输入、ASR 和发布验收等工作仍在推进。文档中的内容按以下状态区分：

- **已决定**：除非出现新的关键证据，否则作为项目约束执行。
- **待决定**：保留候选方案，讨论后再确定。
- **暂缓**：当前阶段不实现，但保留未来扩展空间。

## 文档原则

1. 先写清问题和边界，再选择技术。
2. 已有成熟实现能满足需求时，优先集成，不重复建设。
3. 重要选择必须记录状态、理由和代价。
4. README 只保留高层概览，详细说明进入 `docs/`。
5. 文档描述当前事实；设想和候选方案必须明确标注。

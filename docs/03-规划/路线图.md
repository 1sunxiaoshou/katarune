# 路线图

路线图不绑定日期，按风险和依赖关系推进。第一目标是验证架构闭环，而不是快速堆积功能数量。

## P0 · 项目准备

- [x] 确定项目名称与基本定位。
- [x] 建立独立目录和文档结构。
- [x] 记录首批架构原则与待决策项。
- [x] 制定代码、文档、版本和提交规则。
- [ ] 完成名称的商标、域名及主要分发平台检查。
- [ ] 确定许可证与开源边界。

## P1 · 技术验证

- [x] 验证 Electron 内置 Node.js 运行时及 main/preload/renderer 安全边界。
- [x] 验证并锁定 npm、`electron-vite` 与 `electron-builder` 的兼容版本。
- [x] 锁定 AI SDK 与 assistant-ui 的兼容版本。
- [x] 验证 Electron 开发、`better-sqlite3` 原生模块重建、ASAR 解包与 Windows 打包链路。
- [x] 验证 `better-sqlite3` + Drizzle 稳定版并锁定版本与迁移流程。
- [x] 建立共享的 Zod 契约和最小测试体系。

完成标准：形成一次可复现的技术决策，而不是交付完整产品。

## P2 · 最小垂直闭环

- [x] 接入 assistant-ui 官方成品 Thread 与 shadcn/Tailwind 基础，删除重复基础组件和旧验证页面视觉实现。
- [x] 显示一个可恢复的聊天线程。
- [x] 建立安全凭据引用、Provider/模型配置持久化、首批 Provider Factory、动态 Registry 与显式连接测试。
- [x] 通过应用内受信任配置选择一个模型并完成流式回复。
- [x] 执行一个类型安全、无高权限的本地测试工具。
- [x] 按当前模型 Provider 能力装配原生 Web 工具，不支持时明确保持不可用。
- [x] 将 assistant-ui / AI SDK 原生格式消息写入 SQLite，并通过关闭、重开恢复测试。
- [ ] 接入一个 TTS Provider 并完成播放。

完成标准：用户能与一个有模型和声音的角色完成一次可恢复的持续会话，并验证完整工具调用链路。

## P3 · 现有能力接入

- [x] 完成供应商、模型和受信任凭据录入的功能链路验证。
- [x] 使用 shadcn 默认组件重新建立设置界面，并保留 Provider、模型与凭据功能链路。
- [ ] 完成应用级默认模型。
- [x] 完成角色级模型选择。
- [ ] 角色、提示词和资产管理（已完成角色即 Agent、默认初始化、按创建时间倒序、草稿式新增、确认删除、编辑、模型引用、系统提示词、共享角色卡片、活动角色、通用资产注册表、资产协议与托管立绘导入；手动排序或拖拽调整顺序及其他资产类型待完成）。
- [ ] 将立绘专用导入泛化为通用托管资产导入，接受未知附件格式，保留不可变文件、SHA-256、MIME、原始文件名、缺失修复和安全资产协议边界。
- [ ] 使用 assistant-ui `AttachmentAdapter` 实现 `KataruneAttachmentAdapter`，通过 preload/IPC 导入附件并生成 AI SDK 原生 `FileUIPart`；renderer 与 SQLite 不保存完整 Base64 或原始绝对路径。
- [ ] 在 main process 完成附件发送物化：按 Provider 能力复用 `providerReference`、调用 AI SDK `uploadFile()` 或临时内联内容，并为不支持的模型返回明确错误；建立消息资产引用、Provider 引用缓存、移除与垃圾回收验证。
- [x] 实现多会话与消息历史，并在交互和结构上清晰区分“新建会话”操作（角色与线程固定绑定、按角色隔离、跨角色后台并发、角色风格自动标题、按最近消息活动实时排序和星轨会话侧栏已完成；归档管理入口待规划）。
- [ ] 调查并确定长期记忆的语义模型、生命周期和评估方法。
- [ ] 设计记忆的检索、更新、遗忘以及用户可见、可编辑机制。
- [ ] 分析旧文件记忆并制定数据迁移方案。
- [ ] 调查并确定 VRM 渲染、资产、动作、表情和反馈链路的技术路线。
- [ ] 接入现有 TTS 与 ASR 能力。
- [ ] 制定 ATRI Chat 数据迁移方案。

完成标准：覆盖现有产品的核心使用场景，同时保持新的架构边界；用户选择的附件进入本地托管资产库，重启后仍可预览，并能按当前模型的真实能力发送或得到明确的不支持错误。

## P4 · 言奏核心体验

- [ ] 根据技术验证结果接入 VRM 运行时与驱动接口。
- [ ] 统一角色状态、语音与形体表现。
- [ ] 建立可扩展的决策器和行为策略接口。
- [ ] 改善长期记忆的可控性、可见性和可编辑性。
- [ ] 建立工具权限、用户确认和桌面安全策略。
- [ ] 完善角色资产的导入、组织与预览体验。

## P5 · 生态扩展

- [ ] 按实际需求接入 MCP 工具。
- [ ] 评估 ACP/A2A 等外部 Harness 协议。
- [ ] 评估现成文件、脚本执行和长期记忆实现。
- [ ] 建立第三方扩展边界与兼容策略。

P5 不应提前阻塞 P2 和 P3；只有真实需求出现时才引入对应系统。

# 路线图

路线图不绑定日期，按风险和依赖关系推进。第一目标是验证架构闭环，而不是快速堆积功能数量。

## P0 · 项目准备

- [x] 确定项目名称与基本定位。
- [x] 建立独立目录和文档结构。
- [x] 记录首批架构原则与待决策项。
- [x] 制定代码、文档、版本和提交规则。
- [ ] 完成名称的商标、域名及主要分发平台检查。
- [ ] 确定许可证与开源边界。

## P1 · 技术验证

- [ ] 比较并确定 Node.js、Bun 或混合运行时方案。
- [ ] 锁定 AI SDK 与 assistant-ui 的兼容版本。
- [ ] 验证 Tauri 开发、sidecar 与 Windows 打包链路。
- [ ] 确定 SQLite 驱动、查询层和迁移工具。
- [ ] 建立共享的 Zod 契约和最小测试体系。

完成标准：形成一次可复现的技术决策，而不是交付完整产品。

## P2 · 最小垂直闭环

- [ ] 显示一个可恢复的聊天线程。
- [ ] 配置一个模型供应商并完成流式回复。
- [ ] 执行一个结构化 VRM 表情工具。
- [ ] 将消息写入 SQLite，重启后恢复。
- [ ] 接入一个 TTS Provider 并完成播放与口型驱动。

完成标准：用户能与一个有模型、形象和声音的角色完成一次持续会话。

## P3 · 现有能力接入

- [ ] 供应商与模型配置管理。
- [ ] 角色、提示词和资产管理。
- [ ] 多会话与消息历史。
- [ ] 迁移现有角色记忆语义。
- [ ] VRM 动作、表情、镜头和反馈链路。
- [ ] 接入现有 TTS 与 ASR 能力。
- [ ] 制定 ATRI Chat 数据迁移方案。

完成标准：覆盖现有产品的核心使用场景，同时保持新的架构边界。

## P4 · 言奏核心体验

- [ ] 统一角色状态、语音与形体表现。
- [ ] 建立可扩展的决策器和行为策略接口。
- [ ] 改善长期记忆的可控性、可见性和可编辑性。
- [ ] 建立工具权限、用户确认和桌面安全策略。
- [ ] 完善角色资产的导入、组织与预览体验。

## P5 · 生态扩展

- [ ] 按实际需求接入 MCP 工具。
- [ ] 评估 ACP/A2A 等外部 Harness 协议。
- [ ] 评估现成文件、脚本执行和长期记忆实现。
- [ ] 建立第三方扩展边界与兼容策略。

P5 不应提前阻塞 P2 和 P3；只有真实需求出现时才引入对应系统。

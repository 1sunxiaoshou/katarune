# 角色行为与动画系统推进计划

> 状态：讨论中，作为后续 AI 与开发者执行本方向工作的主推进文档。架构边界以[角色行为与动画系统](../02-架构/角色行为与动画系统.md)为准；本页只描述实施顺序、阶段交付物和验收条件。

## 推进目标

用最少的系统代码和三类代表性真实素材，验证“高层行为请求 → 资产解析 → 多通道调度 → 动画混合 → 柔性打断 → 恢复基础状态”的完整链路。在链路稳定以前，不批量制作动作、不建设插件生态，也不增加动作名称分支。

核心顺序是：

> 先搭最小系统骨架，立即用真实素材验证；系统和资产共同迭代，但不让任何一侧提前扩大规模。

## 桌面可玩切片优先

> 状态：当前产品方向；具体玩法仍开放讨论，不在本阶段一次定完。

本计划的近期目标不是单独完成一套通用动画框架，而是支持一个用户能够实际体验并判断价值的桌面可玩切片。切片至少需要形成以下循环：

1. 用户发起一次真实任务、共同活动或直接场景交互。
2. 角色的身体与注意表现映射真实运行状态，而不是只播放随机装饰动画。
3. 用户可以在过程中观察、插话、打断或改变方向。
4. 行为结束后产生可见结果或持续状态，使下一次互动不是完全重新开始。

首个切片的具体空间形态、交互物体和轻量玩法在 B 至 D 阶段开始前单独做产品对齐；可以是透明桌面形态，也可以加入有限的桌面场景，但不因此提前建设完整房间模拟、养成系统或游戏关卡。动作数量、调度能力和素材投入都应由该切片的真实需求反推。

VRChat、其他社交场景和外部虚拟世界接入保留为后续探索方向。当前不为其平台约束、Avatar 规范或网络同步提前修改领域模型；只有桌面切片证明角色陪伴与具身交互具有价值后，再独立调研平台规则和最小接入路径。

## 当前基线

当前 Unity Runtime 已具备独立工程、透明桌面窗口、VRM 原子加载、标准化 Control Rig、表情与视线驱动、程序化基础姿态、行为资产、PlayableGraph 混合、调度器、Facade 和带 Revision 的权威快照。

2026-08-30 默认待机现改为本机测试 VRMA 循环，替代当日临时恢复的程序化呼吸与颈头微动。默认模型和动作统一为 `default-avatar.vrm`、`idle-standing-breathing.vrma`，后续可替换同名文件。保留眨眼、视线与环境风；最终角色动作美术仍未锁定。测试素材只进入 Git 忽略目录与本机 Player，详见 D-050。

2026-08-30 桌宠 HUD 新增默认关闭的一级角色展示开关。开启期间把 VRM 根固定在世界原点并只绕作者根轴水平旋转，提供跟手阻尼与松手惯性；左键垂直拖动提供上下各 `45°` 的受限摄像机俯仰，滚轮只平滑改变投影倍率，中键只平滑改变 `lensShift` 构图偏移。三类状态互不改写，缩放和平移都不移动角色或基础相机位姿。透明窗口仅在该模式期间整窗接收输入，关闭或卸载模型后恢复普通点击穿透。视线追踪继续复用最终摄像机和当前角色根朝向，不新增设置字段或模式。

推进工作保持模型事务、Facade、快照和 Core / Motion / UniVrm / Runtime 分层，并以 Unity 能力清单和行为资产扩展表情与动作，不增加固定动作枚举或绕过调度器的播放入口。

## 首轮范围

首轮只验证一个角色、一个基础骨架和三类动作：

1. **基础待机循环**：验证持续底层、循环接缝和恢复姿态。
2. **解释动作**：按素材真实覆盖范围声明身体通道；当前 UAL1 `Idle_Talking` 是全身动作，用于验证说话、口型和视线与全身表演并行。
3. **可中断短表演**：使用十五至三十秒的舞蹈或连续动作，验证全身所有权、安全退出点和自然回待机。

首轮不做：

- 批量动作库和多角色全量兼容。
- 完整动作编辑器或面向用户的素材市场。
- MCP、第三方插件平台和公开逐帧控制接口。
- 生成式人体动作、自动编舞和端到端 AI 骨骼控制。
- 完整移动、攀爬、战斗或游戏式地形交互。
- 为迁就某一个测试模型而在领域层写入 PMX、VRM 或原神特有名称。

## 资产策略与安全边界

### 测试资产分级

- `dev-only`：仅用于本地研究和适配测试，不进入仓库、CI、演示包或安装包。官方公开但禁止再分发或禁止营利的 PMX 模型属于此类。
- `prototype-distributable`：许可允许仓库保存与原型分发，可作为自动化测试和团队共享样片。
- `commercial-ready`：拥有明确商业使用、修改、嵌入和必要分发权，可进入候选产品资产库。

格式转换、重定向、裁剪或修改不会改变授权等级。每项资产必须保存来源、作者、原始许可证、获取日期、允许用途、是否允许修改、是否允许再分发和证明文件；授权不明时按 `dev-only` 处理。

### 获取优先级与数量控制

首轮不建设动作收藏库。同一用途默认只选择一份最合适的素材，并按以下顺序处理：

1. 优先选择免费、授权清楚、质量较高、发布时间或维护状态较新的素材。
2. 免费候选能够满足架构验证时，不再下载同类替代品，也不花预算购买重复动作。
3. 找不到合适免费素材时，再评估低价付费素材；总预算单独确认后才购买。
4. 只有现成素材无法表达所需动作，或后续需要角色专属风格与更高质量时，才使用手机录制、无标记动捕和人工精修。
5. 定制委托属于最终内容阶段，不用于弥补首轮系统尚未验证的问题。

任何外部素材进入 Unity 都仍需完成必要的技术适配，包括骨骼重定向、循环检查、根位移策略、同步点、安全退出点和许可登记。这些属于导入验收，不等于重新创作或美术精修。

### 首轮素材来源

- 模型：可以用官方公开 PMX 作为本机适配样本，但不提交和不打包；同时准备至少一个可分发的标准 Humanoid 测试模型供 CI 和其他开发者使用。
- 待机、移动与短表演：首轮优先从 [Rokoko 免费资源](https://www.rokoko.com/free-resources) 和 Motion Library 的免费动作中选择。官方页面说明其免费动作可用于动画、VFX、游戏和其他 3D 项目，包括商业用途；下载时仍须保存具体资源页、许可文本和获取日期。候选顺序是 everyday idle、walk/run、dance，再从 office 或 TV 类动作中寻找可裁剪的上半身手势。
- 手势补充：Rokoko 免费库缺少合适的解释或反馈动作时，再使用许可清楚的 CC0 / Mixamo 素材，或用手机视频无标记动捕自行制作。
- 短表演不得使用游戏客户端解包动作；音乐、编舞和动作数据分别核对授权，不能因动作文件可用而推定配乐可用。
- 音频：首轮表演可用节拍或无版权测试音频；不得因为动作可用而默认音乐和编舞也获得授权。

### 最小加工流程

```text
获取与授权登记
  → 源文件隔离
  → 骨骼映射与重定向
  → 脚底、重心、抖动和穿模清理
  → 循环、入口、退出与同步标记
  → 通道与兼容性声明
  → Unity 预览验证
  → 打包并生成清单
```

首轮不要求自动化全部加工步骤，但产物必须能由另一位开发者按清单复现。开发期本地受限资产通过外部路径加载，不写入仓库相对路径或机器绝对路径。

工作项：

### C · 打通三个素材样片

工作项：

- [x] 待机循环能连续播放，首尾没有明显跳变，并能作为身体 `GroundState`。
- [x] 解释动作按真实覆盖范围申请身体通道，不破坏正交的视线与口型；当前 UAL1 `Idle_Talking` 已纠正为无 Mask 的独占全身表演。
- [x] 短表演声明全身所有权、至少一个安全退出点和一个退出段，完成后自然回到基础待机。
- [x] 记录每份样片的来源、许可证、骨架、重定向修正、同步点和已知缺陷。

交付物：三份可重复导入的动作样片与对应定义。美术质量只需足够暴露架构问题，不以数量或最终观感作为完成标准。

完成条件：三份素材都通过同一个资产入口加载，不为单个动作增加硬编码枚举或名称分支。

验收记录（2026-08-22，2026-08-23 修正）：三份样片分别为项目自有 `KataruneQuietIdle`、Quaternius UAL1 `Idle_Talking` 规范化的全身解释动作，以及 UAL1 `Dance` 规范化的 16.5 秒短表演。实机复查确认 `Idle_Talking` 的腿、重心和头部都是原动作组成部分，原上半身 Mask 会造成不自然裁切，现已删除；真实上半身专用样片尚未验收，`Gesture.UpperBody` 只保留为领域能力。UAL1 官方页和包内 `License.txt` 均标明 CC0 1.0；仓库只收录规范化 Unity Clip，原始 FBX 留在 Git 忽略的本地源目录。三者均由同一 `.kbehavior` 导入器加载；C 阶段没有新增动作枚举。

真实素材压力使定义补充了有限循环次数、退出段对应的安全同步点、可选 Avatar Mask、完整使用权元数据和可选段存在位。短表演的稳定安全点是 0.5 秒站姿，十五个完整循环后等待下一次该点进入一秒退出段；Root/Motion 固定到待机基线，退出肌肉曲线禁止过冲。2026-08-23 修正后的批处理预览检查待机首尾、全身解释、舞蹈循环、退出中点与恢复待机；Avatar Mask 的解析与校验仍有自动化覆盖，但不再声称当前解释动作通过 Mask 完成了真实局部手势验收。

2026-08-28 用户否决了上述三份动作的表现质量，并从当前工作树移除对应规范化 `.anim`，转为从 Git 忽略的本地候选中人工重选。C 阶段的契约压力结论继续有效，但三份历史样片不再是当前正式资产；与其文件存在性和视觉内容绑定的阶段性测试已退役。新选择必须重新完成循环、重定向、通道、退出和许可证验收，不能借用历史样片的通过记录。

交付物：可在 Unity 内独立运行的两个验收场景。

完成条件：调度器是唯一通道所有者；所有终态释放资源；重复取消不会产生第二次副作用。

实现记录（2026-08-22，2026-08-23 修正）：Core `PerformanceScheduler` 已成为新行为实例唯一的通道授予与释放点，Motion 层通过 Resources 中的三样片目录完成资产解析、能力校验和单 Clip 播放计划执行。现有同一张 `AnimationLayerMixerPlayable` 承载基础身体和一个归一化的全身 Performance Mixer；解释与短舞蹈都按源素材作为无 Mask 的独占全身表演。全身表演以 SmoothStep 在 0.20 秒内淡入，自然完成以 0.25 秒恢复，安全退出尾段以 0.20 秒恢复，立即取消在 Core 立即释放后只保留 0.12 秒冻结姿态视觉淡出。过渡期间程序化身体按表现总权重连续降低或恢复，表情、视线与口型仍由正交通道继续运行。安全退出在 `exit.safe` 前保持所有权，退出段完成后才提升互斥队列；重复取消不再产生第二次结束或播放副作用。Facade 与带 Revision 的 Snapshot 新增行为请求、命令和调试状态入口，日志可见实例、阶段、通道所有者、同步点与结束原因。

两个独立验收场景位于 `Assets/Katarune/Scenes/Acceptance`：说话与全身解释场景模拟语音、自动凝视、口型和全身解释动作，舞蹈中断场景自动复现安全退出、互斥排队与明确停止。基础姿态和调度身体实例共享同一 Animator 输出，不会形成双重驱动。2026-08-23 修正后定向 EditMode 28/28、完整 EditMode 139/139、PlayMode 4/4 通过；另有 1 项本地 VRM 烟测因未设置仓库外 `KATARUNE_TEST_VRM_PATH` 按设计跳过。批处理重新生成六张样片帧，新的全身解释帧保留了原动作的分腿站姿和重心。两个场景在产品 VRM 上的混合观感仍待人工复验；D 阶段在该实机验收前不标记为整体完成，也不进入 E 阶段。

2026-08-28 清理后，运行时不再包含覆盖角色身体的全局对话阶段，基础身体只使用一个稳定循环，口型只接受显式 viseme 输入；HUD、命令行、灯光和快照同步移除阶段入口。调度器、通道所有权与实例生命周期测试继续保留。当前完整 EditMode 为 118/118 通过，PlayMode 为 4 通过、0 失败、1 项因未设置仓库外 VRM 路径跳过。由于正式动作正在重选，验收场景结构仍在，但必须绑定新定义并重新完成产品 VRM 视觉验收后才能作为 D 阶段完成证据。

### E · 接入 Unity 能力协议与 TTS 时钟

工作项：

- [ ] 定义能力清单、工具调用、控制命令、事件和权威快照；调用、结果与状态不共用一种消息结构。
- [ ] 为请求和运行实例建立独立关联，支持重试去重、迟到事件忽略和断线快照恢复。
- [ ] Unity 只上报已接受、已开始、同步点、退出中、完成、取消和失败等关键事件，不传输逐帧动画状态。
- [ ] Unity 根据当前角色与资产公布工具描述、受限参数 Schema、表情枚举和命名表演目录；Electron 动态注册并转发，不保存第二份能力事实。
- [ ] 建立宿主中立的语音合成端点：Electron main 调用 TTS Provider，Unity 的 `speak` 工具请求音频并作为形体模式唯一播放时钟，renderer 只作无形体回退。
- [ ] 用户输入和模型生成使用事实事件，语音播放与动作使用权威实例；协议不引入覆盖整个角色的全局阶段。

交付物：Electron 与 Unity 之间可重连的能力/控制链路，一份随当前模型变化的工具清单，以及一段由 Unity 播放并驱动口型的测试语音。

完成条件：进程重连后 Electron 能通过能力清单与快照恢复认知；同一语音不会双重播放；Electron 不硬编码 Unity 表情枚举或动作资产。

### F · 接入并行 AI 表演工具循环

工作项：

- [ ] 将 Unity 的 `set_expression` 注册为非阻塞工具；情绪只使用 Unity 工具描述公布的有限语义表情枚举。
- [ ] 将 `speak` 注册为阻塞工具：其文本进入正式对话历史，Electron 生成 TTS，Unity 实际播放结束、取消或失败后才返回。
- [ ] 建立普通动作、表演搜索和显式执行工具；动作执行阻塞到对应 `PerformanceInstance` 终态，AI 只能选择 Unity 报告的稳定语义 ID。
- [ ] 验证同一步的表情、语音和动作调用并行执行，并且 Agent 只在该批次全部阻塞调用终结后生成下一段；精确同步使用共享节拍或语音锚点，不依赖调用到达顺序。
- [ ] 建立显式回合完成条件，避免工具化对白后再生成、显示或朗读一份重复终稿；保留无工具模型的普通文本降级路径。
- [ ] 验证模型不调用工具、重复调用、调用延迟或当前模型不支持工具时，默认表现仍然正确。
- [ ] 验证明确用户停止与安全策略始终优先于 AI 表达建议。

交付物：至少两个连续表演节拍：第一节拍并行切换表情、说一句话并执行短动作，全部终结后 Agent 再生成第二节拍；另包含一次搜索并完整执行长表演的端到端演示。

完成条件：没有工具调用时聊天与默认形体仍可用；长语音或动作未结束时 Agent 不提前生成下一段；AI 不能指定 Clip、路径、骨骼、BlendShape 或逐帧参数。

### G · 扩大资产生产能力

只有 A 至 F 的验收场景稳定后才进入本阶段。

工作项：

- [ ] 依据真实缺陷决定是否制作批量导入、预览、同步点编辑和许可证校验工具。
- [ ] 优先扩充高频待机、倾听反馈、说话手势和情绪过渡，再增加低频长表演。
- [ ] 建立“普通素材自动加工 + 高频素材人工精修 + 招牌内容定制”的成本分层。
- [ ] 评估手机视频动捕、付费视频动捕服务与动画师精修在实际样片上的成本和质量。
- [ ] 当一个表演需要角色专属修正时，使用角色包覆盖，不污染通用行为定义。

完成条件：新增同类动作主要是增加资产和清单，不需要修改调度核心。

## 两个强制验收场景

### 场景一：说话与解释手势

1. Electron 发起一次测试语音与“解释”语义动作。
2. 基础身体持续运行，Unity 启动口型并保持看向用户。
3. 上半身手势在指定词语或语义标记到达 `stroke`。
4. 手势完成并回收，口型继续，其他通道不被清空。
5. 语音结束后角色保持当前语义表情并回到基础身体表现。

通过标准：无全身硬切、无双重音频、无口型与手势明显漂移、终态无通道泄漏。

### 场景二：舞蹈中用户插话

1. 短表演获得全身通道，表情与视线按资产策略继续运行。
2. 用户开始输入时，视线先做可逆的注意反射，舞蹈不被立即清空。
3. 普通附和只产生反馈；普通问题请求最近安全点退出；明确停止立即取消。
4. 安全退出时完成合法过渡并恢复基础身体，随后才启动互斥的新行为。
5. Unity 返回完整的退出阶段与结束原因，Electron 不猜测动画状态。

通过标准：输入事件不自动切换身体 Clip，明确停止可靠生效，安全退出期间新实例不会提前抢占未释放通道。

## 扩张门槛

以下条件全部满足前，不批量制作资产或接入外部 Agent：

- 两个强制场景可以稳定重复执行。
- 至少更换过一次测试模型和一次动作文件，调度器无需修改。
- 所有活动实例在完成、失败和取消后都能释放通道。
- 本地受限素材不会被版本控制、CI 或打包流程收集。
- 调试信息能够解释一次动作为何执行、排队、被拒绝或被打断。
- 至少一次断线重连能通过快照恢复，而不是重放不确定的历史命令。

如果真实素材证明六类通道或当前动作定义不足，应先更新架构文档并补测试，再继续实现；不得通过动作名称特判绕过领域模型。

## 迁移与旧代码清理规则

新旧实现只允许在迁移切片期间短暂并存。一个新组件通过验收并接管职责后，必须在同一阶段完成以下清理，不长期保留“以后可能有用”的兼容代码：

- 使用引用搜索、程序集编译和测试确认旧类型、枚举、入口与资源已无有效调用方。
- 删除被替代的脚本及其 `.meta`，同时清理 asmdef 引用、场景/Prefab 挂载、资源清单、测试和文档入口。
- 检查场景和 Prefab 不存在 Missing Script，运行时没有两个组件同时写同一骨骼、表情或通道。
- 删除只为旧架构保留且没有真实消费者的适配器、Facade 重载、序列化字段和回退分支。
- 保留旧实现时必须在推进文档写明仍由哪个验收场景依赖、何时删除；不能仅以“保险”为理由保留。
- 每次提交只包含一个可验证迁移结果，提交前检查生成物、本地模型、测试输出和无关脏改动没有进入暂存区。

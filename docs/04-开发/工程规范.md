## 开发与验证

在仓库根目录执行命令，Unity 子项目命令另有说明。Node/npm 版本以 `.node-version` 和 `package.json` 为准。

```powershell
npm ci
npm run dev
```

启动只准备 Electron，不自动下载 ASR 权重、构建 Unity 或配置模型。首次使用在设置中录入自己的供应商、凭据与模型；离线语音先运行 `npm run asr:download`。

按风险选择检查，纯文档只检查差异、链接和命令。仓库没有统一格式化/Lint 脚本，不声称未运行的检查通过。测试集中于数据保持、安全、状态切换、取消和失败恢复，避免框架演示、重复包装与可逆文案/样式的源码断言。

UI 回归使用原生鼠标事件时，控件存在不代表点击坐标已稳定。切换新对话先等待欢迎区与可输入控件就绪，取坐标前等待连续布局帧稳定；发送消息后先确认请求进入合成流，再检查工具卡片。新对话的输入框会从底部移到中央，不能把漏点造成的工具等待超时当作记忆工具故障，也不靠增加全局等待时间或重试点击掩盖漏点。

Windows 的 UI 测试若在业务检查结束后报 `PostQueuedCompletionStatus (6)`、退出码 `2147483651`，不能因断言已通过而判整套测试成功。旧 Electron 43.1.1 缺少[延迟任务退出竞态修复](https://github.com/electron/electron/pull/53013)，项目锁定包含修复的 43.x（精确版本见包锁）。更新依赖前正常退出正在运行的 Katarune，避免安装时 `EBUSY`；`npm ci` 后运行 `npm run electron:install` 准备实际运行时。退出回归仅使用隔离配置和本机 HTTP 重定向，不调用供应商；同时检查实际运行版本、正常退出和故意失败的退出码。不得忽略原生崩溃码、强制改成成功或以自动重跑掩盖失败。

另一个已定位问题是 `RemoveEnvironmentCleanupHook` 的 `env != nullptr` 断言，原生栈包含 SQLite `Statement` 析构。2026-11-01 在 Electron 43.5.0／Node 24.19.0 与 better-sqlite3 12.11.1 下，用无界面、无 HMR 的内存数据库自然 GC 压力脚本复现了退出码 134；同脚本切换至 13.0.3 后完成 40 万条语句并正常退出。驱动已固定升级至 13.0.3 的 N-API 实现，决策见 D-012。热更新可能恰好触发回收，但不能用最后一条 HMR 日志判定 CSS 或 React 组件是原生崩溃根因。`test:sqlite-gc` 使用分配引发的正常 GC，不能仅以显式 `global.gc()` 或一次 UI 未复现替代。此项与上段退出竞态分别验证，原生异常必须按实际退出码失败。

舞蹈伴奏保留原始音频，由 Unity 在导入和播放时使用同一原生解码器校验，无需预先转换为 PCM WAV。可选 UTF-8 SRT 歌词使用粉色，按实际音频游标显示；演出独占声音和主字幕，歌词空隙清空；对应对白须取得 Unity 出声许可才合成 TTS。合成素材与完整 224.5 秒本地素材已验证实际解码、播放时钟、歌词及完播恢复；身体和目标支持的表情曲线已通过 Player 抓取与源数据核对。服装物理和整体观感仍由使用者确认。

记忆改动同时检查 `test:database` 和 `test:ui`：前者包含真实 SQLite 的角色隔离、版本、遗忘、重启及模拟 Agent／每日整理；后者使用隔离数据库验证界面读写，不访问使用者的聊天和记忆。日记只处理启用后排队的消息，应用退出时停止生成；不通过扫描旧 Wiki 或用户历史库准备测试资料。真实模型的整理质量须另外验收，普通检查不调用供应商。

`test:ai:deepseek`、`test:ai:openai-tts`、`test:ai:google-tts`、`test:ai:fish-audio-tts` 会调用真实服务，可能收费；仅在任务已授权且本地专用测试凭据可用时执行。密钥保存在忽略的本地配置中，不写入文档、输出或夹具。

2026-10-31，AI SDK 核心从 7.0.31 升至 7.0.159，已使用的 Provider／React／MCP 包同步更新并精确锁定；升级前检查 npm dry-run、peer dependencies 与 xAI 5 的 Responses API 边界。项目级 ai-sdk Skill 经上游差异审查后单项更新，并同步 `skills-lock.json`。399 项单元测试、类型／生产构建、SQLite 集成、Electron 界面与合成双平台主持检查通过；新增检查覆盖中断回复保留正文且不计成功、中断日记不接受有效外形的未完成草稿。未调用真实模型／语音供应商，未运行实际 Player、真实联网搜索或安装包验收。

`npm run models:snapshot` 显式联网刷新 LiteLLM 目录，运行后审查数据、来源元数据与许可证；安装、启动和普通构建不自动刷新。

首发安全维护保持 AI SDK 核心与 assistant-ui 版本不变，更新 Zod、Protobuf、MCP SDK、Electron 及相关构建工具的安全修复。两个官方工具包虽声明依赖 Zod 3.25.76，源码实际导入 `zod/v4`；通过定向 `overrides` 复用项目锁定的 Zod 4，避免携带旧校验器。`guarded-fetch` 的 `undici` 同样通过定向覆盖锁定修复版本，保留原有 SSRF 校验与重定向策略。上游解除旧依赖锁定后再移除相应覆盖，不通过 `npm audit fix --force` 降级构建工具。安全检查使用 `npm audit --registry=https://registry.npmjs.org`，生产依赖另加 `--omit=dev`；镜像源若未实现审计接口，不将请求失败视为零告警。

开发工具链仍包含 `minimatch`、`esbuild` 和 `deepmerge` 的上游告警，分别经打包／脚手架工具、Drizzle 的旧加载器及 shadcn 引入。生产依赖审计与完整依赖审计分开报告；构建后检查实际 ASAR，不将开发工具告警描述成产品漏洞，也不将生产依赖零告警描述成整个仓库零告警。开发工具的大版本迁移另行安排。

本机工具检查使用 `npm test` 中的 `agent-tools.test.ts` 覆盖角色工作区隔离、同角色会话共享文件与权限隔离、穿越／目录链接、只读与撤销、附件首次发送、原件保持、图片输出、目录及联网签名批准、原生命令联网，以及只取消当前会话进程。`test:database` 验证真实 SQLite 的会话权限持久化、归属拒绝与删除级联，0030 角色级权限升级到 0031 时不继承旧授权且保留消息／工作区文件，以及 Electron 中的托管附件／官方 Bash 实际读取。`test:ui` 验证输入框内模式选择、最小窗口、草稿保持、空白会话读取权限不入库、切换会话恢复各自模式，以及目录／网页批准后续跑，模型使用合成流。Windows 完全访问需要 Git for Windows 的 Bash，缺失时明确失败，不切换成 WSL 或虚拟命令；此程序不打进安装包。Web Fetch 公网读取须另做实际网络检查，保留对私网／保留地址的拒绝；VPN 的 fake-IP DNS 可能被判为不可访问，不得关闭 SSRF 来让测试通过。

## 代码与提交

- 严格 TypeScript；外部输入、持久化数据、IPC 与工具参数进行运行时校验。共享 Zod Schema 推导类型，不在多个进程手工复制结构。
- main/preload/renderer、Unity 及 Worker 的职责保持清晰；框架已有公开接口和持久化格式直接复用。
- 标识符与文件名使用英文，产品文案与文档以中文为主；组件 PascalCase，变量/函数 camelCase，固定常量 UPPER_SNAKE_CASE。模块名表达所属领域，不建立宽泛的 utils/common 聚合层。
- Renderer 沿用 assistant-ui Registry、shadcn/Base UI 默认组件与主题；默认交互、焦点管理和动效放在共用组件中，页面负责布局与业务组合，不重复手写弹层或覆盖同一套默认行为。页面入场与内容切换复用共用动效规则，遵循系统和应用的减少动态效果设置。图标使用已有且注明来源的 SVG，图标按钮保留可访问名称。具体框架 API 按项目锁定源码与相关 Skill 核对。
- 普通固定选项选择复用 `OptionSelect`；需要与触发按钮等宽的弹层使用 `PopoverContent.matchTriggerWidth`，不再另设菜单固定宽度。
- 表单复用 `components/form.tsx` 的 Base UI `Form`／`FormInput`：原生必填、格式、范围及长度约束由框架校验，禁止使用浏览器校验气泡或新增占据布局的错误段落。错误字段统一为 1px 错误色边线，聚焦与未聚焦均不添加外圈；已有边框只改变颜色，无边框编辑器及组合字段使用 `field-error-frame` 绘制内侧细边线，保持布局尺寸。首个错误聚焦和修正后重验保持统一；字段旁反馈走现有通知系统，复用 `ui/tooltip.tsx` 的紧凑尺寸和箭头，采用错误配色、字段下方定位与随文字收缩的宽度，不带大通知卡片的图标或关闭按钮。一次只展示当前字段的一条，支持失焦／修正／卸载清理和 Escape 关闭。自定义编辑器通过 `useFieldError` 使用同样的反馈，保存／连接等操作失败使用普通 Toast；页面加载失败与连接状态等持续业务状态仍在所属页面表达。边界 Schema 错误按字段名薄适配，不自建第二套表单状态机。
- 依赖升级独立实施；不混入无关格式化、生成物、素材或用户本地修改。生成文件标明来源并保持可复现。
- 版本遵循 SemVer，标签为 `vMAJOR.MINOR.PATCH`；稳定公开版本前使用 `0.y.z`。发布版本、锁文件、标签和产物须一致，并来自可追溯提交。
- 提交遵循 `<type>(<optional-scope>): <summary>`，一次表达一个可评审意图。提交前审查暂存差异和敏感信息；PR 说明结果、验证及实际未覆盖范围。
- `main` 保持可继续开发的已验证状态；使用短生命周期分支，按当前协作工具的分支约定命名。

### 已知本地数据库迁移历史

`drizzle/` 中的版本化 SQL 是迁移依据；Schema 入口为 `src/main/database/schema.ts`。生成迁移用 `npm run db:generate`，检查 SQL 后提交，启动在开窗前迁移。

附件迁移 `0014_futuristic_arclight` 曾以 `1785685134232` 执行，合并后 journal 为 `1785688523544`。仅在最后一条迁移的已知时间戳和 SHA-256 同时匹配时校正 journal；未知历史继续报错。禁止删库、凭“表已存在”判定完成或统一添加 `IF NOT EXISTS` 掩盖冲突。

### MCP 服务开发与验证

设置页提供 STDIO 与流式 HTTP 服务的增删改、全局启停、连接测试及工具列表。逐项参数不经过 shell 拼接；STDIO 启动程序和对应运行环境由使用者安装，工作目录使用绝对路径。环境变量值、Bearer Token 和请求头值走 CredentialStore，编辑页留空保持已保存值；删除对应环境变量／请求头行会移除其值，令牌有独立清除操作。环境变量传递只读取显式选择的变量及 SDK 基础运行变量，不继承宿主全部环境。HTTP 首版通过令牌／请求头认证，不支持 OAuth 登录。

`npx vitest run tests/mcp.test.ts tests/chat-service.test.ts` 验证实际本地 STDIO、合成 HTTP、凭据保持、聊天连接隔离、停用与取消、进程树回收及会话权限独立性；`npm run test:database` 验证迁移和重启保持。`npm run test:ui` 使用隔离 SQLite、系统凭据加密与本地合成 MCP，覆盖设置管理和深浅色／小窗口；可用 `KATARUNE_UI_TEST_STEPS="MCP settings manage global services and protect credentials"` 定向运行 `npm run test:ui:run`（需先构建）。真实第三方 MCP 账号、真实模型工具选择及长时间连接按所接服务另行验证。

## Windows 内部发行包

准备项目锁定的 Unity Editor/CLI、默认 VRM、清单引用的动作、ASR/VAD 权重，以及 Visual Studio C++ x86/x64 工具和 Windows SDK。直播媒体资源先运行 `npm run live:prepare`，版本与来源按下方直播验证章节。NSIS 来自 electron-builder 的锁定来源，无需 Qt SDK；缺少资源即停止构建。

`just-bash` 的可选 XZ 依赖 `node-liblzma` 2.2.0 在 Windows 构建中强制使用 `/std:c++latest`，本机 MSVC 14.39 处理 Electron 43 的 V8 `std::span` 头文件时会报 `C2036`。仅包含 `node_buffer.h` 即可复现，使用 C++20 则通过，与 Unity 构建无关。仓库通过开发依赖 `patch-package` 和 `patches/node-liblzma+2.2.0.patch` 将该依赖的 Windows Debug/Release 编译标准固定为 C++20；`postinstall` 在 Electron 原生依赖重建前应用补丁，失败即停止。升级该依赖时须复核并移除已不需要的补丁。

原生依赖源码构建还需要 Python 3 和 CMake。若 Windows 的 `python3` 指向商店占位程序，可在当前构建终端用 `$env:npm_config_python = (Get-Command python.exe).Source` 指定实际解释器。Anaconda 的 HTTPS 证书配置需要可用的信任链；指定 `SSL_CERT_FILE` 时使用不含中文的路径，并保留证书校验。该环境设置仅用于本机构建，不写入应用运行配置。

## 桌宠默认模型与启动排错

默认模型随仓库保存在 `resources/characters/default-package/avatar/model.vrm`，清单位于同一包的 `manifest.json`。模型、立绘和动作均从角色包目录加载；发行构建由 Electron 原样复制到 `resources/characters/default-package/`，不再复制到 Unity Player 的数据目录。Unity Editor 预览与默认待机烘焙读取同一份包内模型；独立 Player 通过宿主提供的包描述或显式 `--vrm` 路径加载。默认包已配置公共人体待机和两段待机变化；素材许可仍以各自授权为准。

Runtime 只接受 VRM 1.0；扩展名不能证明格式。VRM 0.x 可用锁定 UniVRM 离线转换：设置 `KATARUNE_VRM_SOURCE` 与 `KATARUNE_VRM_OUTPUT` 为不同绝对路径，输出须不存在，再运行：

```powershell
unity run unity/KataruneAvatar -- -executeMethod Katarune.Avatar.Editor.AvatarModelConverter.ConvertFromEnvironment
```

转换成功后再替换本机默认模型并重建，保留原文件；转换器不进入 Runtime。

启动诊断位于开发 userData 的 `logs/diagnostics/events.jsonl`，可从设置 → 常规打开日志目录；Unity 断连后备记录位于 `avatar-runtime/unity-fallback.jsonl`。模型缺失或加载失败通过 `startup-error` 返回具体原因，Electron 清理进程；超时只兜底没有启动结果的情况，不掩盖资源错误。连接、会话切换和窗口操作见[桌面交互设计](../00-项目/桌面交互设计.md)。

### 音色校准

Profile 使用上游原生 JSON，保存于 `userData/speech-profiles/<voiceKey>.json`。`voiceKey` 是 UTF-8 `JSON.stringify([providerConfig.id, modelConfig.modelId, character.speechVoice])` 的 SHA-256 小写十六进制；不用显示名称替代实例/模型/Voice ID。缺失或无效文件回退默认示例，日志中的 `source=default-example` 不代表已校准。

1. 用真实音色准备 A/I/U/E/O 和非语音 Noise，导入忽略的 `Assets/KataruneLocal/SpeechCalibration`；使用 Decompress On Load。
2. 六个 Clip 按上述名称命名并一起选中，运行 `Katarune > Speech > Calibrate Selected Vowel Clips`。每类至少 16 个有效分析窗口；纯静音不用作 MFCC 噪声样本，静音通过音量门限闭嘴。
3. 按当前 voiceKey 保存 Profile；更换音色重新校准。用中/日/英文、停止/重播及语义表情检查口型，不覆盖模型声明的表情互斥。

录制须显式启用 `KATARUNE_SPEECH_CAPTURE`，`KATARUNE_SPEECH_CLOSEUP=1` 只用于验收近景。捕获限定本 Player 的画面与 AudioSource 输出，诊断是引擎输出口径，不代表声卡延迟或逐音素对齐精度。

### 增量 PCM 与连续语音

- 播放时钟来自实际 AudioSource 游标；PCM 预读和网络字节数不是已播放音频。慢流验收覆盖位置冻结、对齐迟到、尾音未截断与取消清零。
- 时间戳在供应商和缓存边界验证，完整音频再验证总时长；流中断不缓存。语音临时目录仅清理当前应用可确认已退出的自有 session。
- `npm run asr:download` 准备固定 SenseVoiceSmall INT8 与 Silero VAD 权重，`npm run test:asr` 使用固定公开音频及模拟麦克风验证离线识别链路。
- 真人验收按任务覆盖耳机/外放、停顿、长句、设备断开、最小化、切换、插话与误触恢复；另记录实际冷启动、识别和首音，不用加速固定音频推理时间替代。
- 新素材、音色、安装包和设备组合需验证对应变化；已接受的现有体验不重复写成未验收。

## 直播准备与验证

进入直播页默认显示 B 站开放平台、B 站网页连接、抖音三个入口，标注当前已配置方式并显示已保存账号昵称；每种方式只保留一份配置。点击入口后进入详情并连接／检测，已有在线连接直接复用，进入页面本身不触发检测。首次登录或详情菜单中选择「重新登录」才获取二维码，手机确认后识别自己的直播间；B 站开放平台首次配置或「修改凭据」使用项目凭据表单。不提供手动房间号和 Cookie 输入。刷新二维码位于标题栏，与返回并列；二维码按卡片剩余空间缩放。平台报告已扫码后以勾选图标替换二维码，提示在手机确认，此时不视为已登录；平台验证账号成功后显示登录成功并检测房间，隐藏二维码刷新。过期及失败直接反馈；抖音需要额外验证时，由使用者点击「完成安全验证」打开官方窗口。账号经平台查询验证后才保存，renderer 不接收 Cookie。

详情显示直播间／账号信息及开播状态，右上角「返回」回到方式选择，保留现有连接、配置与登录态；扫码页返回取消扫码，房间检测即使稍后完成也不会抢回详情。选择另一种方式才断开旧连接并复用目标凭据，清除旧方式派生房间号。确认开播后显示弹幕，可从「连接操作」查看直播间信息，再返回弹幕。下播或重连自动回到信息页。正在主持时可以返回和查看当前方式，其他方式及凭据操作禁用，须先停止当前场次。

已验证账号但没有返回直播间时，进入正常的等待状态：右上角保留「返回」，内容使用真实用户头像、昵称、平台、等待说明与「重新检测」，不显示红色错误、不弹故障通知、不生成故障编号。尚未开通 B 站直播间同样处理；重新检测到房间后直接连接，凭据保持不变。未开播时优先展示账号卡片及「未开播」状态，隐藏用户 ID、房间号、房间标题和空简介；平台图标仅标注平台，头像缺失时使用中性用户图标。账号校验、网络或数据异常仍走原错误链路。

「启动」开启角色输出、本地预览及 RTMP，可在未连接或未开播时测试画面与声音；不以房间配置、连接或开播状态阻止媒体启动。已有连接配置可在后台尝试连接，连接失败不停止预览。后台 AI 主持仍须同时满足媒体运行、消息连接有效且平台确认开播；离线预览不调用模型。角色包、模型／语音配置及本地媒体资源的原检查保持有效。

详情的「连接操作」菜单提供断开、重新登录／修改凭据及退出账号。断开只关闭连接，保留所有配置与凭据；退出账号清除指定网页登录态和当前派生房间号，另一平台账号及 B 站官方凭据保留。重新登录成功后同样清除旧账号派生房间号，避免连接旧账号房间。角色、互动及输出参数不变。登录失效或访问校验失败明确反馈，不自动切换方式。账号自动识别在 main 重新验证登录身份，B 站按 UID 查询对应直播间，抖音仅采用当前账号自资料 room_data.owner.web_rid；未返回时保留登录态并提示重新检测，不把内部 room_id、账号 UID、抖音号当作网页房间号。

抖音扫码使用临时隔离的隐藏官方登录页，先导航空白页再启用 Electron Debugger 网络观察，避免首次导航前命令挂起。纯 HTTP 二维码接口的 4031 不能靠弹幕签名解决；不读取使用者其他浏览器登录态。恢复账号时在新隔离页面中重新校验，结束后销毁页面及临时存储。Chromium 可能返回无名称 Cookie，导出时排除、读取既有凭据时仅忽略该项；其他格式异常继续报错。不要因房间尚未建立而清除有效登录或要求再次扫码。使用者手动测试结论见路线图。

抖音已建立消息连接后，状态检测与心跳分开调度；未开播／待确认时查询间隔为 3 秒，直播中为 10 秒，实际同步还包含平台更新及请求耗时。下播控制消息立即生效，查询失败逐步退避，不并发堆积。模拟协议检查覆盖快速开播检测、迟到响应、下播后的旧状态、新一场房间 ID、退避和取消；真实开下播响应耗时须另外测量。尚无网页房间号时仍使用账号页的「重新检测」。官方 [直播 SDK 状态回调](https://developer.open-douyin.com/docs/resource/zh-CN/dop/ability/douyin-live-sdk/douyin-live-sdk/interface-and-function)需要对应接入和主播白名单，不属于当前扫码登录能力。

| 端口占用、监督程序终止、编码器退出、控制管道关闭 | `npm run test:live:cleanup` |
| 页面布局、监听、实时历史且不重复写入 | `npm run test:ui` |

预览连通性探针已完成开发验证，不保留独立测试窗口与重复运行入口。实际直播页面回归检查角色画面与声音同步、连续切换本机监听、离页／最小化后返回的恢复，以及直播软件接收端。

输出支持 16:9 横屏与 9:16 竖屏，默认横屏 1K（1920×1080）；1K／2K 两档横屏分别为 1920×1080／2560×1440，竖屏分别为 1080×1920／1440×2560。比例与分辨率须停止后修改，旧配置缺少比例时保持横屏。原 720p 设置读取为默认 1K；本地 RTMP 素材流内部使用 60 fps，1K／2K 对应 12000／24000 kbps，横竖相同，界面不提供码率或帧率。最终平台推流参数在直播软件设置。预览与 RTMP 复用同一次 H.264／AAC 编码，以关键帧分段 MP4 交给 MediaSource 播放，保留原尺寸、有界缓冲与页面可见性控制；UI 检查实际解码、监听静音、分段确认和跳段重接。迁移 0028 仅移除配置 JSON 中旧编码参数，保留其他配置与凭据引用；修改默认值不覆写已有分辨率选择。Player 测试先构建当前 Unity 开发二进制；`test:live:player` 可通过 `KATARUNE_LIVE_PLAYER`／`KATARUNE_LIVE_TOOLS` 指定发行载荷，媒体均使用绝对资源路径，并验证结束直播后恢复原桌宠绑定与播放。`$env:KATARUNE_LIVE_DANCE='1'; npm run test:live:packaged` 另验证默认舞蹈从原生模型工具调用、配乐／歌词／镜头、自然结束到后续主持恢复，耗时约四分钟。

`test:live:media` 默认使用横屏 1080p60，`KATARUNE_LIVE_WIDTH` 可设为长边 1280／1920／2560；PowerShell 使用 `$env:KATARUNE_LIVE_ASPECT_RATIO='9:16'; npm run test:live:media` 检查竖屏，改为 `'16:9'` 检查横屏。使用 `$env:KATARUNE_LIVE_SOAK_SECONDS='3600'; npm run test:live:media` 启用 60 分钟检查。横屏产物位于忽略的 `.test-dist/live-media-optimized`，竖屏位于 `.test-dist/live-media-portrait`，包括音视频、原尺寸预览、Player／编码诊断和每 30 秒进程内存采样。同步测试在持续运行前后，分别对合成音频脉冲与实际音频回调驱动的画面标记比较容器时间戳，跳过接收初始关键帧边界；目标稳态偏差不超过 50 ms。另按采样时间统计真实新画面和重复帧，预热后平均新画面至少 58 fps、重复帧不超过 3%，不能只检查编码器报告的 60 fps。验收标记仅在显式 `KATARUNE_LIVE_ACCEPTANCE=1` 的测试 Player 中启用，不进入普通画面。报告实际持续时间、运行前后偏差和画面帧率。

官方账号联调要求已获批项目、开发者凭据及对应消息权限。先连接，确认状态未知不会主持，再在直播软件开播，验证官方开始／结束事件、真实弹幕和礼物、掉线及停止。网页联调只使用使用者授权的扫码账号与直播间，不读取其他浏览器账号。二维码真实签发、手机确认并持久化、重新启动恢复、平台弹幕／礼物与开下播分别记录；合成协议和签名向量不替代这些步骤。不得用用户文本伪造礼物或把真实凭据加入夹具。真实模型调用按原费用授权要求执行。

直播姬多媒体与 OBS 媒体源分别拉取界面提供的本地 RTMP 地址，验证画面、声音、停止后断流、重启后重新拉取、本机监听关闭但音轨仍有效。另查后台运行、舞蹈配乐／歌词间隙／镜头和完整安装后的环境。自动化、实际 Player、接收端、官方账号与使用者验收分别报告；桌面锁定或自动化拒绝访问时不能将原生窗口测试记为通过。

## 日志与诊断验证

统一日志契约见[技术选型](../02-架构/技术选型.md#日志与诊断)。设置 → 常规 → 打开日志目录可访问日志；状态与导出保留为内部诊断接口，不在普通设置页展开。新常规日志为数据目录下 `logs/diagnostics/events.jsonl`，不能用旧 `avatar.log` 判断 Main/TTS/ASR 是否记录。

`npm test` 覆盖错误投影、循环 cause、容量、退出标记、磁盘不可写与保留策略；`npm run test:diagnostics` 包含构建，并验证 ASAR 中的写入线程，在隔离 Electron 中验证 IPC、限流、导出/取消、renderer 崩溃，以及 Main FATAL 收尾和非零退出。Unity `AvatarDiagnosticsTests` 覆盖线程回调、隐私与断连后备；完整 Player 启动/舞蹈/切换用 `npm run test:startup`。

两个 preload 必须独立打包以支持 sandbox；锁定的 electron-vite 5.0.0 在 isolatedEntries 的重定向输出中直接调用 TTY 方法，配置仅为缺失的光标方法提供空实现，不修改依赖源码或运行时沙箱。

扩展或回归时使用隔离目录和模拟供应商验证以下边界，自动化与使用者手动测试分别记录：

- 注入 TTS 未配置、401、429、超时、断流、损坏音频与传输失败；每次只生成一个故障编号，能关联前后对白及表演，界面显示对应原因，原因链不丢失。
- 取消、chat-only、空正文、正常停止不得记成 ERROR；对重试/降级保留最终结果，不重复打印同一异常。
- 操作拒绝只在明确的输入／权限／状态检查处构造 `OperationRejected`，可选提示仅用可信固定文案；请求参数用 `parseRequest`，内部数据与返回值继续使用原 Schema 校验。检查 WARN 的 `outcome=rejected`／`reasonCode` 与 ERROR 的故障编号彼此区分，数据库损坏不得被归类成资源不存在或操作不允许。
- 拒绝回归覆盖非法参数不执行副作用、归属不匹配、消息式入口关闭、内部 Schema 故障、取消、洪泛汇总与安全字段导出；入口为 `npm test`、`npm run test:database` 和 `npm run test:diagnostics`，均不调用真实供应商。
- 在每个入口注入伪密钥、正文、响应体、绝对路径、CR/LF、超大及循环对象；普通文件、后备文件、控制台和导出包均不得泄露这些值，坏事件不影响其他请求。
- 验证无权限、磁盘满、日志洪泛、轮转、过期、关闭与重启；目录总量和内存有界，丢弃可见，不能卡住 UI、PCM 回调或退出。
- 在隔离测试进程中触发 Main、renderer、ASR、Unity 的异常与意外退出，校验来源、退出码、故障编号和下次启动标记；不能以抓到 JS 异常宣称原生崩溃诊断通过。
- 在实际 Player 核对“引导语 → TTS/无声回退 → 舞蹈”的同一运行关联、会话代次隔离，以及断连后的有界后备记录。导出必须排除数据库、凭据、资源清单、测试音频及未明确选择的崩溃转储。

验收目标：仅凭一次受控诊断导出，能够定位故障进程、阶段、错误类型/状态、重试与恢复结果；无需索取用户聊天正文或 API Key。真实供应商与真人语音依旧单独授权、单独报告。

# 工程规范

本页是开发、验证、构建与排错的操作入口。协作约束和 Skills 规则见 [AGENTS.md](../../AGENTS.md)，系统边界见[技术选型](../02-架构/技术选型.md)，进度见[路线图](../03-规划/路线图.md)。

## 开发与验证

在仓库根目录执行命令，Unity 子项目命令另有说明。Node/npm 版本以 `.node-version` 和 `package.json` 为准。

```powershell
npm ci
npm run dev
```

启动只准备 Electron，不自动下载 ASR 权重、构建 Unity 或配置模型。首次使用在设置中录入自己的供应商、凭据与模型；离线语音先运行 `npm run asr:download`。

| 变更或目的 | 命令 |
| --- | --- |
| 类型 | `npm run typecheck` |
| 单元测试 | `npm test`；开发监听用 `npm run test:watch` |
| Electron 生产构建 | `npm run build`，包含类型检查 |
| 数据与迁移 | `npm run test:database` |
| 系统凭据 | `npm run test:credentials`，使用测试凭据 |
| UI 与持久化 | `npm run test:ui`；已有构建用 `npm run test:ui:run` |
| 启动 | `npm run test:startup` |
| 角色包导入 | `npm run test:character-packages` |
| 实际 Player 角色包加载 | `npm run test:avatar-packages`，先准备开发 Player |
| 离线语音识别 | `npm run test:asr`，先构建应用并下载模型 |
| 固定聊天/工具路径 | `npm run validate:ai`，无真实供应商调用 |

按风险选择检查，纯文档只检查差异、链接和命令。仓库没有统一格式化/Lint 脚本，不声称未运行的检查通过。测试集中于数据保持、安全、状态切换、取消和失败恢复，避免框架演示、重复包装与可逆文案/样式的源码断言。

`test:ai:deepseek`、`test:ai:openai-tts`、`test:ai:google-tts`、`test:ai:fish-audio-tts` 会调用真实服务，可能收费；仅在任务已授权且本地专用测试凭据可用时执行。密钥保存在忽略的本地配置中，不写入文档、输出或夹具。

`npm run models:snapshot` 显式联网刷新 LiteLLM 目录，运行后审查数据、来源元数据与许可证；安装、启动和普通构建不自动刷新。

## 代码与提交

- 严格 TypeScript；外部输入、持久化数据、IPC 与工具参数进行运行时校验。共享 Zod Schema 推导类型，不在多个进程手工复制结构。
- main/preload/renderer、Unity 及 Worker 的职责保持清晰；框架已有公开接口和持久化格式直接复用。
- 标识符与文件名使用英文，产品文案与文档以中文为主；组件 PascalCase，变量/函数 camelCase，固定常量 UPPER_SNAKE_CASE。模块名表达所属领域，不建立宽泛的 utils/common 聚合层。
- Renderer 沿用 assistant-ui Registry、shadcn/Base UI 默认组件与主题；图标使用已有且注明来源的 SVG，图标按钮保留可访问名称。具体框架 API 按项目锁定源码与相关 Skill 核对。
- 依赖升级独立实施；不混入无关格式化、生成物、素材或用户本地修改。生成文件标明来源并保持可复现。
- 版本遵循 SemVer，标签为 `vMAJOR.MINOR.PATCH`；稳定公开版本前使用 `0.y.z`。发布版本、锁文件、标签和产物须一致，并来自可追溯提交。
- 提交遵循 `<type>(<optional-scope>): <summary>`，一次表达一个可评审意图。提交前审查暂存差异和敏感信息；PR 说明结果、验证及实际未覆盖范围。
- `main` 保持可继续开发的已验证状态；使用短生命周期分支，按当前协作工具的分支约定命名。

### 已知本地数据库迁移历史

`drizzle/` 中的版本化 SQL 是迁移依据；Schema 入口为 `src/main/database/schema.ts`。生成迁移用 `npm run db:generate`，检查 SQL 后提交，启动在开窗前迁移。

附件迁移 `0014_futuristic_arclight` 曾以 `1785685134232` 执行，合并后 journal 为 `1785688523544`。仅在最后一条迁移的已知时间戳和 SHA-256 同时匹配时校正 journal；未知历史继续报错。禁止删库、凭“表已存在”判定完成或统一添加 `IF NOT EXISTS` 掩盖冲突。

## Windows 内部发行包

准备项目锁定的 Unity Editor/CLI、默认 VRM、清单引用的动作、ASR/VAD 权重，以及 Visual Studio C++ x86/x64 工具和 Windows SDK。NSIS 来自 electron-builder 的锁定来源，无需 Qt SDK；缺少资源即停止构建。

| 目的 | 命令与产物 |
| --- | --- |
| 正式 Unity Player | `npm run build:avatar` → `build/release/avatar`；成功后替换发行目录，不覆盖开发 Player |
| 完整 unpacked | `npm run package:win:dir` → `dist/win-unpacked`；包含 Unity、Electron、默认资源及语音权重 |
| 安装器 | `npm run build:installer` → `dist/Katarune-Setup-<version>.exe`；复用 unpacked，编译源码绘制 DLL |
| 完整包 | `npm run package:win`；不执行完整发布检查 |
| 内部发布检查 | `npm run release:win`；单元/数据库、完整构建、UI、隔离首启默认立绘验证，再生成 NSIS；不调用真实供应商 |
| 安装/卸载验证 | `npm run test:uninstall:win`；PowerShell 7，唯一身份的隔离载荷 |
| 安全界面预览 | `npm run preview:installer`；不执行安装、卸载、数据清理或应用启动 |

预览默认安装页，可传入 `-- --page=install-progress`、`install-finished`、`uninstall`、`uninstall-progress`、`uninstall-finished`；先关闭已有预览再重建。源码位于 `resources/installer/`，生成工具和 DLL 留在忽略的 `build/`。

默认卸载保留个人数据，只清理固定身份下的缓存、暂存和安装版 Unity 状态；全部删除须用户显式选择。清理拒绝目录链接并检查文件占用，失败保留程序/卸载器。覆盖更新跳过数据清理；开发和安装身份隔离。旧 Qt 安装先正常卸载，再使用 NSIS 安装。

安装进度反映真实阶段和处理量，完成前不得显示 100%。绘制层只处理品牌、控件和局部重绘，不接管上游安装清单、重试或回滚；适配锁定模板时检查目标，不直接修改 `node_modules`。

图片、默认 VRM 和角色参考美术保留原始字节；不能仅因运行时未引用就删除参考资产。生产包可排除开发源码、PDB、`*_DoNotShip` 与明确的参考图，但须保留许可证和运行资源。修改 Unity 裁剪或资源过滤后，用实际发行 Player 检查动态加载、切换、取消、对白与字幕：

```powershell
node tests/avatar-package-player.integration.mjs build/release/avatar/KataruneAvatar.exe
```

内部包当前无签名且不自动公开；签名、更新、跨平台及完整安装验收状态只在路线图维护。安全预览、隔离载荷和构建通过不替代正式完整安装后的体验。

## 桌宠默认模型与启动排错

开发 Player 路径为 `unity/KataruneAvatar/Builds/Windows/KataruneAvatar.exe`；发行路径为 `build/release/avatar`。两者用途分开，构建开发 Player 见 [Unity README](../../unity/KataruneAvatar/README.md#build)。

默认模型位于忽略的 `unity/KataruneAvatar/Assets/KataruneLocal/Models/default-avatar.vrm`，新电脑需单独恢复。默认包清单位于 `resources/characters/default-package/manifest.json`，当前动作为空；模型、动作和许可不能仅靠克隆仓库获得。

Runtime 只接受 VRM 1.0；扩展名不能证明格式。VRM 0.x 可用锁定 UniVRM 离线转换：设置 `KATARUNE_VRM_SOURCE` 与 `KATARUNE_VRM_OUTPUT` 为不同绝对路径，输出须不存在，再运行：

```powershell
unity run unity/KataruneAvatar -- -executeMethod Katarune.Avatar.Editor.AvatarModelConverter.ConvertFromEnvironment
```

转换成功后再替换本机默认模型并重建，保留原文件；转换器不进入 Runtime。

启动日志位于开发 userData 的 `logs/avatar.log`。模型缺失或加载失败通过 `startup-error` 返回具体原因，Electron 清理进程；超时只兜底没有启动结果的情况，不掩盖资源错误。连接、会话切换和窗口操作见[桌面交互设计](../00-项目/桌面交互设计.md)。

## Unity 编辑器动态程序集排错（2026-09-27）

Unity `6000.3.11f1`、Pipeline `0.8.0-exp.1` 与 Windows 中文工程路径下，`eval` / `eval_file` 会生成 `GetName()` 失败的 `PipelineEval_*` 动态程序集，可能使 QuickInstaller 持续刷错。此组合禁用这些命令；其他加载动态程序集的命令先验证。

优先用已注册场景、播放、截图和测试命令；C# 操作放在正常编译的 Editor 脚本中。截图可用 `capture_game_view` 的 `source=screen`，测试前保存未命名场景。

恢复须先保存场景，再通过正常重编译/脚本域重载或重启卸载动态程序集，最后清理历史条目并观察新增错误。只清空 Console、屏蔽异常、修改 PackageCache 或全局编码不能修复。相关版本升级后重新验证，不把当前规避当作上游修复。

## 语音与 uLipSync 开发验收

真实接口测试可能收费；Player 回放可复用已有音频。两类测试分开执行和报告，不能将分离测试的耗时称为端到端首音延迟。

| 入口 | 用途 |
| --- | --- |
| `tests/fish-timestamp-live.integration.ts` | Fish 时间戳/PCM 实测；`--saved-config` 只读开发配置，`--calibration` 生成元音样本 |
| `tests/dialogue-speech-live.integration.ts` | 真实文本流 → TTS → Unity 及取消 |
| `tests/avatar-speech-player.integration.mjs` | 已有音频回放；`--calibrated --closeup --expressions` 检查音色、口型和表情 |
| `tests/avatar-streaming-player.integration.ts` | 已有 PCM 的慢流、断流、取消、尾音与字幕检查 |
| `tests/avatar-user-subtitles.integration.mjs` | 用户/角色字幕接替 |
| `tests/render-speech-capture.mjs` | 将录制目录的帧和 PCM 合成预览，需 FFmpeg |

TypeScript 集成入口先用 Vite SSR 打包再运行。例如真实 Fish PCM 与独立 Player 回放：

```powershell
npx vite build --ssr tests/fish-timestamp-live.integration.ts --outDir .test-dist/fish-streaming-bundle
npx electron .test-dist/fish-streaming-bundle/fish-timestamp-live.integration.js --saved-config --streaming
npx vite build --ssr tests/avatar-streaming-player.integration.ts --outDir .test-dist/avatar-streaming-bundle
node .test-dist/avatar-streaming-bundle/avatar-streaming-player.integration.js --visible
```

`--saved-config` 的凭据只在 Electron main 解密，产物留在忽略的 `.test-dist/`，不写入既有聊天。Player 回放先准备开发二进制和对应音频；检查可见窗口画面，隐藏窗口截图可能全黑。传入角色包回放的 `--visible` 时，先显式给出 Player 路径。

### 音色校准

Profile 使用上游原生 JSON，保存于 `userData/speech-profiles/<voiceKey>.json`。`voiceKey` 是 UTF-8 `JSON.stringify([providerConfig.id, modelConfig.modelId, character.speechVoice])` 的 SHA-256 小写十六进制；不用显示名称替代实例/模型/Voice ID。缺失或无效文件回退默认示例，日志中的 `source=default-example` 不代表已校准。

1. 用真实音色准备 A/I/U/E/O 和非语音 Noise，导入忽略的 `Assets/KataruneLocal/SpeechCalibration`；使用 Decompress On Load。
2. 六个 Clip 按上述名称命名并一起选中，运行 `Katarune > Speech > Calibrate Selected Vowel Clips`。每类至少 16 个有效分析窗口；纯静音不用作 MFCC 噪声样本，静音通过音量门限闭嘴。
3. 按当前 voiceKey 保存 Profile；更换音色重新校准。用中/日/英文、停止/重播及语义表情检查口型，不覆盖模型声明的表情互斥。

录制须显式启用 `KATARUNE_SPEECH_CAPTURE`，`KATARUNE_SPEECH_CLOSEUP=1` 只用于验收近景。捕获限定本 Player 的画面与 AudioSource 输出，诊断是引擎输出口径，不代表声卡延迟或逐音素对齐精度。

### 增量 PCM 与连续语音

- 播放时钟来自实际 AudioSource 游标；PCM 预读和网络字节数不是已播放音频。慢流验收覆盖位置冻结、对齐迟到、尾音未截断与取消清零。
- 时间戳在供应商和缓存边界验证，完整音频再验证总时长；流中断不缓存。语音临时目录仅清理当前应用可确认已退出的自有 session。
- `npm run asr:download` 准备固定 SenseVoiceSmall INT8 与 Silero VAD 权重，`npm run test:asr` 使用固定公开音频及模拟麦克风，不代表真人对话。
- 真人验收按任务覆盖耳机/外放、停顿、长句、设备断开、最小化、切换、插话与误触恢复；另记录实际冷启动、识别和首音，不用加速固定音频推理时间替代。
- 新素材、音色、安装包和设备组合需验证对应变化；已接受的现有体验不重复写成未验收。
